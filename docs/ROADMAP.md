# 최종 목표까지의 연구 로드맵

작성: 2026-11-03, Asia/Seoul. 상태: **계획 반영 완료, 아래 신규 실험은 미실행**.
사용자의 시각 기여·다양한 맵 대응 요구를 기존 [PROJECT_CHARTER.md](PROJECT_CHARTER.md)에 맞춰 구체화한다. 확정 대전제를 바꾸지 않으며 설명용 HTML은 만들지 않는다.

**초파리의 겹눈/운동 시각과 비행 유래 균형·운동 회로를 자동차라는 가상 몸에 연결한다. 차체 기울기·회전·하중·타이어 상태를 몸 감각으로 되먹임하며 조향·가감속과 빠른 레이싱 라인/랩타임을 학습한다.**

최종 산출물은 전후좌우 시각으로 다가올 경로와 감속 필요성을 판단하고, 몸 감각으로 조작 결과를 조절하는 하나의 연속 감각운동 회로다. 서로 다른 트랙·차량·타이어/셋업에 대응하고 조향·가감속·변속·셋업 적응 및 빠른 유효 랩을 검증한다. 별도 일반 CNN/RNN 운전자로 대체하지 않는다. 검증된 상대풍도 장기 입력 범위에 유지하며 차속을 바람으로 바꾸어 부르지 않는다.

## 1. 출발점과 이번 방향 전환

**목표 지표는 시각 가림 오차의 증가율 자체가 아니다.** 몸 경로를 약화시키거나 시각 gain만 올려 가림 점수를 키워도 성능 향상으로 인정하지 않는다. 같은 몸 상태에서도 영상에 따라 미래 코너·감속 판단이 달라지고, 미학습 트랙의 실제 주행이 좋아져야 한다. 위 해석은 원인 가설이며 새 일반화의 증거가 아니다.

## 2. 단계와 통과 기준

아래 수량·horizon은 **첫 실험 설계를 위한 제안값**이다. 가용 트랙·교사·지연 측정 후 개발 자료만으로 확정하고 최종 시험 전에 manifest로 봉인한다. 일정은 날짜 약속보다 단계별 통과를 기준으로 한다.

| 단계 | 핵심 작업 | 검증/통과 기준 | 다음 단계 전 보존물 |
|---|---|---|---|
| R0 기준선·정보 경계 | 현 checkpoint/자료/지표 고정, 트랙·교사 보유 현황 확인, 새 분할 설계 | 기존 결과 재현과 데이터/단위/시간 계약 감사. 기존 test는 이미 소비됐다고 표시 | 기준 manifest, 실패 분류, 새 train/dev/test 목록 |
| R1 시각·비행 경로 진단 | 겹눈→T4/T5→공간/시간 표현→비행 회로→근육 출력의 전달과 몸 보정 검사 | 좌/우·정지·접근/회전 자극에 사전 예측한 반응. 기존 학습 자료에서 정보 소실/포화/gradient 문제 위치를 좁힘 | 단계별 활동·반응 지연·감도·개입 결과 |
| R2 시각 선행 예측 | 공간 구조를 보존하고 회로 상태에서 미래 경로·감속 필요를 보조 학습 | 몸/시간만의 비교군보다 개발의 미관측 코너 예측·조작이 개선. 몸 안정화 성능은 악화시키지 않음 | 보조 목표/단위/horizon 계약, architecture 비교·고정 checkpoint |
| R3 다중 트랙 학습 | 검증된 교사로 서로 다른 곡률·고저·직선 길이의 자료 수집, 하나의 회로에 공동 학습 | 트랙/에피소드 완전 분리. 미학습 개발 트랙에서 anticipatory steering/braking 개선, oracle/HUD 누출0 | 교사별 재현·정합 증거, 공동 학습/개발 결과 |
| R4 실제 학생 완주·새 트랙 평가 | 정지 shadow→저속→코너→전체 랩. 실제 actor 시간 예산과 회복 능력 검증 | 개발 승격 제안: 조건당 고정5회 중4회 이상 유효 완주·진행 중 teacher 개입0. 이후 봉인 트랙 고정 시험을 전부 보고 | 모든 시도·이탈·중단·제어권 반환, 유효 랩 분포 |
| R5 차량 몸 일반화 | 새 차종, 질량/관성·조향비·기어·타이어·하중 차이와 셋업 변화 해석. 변속/느린 셋업 출력을 점진 확장 | 트랙 변화와 차종 변화를 나눠 평가. 무적응과 사전 정한 제한 적응을 분리, 알려진 차 성능 회귀 방지 | 차종/셋업 계약·미학습 조건 평가·적응 비용 |
| R6 빠른 라인·랩타임 | 안정적 완주 뒤 보상/critic을 이용해 조향·페달·변속·셋업과 라인 공동 개선 | 유효 완주율·이탈/타이어 상태를 지키면서 반복 유효 랩의 중앙값/분산 개선. 새 봉인 조건에서 재확인 | 유효/무효 전체 분포, 고정 교사·기준 학생 대비표 |
| R7 최종 통합 판정 | 기전과 운전 성과를 함께 감사·재현 | 시각/비행/몸 경로의 기능·기여와 여러 미학습 조건의 학생 유효 주행을 각각 충족 | 재현 가능한 통합 checkpoint·계약·실패 사례·미검증 목록 |

R1과 병행해 R3의 트랙/교사 가용성과 몸 감각 등록을 조사한다. 본격 다중 트랙 학습은 R1/R2의 결함을 확인한 뒤 진행하고, 랩타임 최적화는 R4의 실제 완주 근거를 얻은 뒤 진행한다. 기존 단일 트랙의 짧은 학생 주행 시험은 R3 자료 준비와 병행할 수 있으나 최종 미학습 트랙을 조기 튜닝에 쓰지 않는다.

## 3. R1: 가장 먼저 확인할 시각 경로

### 3.1 전달·표현·학습을 나눠 진단

현재 `scripts/prepare_synchronized_sac_student.py`는 네 시야의 frozen FlyVis 출력을576개 특징으로 pool하고, `UnifiedFlightSensorimotor`가 단일 비행 회로의 감각 경계와6근육 출력에 연결한다. 다음은 결함 확정이 아니라 검사 대상이다.

| 위치 | 확인 사항 | 비교/조치 조건 |
|---|---|---|
| 입력/겹눈 | 각 시야의 방향·단위·노출/대비·원래 시간 간격·결측, 원거리 코너 가시성 | 실제 영상과 진단용 통제 자극을 구분. 정상 반응 방향이 없으면 입력 계약부터 수정 |
| T4/T5 운동 시각 | 방향 선택성·정지/회전/접근 구분·포화·SNR | 회전하는 몸과 장면 운동의 구분 반응을 측정. 생리 수치는 별도 일차 근거 없이 정답으로 invent하지 않음 |
| 공간 표현 | 현재 pooling이 원/근거리·좌우 경계·코너 형태를 얼마나 잃는지 | 동일 동결 특징의 전/후 정보 판독 비교. 필요하면 retinotopic 위치·시야별 공간 구조를 보존 |
| 비행 회로 입력 | 시각 drive, 상대 운동 흔적, 몸 보정, synaptic 경로의 전달 | 시야/방향 선택적 개입과 몸 회전 고정 비교. 연결 확인과 생리 기능 검증은 별도 |
| 근육→차량 readout | 근육 활동의 동적 범위·포화·시간 지연, 학습 gradient와 정규화 영향 | `.001` scale floor·8사건 TBPTT·작은 근육 변동의 영향을 train/dev에서만 비교. gain을 올리기 전에 병목 확인 |

원거리 도로 형태에는 운동 시각뿐 아니라 정적 공간 구조도 필요할 수 있다는 설계 가설을 검사한다. T4/T5만으로 미래 경로를 모두 안다고 가정하지 않는다. HS/VS 등 시각 안정화 기능 근사와 차량 대응을 검토할 수 있지만 근거·실측 연결·공학적 구현을 각각 명시하며 이름만 바꾸어 구현됐다고 판정하지 않는다.

### 3.2 몸 감각과 시각의 역할 분담 시험

- **선행 판단:** 현재 속도·회전·하중이 비슷하지만 앞으로 좌/우 코너나 제동 필요가 다른 장면에서 예측·조작이 적절히 갈리는지 검사한다.
- **안정화:** 비슷한 경로 영상에서 차체 기울기·회전·하중·접지 조건이 다를 때 조작 보정이 달라지는지 검사한다.
- 단일0 clamp 외에 시야별 가림, 과거 영상 유지, 시간 순서 교란, 상대적으로 장면과 몸이 맞는/어긋난 통제 진단을 구분한다. 교란 자료를 실제 동기화 학습 자료로 편입하지 않는다.
- 비교는 원래 에피소드를 각각 연속 재생한 상태에서 한다. 구간을 이어 붙이거나 회로 상태를 임의 reset해 유리한 반응을 만들지 않는다. 조명/HUD/고정 출발 순서의 대리 신호도 검사한다.
- 기존 zero clamp는 분포 밖 입력일 수 있다. 개입 오차 증가 하나만으로 생리적 인과나 일반화를 선언하지 않는다.

## 4. R2: 미래 예측을 같은 회로에 붙이는 방법

1. 보조 판독은 **기존 통합 회로의 상태/감각 경계**에서 출발한다. 별도 지도 운전자나 CNN이 차량 출력을 대신 내는 우회 경로를 만들지 않는다.
2. 제안 horizon은0.25/0.5/1/2초다. 물리 제동거리·영상 가시범위·현재 처리 예산을 개발 자료로 확인한 뒤 확정한다. 짧은 horizon 하나만으로 고속 코너 선행 판단을 검증하지 않는다.
3. 제안 목표는 미래 경로의 좌/우 변화, 통과 여유/경계 접근, 감속 필요와 미래 조향·페달 계획이다. 미래 차체 yaw만 맞추면 현재 몸 회전의 외삽으로 풀 수 있으므로 도로 형태/제동 목표와 몸·시간 비교군을 함께 둔다.
4. 지도·미래 곡률·교사 rollout·world pose는 **학습 정답/손실·critic·평가 생성에만** 쓴다. 추론에는 실제 영상·허용된 몸 감각·그로부터 계산한 예측만 제공한다. 정답 waypoint·곡률·절대 heading·진행률·교사 조작을 actor에 주입하지 않는다.
5. 조작 모방 손실과 보조 예측 손실의 비중은 train/dev로만 정한다. 미래 라벨은 에피소드 경계를 넘지 않으며 관측 접두부까지만으로 예측한다. 실제 미래 정답이 현재 recurrent state에 들어가지 않게 데이터 계약을 검사한다.
6. 몸 감각을 무작정 끄지 않는다. 필요 시 train-only에서 감각별 정규화·loss balancing·조건부 학습을 비교하되 현실 결측 처리와 실험 개입을 구분한다. 최종 승격은 모든 정상 감각을 함께 쓸 때의 성능으로 판정한다.
7. 첫 비교는 현 checkpoint 대조, 공간 보존만 변경, 예측 보조 목표만 변경, 병목 수정 후 결합의 순서다. 한 번에 전부 바꾸어 기여 원인을 잃지 않는다.

고정된 실측 화학 연결·보호된 몸 감각 경계와 기존 checkpoint는 먼저 보존한다. 새 실측 세포/연결을 도입하거나 동역학을 바꿔야 한다면 새 버전·근거·부품 검증을 등록한다. 생리 근거 없는 연결 조작을 기존 실측 회로의 학습으로 바꾸어 부르지 않는다.

## 5. R3/R4: 미학습 트랙이 드러내는 성능

### 데이터 구성과 교사 제약

- 첫 확장안은 서로 다른 **학습3트랙·개발1트랙·봉인시험2트랙**이다. 이는 가용성 확인 전 제안이며 트랙 이름/교사/시도 수는 수집 전에 확정한다. 부족한 경우 축소된 범위만 주장한다.
- 현재 세션·카메라 도구에는 BMW/Monza 식별과 차량 전용 camera mount 등 조건이 있다. 새 트랙/차종 전에 설치 콘텐츠와 교사 가용성을 목록화하고, 예상 식별/좌표·camera mount·조작 단위의 버전 계약을 확장해 독립 확인한다. 트랙 변경 API가 검증되지 않았다면 외부 선행 조건으로 남기며 AC UI 조작으로 우회하지 않는다.
- 700만 SAC는 현재 BMW/Monza에서 검증됐다. 다른 트랙에 그대로 보내면 교사도 일반화한다고 가정하지 않는다. 다른 공개 교사·검증된 시연 경로를 먼저 해당 차량/트랙에서 재현하고, 적격 교사를 확보하지 못한 트랙은 학습 자료나 성능 기준으로 쓰지 않는다.
- 같은 트랙의 다른 날씨·방향·차량·부분 구간을 독립적인 새 트랙으로 세지 않는다. 차량 조건 비교와 트랙 일반화 시험은 별도 축으로 설계한다.
- 좌/우·S자·급/완만 코너·고저·제동/탈출·접지 변화 등으로 자료 분포를 감사한다. 단순 반복 직선 프레임 수로 확대를 대신하지 않으며 라벨/구간 가중치는 개발에서 고정한다.
- 정규화 통계·pooling 선택·horizon·loss 비중·학습 횟수·적응 규칙은 train/dev에서만 확정한다. 시험 영상이나 시험 통계로 이들을 맞췄다면 해당 시험은 소비된 것으로 표시한다. 동결 전처리를 시험 자료에 적용하는 것과 시험 자료로 전처리를 학습/선택하는 것은 구분한다.
- 기존Monza heldout은 이미 결과를 보았으므로 **회귀/개발 비교용**으로 남긴다. 새 일반화의 최종 시험으로 재사용하지 않는다. 최종 test를 진단/튜닝에 소비했다면 사용 사실을 남기고 새 봉인 시험을 확보한다.

### 고정 비교와 판정

| 비교 | 확인하려는 것 |
|---|---|
| 기존 checkpoint·학습 평균 상수 | 기존 개선의 유지와 단순 평균 예측 이상의 학습 |
| 몸만/시각만/전체 감각의 통제 비교군 | 각 정보의 예측 한계와 상호 보완성. 최종 actor 대체 모델로 취급하지 않음 |
| 경과시간/고정 과제 순서만 쓰는 진단 비교군 | 출발 후 시간·외운 랩 순서만으로 푸는지. 절대 시각/진행률은 최종 actor에 금지 |
| 공간 보존/예측 손실 변경 전후 | 제안한 시각 개선의 실제 추가 가치 |
| 시야·방향·시간·몸 경로 개입 | 어떤 경로가 언제 기여하는지. 전체0 clamp 하나로 끝내지 않음 |

예측 지표는 개발에서 고정한 horizon별 방향/제동 분류와 calibration, 연속량 오차를 포함한다. 조작 지표는 조향·가속·제동별 오차와 코너 진입 전 판단 시점이다. 실제 주행 지표는 **고정된 전체 시도 수 대비 유효 완주율, 이탈·충돌·중단, 유효 랩 중앙값/분산, 코너별 감속·탈출, 하중/타이어 상태, 데이터/제어 지연**이다. 시각 기여는 특정 가림 퍼센트를 목표로 하지 않고 예측과 미학습 조건의 주행 개선을 함께 요구한다.

고정 예산에서 같은 조건/seed로 쌍을 이뤄 비교하고 실패를 분모에서 빼지 않는다. 시스템 감각 실패와 조작 실패를 분류하되 end-to-end 성공률과 유효 감각 조건부 결과를 모두 보고한다. 에피소드별 분산/불확실성을 제시하며 수천 개 연속 프레임을 독립 시험 수로 계산하지 않는다. 안전 제어기의 잦은 대행·속도 강제 제한으로 얻은 완주를 학생 자율 완주로 세지 않는다.

## 6. R5/R6: 몸의 차이에 적응하고 더 빨라지기

- 먼저 차체 기울기/회전·가속도·하중·타이어 상태의 단위·축·부호·원본 시간을 다시 검증한다. 현재 미검증인 가속3축과 pitch/roll 회전율은 검증 전 valid로 바꾸지 않는다. 상대풍도 독립적인 출처·좌표·시간 계약을 갖춰야 한다.
- 속도·휠 회전·하중·차체 크기·조향 범위 등을 공통 물리 표현으로 정리한다. 차량 고유 값이 필요하면 알려진 파라미터와 학습한 적응 상태를 구분하고 절대 위치/지도 누출을 막는다.
- 변속은 출력 단위·부호·허용 시점·실제 적용 확인을 먼저 계약한다. 셋업은 게임이 지원하는 정차/피트 등 검증된 시점의 느린 조작으로 다루며 주행 중 임의 변경을 전제하지 않는다. 여러 시간 척도의 출력도 같은 감각운동 상태를 공유하고 별도 최종 운동 뇌로 분리하지 않는다.
- 미학습 트랙/알려진 차, 알려진 트랙/미학습 차, 둘 다 미학습, 타이어/셋업 변화의 평가를 나눈다. 무적응과 제한 적응의 데이터·시간·reset 허용 범위를 먼저 봉인한다. 새 차마다 전부 재학습한 결과를 무적응 범용성으로 부르지 않는다.
- 안정적 유효 완주 이후 RL/critic을 결합하는 후보를 검토한다. critic/보상만 지도·진행률·정답 라인 등 특권 정보를 사용할 수 있다. actor의 입력 경계와 초파리 구조는 유지한다.
- 보상은 유효 진행/시간 개선과 이탈·충돌·타이어/과도한 조작을 함께 검증하고 단위 오류·보상 편법을 검사한다. 단일 최고 랩보다 반복 유효 랩 분포를 먼저 비교한다. 같은 차종/트랙/타이어·연료·assist·셋업 조건을 묶어 비교하며 다른 차종의 절대 랩타임을 곧바로 우열로 매기지 않는다. 차량/셋업에 따라 빠른 라인이 달라짐을 인정한다.

## 7. 다음 실행 묶음과 공통 제약

**다음 착수 순서:** R0 기준/자료 목록 고정 → R1 시각 전달·공간 pooling·readout/학습 감도 진단 + 몸 축 등록 계획 → 결과에 따라 R2 후보 하나와 다중 트랙 교사 확보 설계 봉인. 이번 요청에서는 계획 문서만 갱신하며 시뮬레이터·학습을 새로 시작하지 않는다.

각 단계는 `runs/`에 계획/config·source revision/hash·seed·범위·통과 기준을 먼저 기록하고 원본·실패·종료 사유·소스/자료 해시를 보존한다. 새 구조/목표의 보조 결과를 기존의 생리/주행 완료로 덮어쓰지 않는다.

- actor의 경로 판단은 전후좌우 영상과 허용된 몸 감각에서 나온다. HUD/정답선·지도·pose·진행률·미래 정답·교사 출력의 우회 주입을 금지한다.
- 기존 몸50ms·영상150ms·결정40ms·bounded 정합25ms는 유지한다. 새 폐루프에서 실제 acquisition→회로→actuator 시간과 오류 중단을 별도 검증한다. 지연이 나면 예산을 늘려 통과시키지 않는다.
- 회로의 수치 상태를 연속 유지하고 episode 경계/명시적 새 재생에서만 reset한다. 실제 결측은 mask/오류로 표시하고 교사 truth로 채우지 않는다.
- AC 데스크톱 창을 자동화하지 않는다. 검증된 CSP lifecycle API와 background 감각/제어만 쓰며 API 실패 뒤 UI fallback을 하지 않는다.
- 원래 측정/생리 근거·기능 근사·차량 대응 가설·학습 어댑터를 구분한다. 단순 완주, 그래프 통과, 모방 오차, 부품 반응은 각각 별도 단계다.

## 8. 최종 완료 판정

**기전 축:** 겹눈의 방향/시간/운동 시각과 공간 단서, 비행 유래 균형·운동 경로, 차체 기울기·회전·하중·타이어 되먹임이 계획한 반응과 개입 효과를 보이고 통합 회로에서 기여한다. 생리 근거가 없는 부분은 가설/근사로 남긴다.

**운전 축:** 학생이 정상적인 모든 감각을 함께 사용해 조향·가감속·변속/적응을 수행하고, 사전 봉인한 미학습 트랙·차량/셋업에서 유효 완주·반복 안정성·라인/랩타임 개선을 보인다. 필요한 제한 적응은 비용과 함께 분리 보고한다.

두 축을 함께 충족해야 장기 목표의 완료를 판단한다. 시각 기여 점수만 커지거나 교사만 빨라진 경우, 한 트랙의 라인을 외운 경우는 최종 완료가 아니다.
