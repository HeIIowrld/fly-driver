# 시각 명령의 학습 안정성 진단

기록일: 2026-10-29, Asia/Seoul. [대전제](PROJECT_CHARTER.md)는 유지한다.
이번 실험은 누락된 상위 시각 경계의 공학적 학습 방법을 진단한다.
실측 초파리 시각→하행 연결이나 실제 운전 능력을 입증하는 시험은 아니다.

후속 새 자료/추종 진단은 [주행선 OFF 기록과 구간별 진단](flight-aid-free-recording-and-tracking-20261029.md)을 따른다.

## 기존 실패에서 확인한 것

`t1101`은 기존 v6의 초기 상태와 epoch06을 학습 기록 3개에서만 검사했다.
개발 배열은 열지 않았고 체크포인트를 선택하거나 저장하지 않았다.
원래 에피소드의 시작부터 상태를 재생했으며 모든 원래 시각과 무표적 prefix를 유지했다.
과거 영상의 보조 주행선 부재는 여전히 미확인이다. 이 자료는 이번 진단에만 사용한다.

- 초기 조향 명령 전류는 네 포트 모두 0.003이었다. epoch06에서는 학습 기록마다
  거의 0 또는 1까지 치우쳤다. 첫 기록에서 포트별 28.0~67.8% 관측이 0.1을 넘었다.
  실제 생리 전류 단위나 생물학적 발화율의 측정값은 아니다.
- 미리 정한 첫/마지막 표적 포함 64관측 chunk 6개 중 하나는 현재 chunk와 미분 연결이 없는
  표적 하나만 있어 업데이트를 건너뛰었다. 나머지 5개에서는 초기 상태의 독립적인 첫 Adam
  업데이트가 모두 원래 prefix를 재생한 뒤의 조향 RMSE를 줄였다.
- 따라서 첫 업데이트 자체가 항상 잘못된 방향이거나 학습률 하나만 원인이라고 결론 내릴 수 없다.
  다섯 독립 probe는 원래 216회 순차 업데이트와 optimizer 상태를 재현한 것이 아니다.
- 같은 과거 상태를 유지한 계산과 새 가중치로 원래 시작부터 다시 계산한 결과에 차이가 있었다.
  학습 중 가중치를 바꾸며 유지하는 과거 상태와 고정 가중치 전체 재생을 구분해야 한다.

원본: [학습 전류·업데이트·상태 대조](../runs/flight-visual-step-audit-20261029-t1101/result.json).
실행 handle 32485는 종료 코드 0으로 끝났다.

## 실행한 통제 실험

설정: `configs/flight-visual-guarded-training-20261029.json`.
구현: `scripts/train_flight_visual_guarded.py`.

1. 동일한 초기 v6와 학습 전용 정규화를 쓴다. 모든 v5 상속 상태는 고정한다.
2. 한 학습 pass 동안 가중치를 바꾸지 않고, 원래 기록 전체를 순서대로 재생한다.
   chunk마다 상태를 detach하지만 수치는 유지한다. 미분은 64관측에서 잘린 근사다.
3. chunk 크기가 달라도 각 교사 표적의 비중이 같도록 표적 수로 가중해 기울기를 합친다.
4. epoch마다 Adam 제안 하나를 만들고, 원래 시작부터 고정 가중치로 재생한 전체 학습 손실이
   감소하는 경우만 적용한다. 최대 8개 step 크기를 확인하며 모두 거절되면 가중치와 Adam
   내부 상태를 함께 복구한다. 개발 자료로 수락 여부를 정하지 않는다.
5. 고정 6epoch의 마지막 상태를 기록한다. 개발 입력·정답은 열지 않는다.
   시각 제거와 몸 회전 피드백은 학습 기록에서 별도로 검사한다.

이 방식의 성공 조건은 전체 학습 손실 감소이며, 시각 일반화·생리 기전·실제 차량 안정화·
유효 완주·랩타임 개선과 구분한다. 이전 216회 업데이트와 업데이트 수가 달라 성능의 공정한
최종 비교 실험도 아니다. 이후에는 적격한 새 영상과 독립 조건에서 따로 검증해야 한다.

## 입력 적격성과 실행 상태

생산자뿐 아니라 `ac_csp_vision.py`의 감각 소비자도 `ideal_line_shown=false`와
`aid_probe_only=false`의 명시적 boolean을 요구한다. 누락·미확인·ON·진단용 프레임은 거부한다.
두 필드는 원본 metadata 해시와 함께 소비자 stream/decision 기록에 남긴다.

`t1104`는 창을 앞으로 가져오지 않고 OFF 프레임 9개를 수신하고 감각 처리 1회를 기록했다.
요청한 25회 계측은 일시정지 중 새 native physics packet을 받지 못해 실패했다.
자료를 주행 학습에 채택하지 않았고 자동 재개/재시작도 하지 않았다.
`t1105`에서 보관 파일 52개와 9프레임의 metadata/영상/RGB 해시·OFF 조건을 대조했다.
이 검사는 과거 기록 전체의 주행선 부재를 증명하지 않는다.

관련 검사: 기존 회로/세션 161개, guarded 학습 4개, 영상 소비자 20개,
캐시 대기/보관 9개 통과. 수정 Python의 Ruff도 통과했다. 전체 저장소 시험은 아니다.
모든 이번 소유 프로세스는 종료됐다. 마지막 `t1106` 상태는 paused/AIoff/cameraoff/gas0/brake1,
주행선 OFF·창 비전면이었다. 후속 실행 때 다시 읽는다.
