# GPU 자원 확대 — 2026-10-28

기존 복구 학습 t574는 AMD Radeon RX 9070 XT에서 64 epoch를 완료했다. 파라미터·관측·목표·기울기의 장치는 `cuda:0`이며, AMD HIP 런타임에서 사용하는 PyTorch 장치 이름이다. 최대 텐서 할당량은 5,248,643,072 bytes(4.888 GiB), epoch 중앙 시간은 18.566초였다. 이는 GPU 사용률이나 실제 상주 메모리 전체를 뜻하지 않는다.

체크포인트 SHA-256은 `0c0a1a8edb9298f6cf1d917b8f9dbc913580c2154c2683cca26dc22fb40072f9`로 결과 파일과 일치함을 확인했다. 학습 자료 내 조향 RMSE는 0.11587에서 0.05771로 감소했지만, 별도 게임 주행 성능을 검증한 결과는 아니다.

## 적용

- 설정: `configs/ac-countersteer-resource-gpu-suite.json`
- 실행: `runs/ac-countersteer-resource-gpu-suite-20261028-t581`
- 학습 후보: t582(제동 양성 가중치 2), t583(가중치 4).
- 동시 작업 1개에서 2개로 확대. 각각 64 epoch로 제한한다.
- 기존과 같은 source499 초기 모델, seed 862953, 11,999개 상태/18개 원본 에피소드, 배치 18, chunk 64, 성공 구간의 고정 정책 목표 1,512개를 사용한다.
- 순환 신경 상태는 각 에피소드 안에서 유지하며 chunk 경계에서는 기울기만 분리한다. 구조적 연결 가중치는 고정한다.
- 두 후보는 부족한 제동 반응을 개선할 수 있는지 비교하기 위한 실험이다. 제동 가중치를 올리면 불필요한 제동이 늘 수 있으므로 기존 성공 구간의 퇴행도 별도로 평가해야 한다.

단일 작업의 기존 최대 할당량을 바탕으로 두 작업 합계 약 9.8 GiB를 예상했다. 그러나 실제 병렬 준비 중 어댑터 전용 메모리는 16,506,015,744 bytes, 공유 메모리는 7,282,626,560 bytes로 관측됐다. Fusion 360과 llama-server도 실행 중이었다. 프로세스별 카운터는 합산하지 않았으며, compute 카운터 합이 100%를 넘은 샘플은 전체 사용률 판정에 사용하지 않는다.

이에 소유권을 확인한 t583 프로세스 PID 9552만 중단하고 t582 PID 45876은 계속 실행했다. t583에는 체크포인트와 학습 장치 확인 파일이 없었으며 중단 사유를 해당 실행 폴더의 `resource-stop.json`에 남겼다. 초기 병렬 실험의 실패 기록은 그대로 보존한다. 중단 후 어댑터 전용 메모리는 13,688,254,464 bytes, 공유 메모리는 4,074,008,576 bytes로 관측됐다. 공유 메모리 수치만으로 전부 페이지 이동 비용이라고 단정할 수는 없지만, 현재 두 학습 작업을 상시 병렬 실행할 여유가 있다는 가정은 철회한다.

실행 확인 수치는 같은 suite 폴더의 `resource-verification.json`에 저장한다. 최종 상태는 제동 가중치 2 후보 한 개의 유한 GPU 학습이며, 다른 앱을 중단하거나 우선순위를 바꾸지 않았다. 단일 작업의 메모리 할당량만 보고 카드 전체가 유휴 상태라고 판단해서는 안 된다.

## 판정 범위

동시 학습은 단일 모델의 epoch를 두 배 빠르게 만든다는 뜻이 아니다. 비교 후보 전체의 처리량을 늘리는 것이 목적이다. 기존 단일 작업과 새 동시 작업의 epoch 시간을 함께 기록하고, 초기 준비 시간을 포함한 총 완료 시간은 suite 종료 후 판정한다.

두 학습은 화면 조작이나 게임 제어를 하지 않는다. 기존 게임 프로세스나 다른 작업은 종료하지 않았다. 실제 서킷 완주와 모델 승격은 아직 검증되지 않았다. 학습 완료 후 제동 양성·음성 오차, 성공 구간 회귀와 별도 주행 시험을 확인해야 한다.

## 추가 처리량 측정 — t689/t690/t691

이후 t582는 정상 완료됐다. 최신 t682는 기존 출력 뉴런을 한 번 재생해 캐시한 뒤 가속 readout 파라미터 5개만 1,000회 최적화한 작업으로, GPU에서 약 31.65초에 완료됐다. 작은 최적화 작업의 낮은 사용률만으로 전체 회로가 CPU에서 학습된다고 판단할 수 없다. 이 측정 시작 시에는 학습 프로세스가 실행 중이지 않았다.

RX 9070 XT에서 같은 체크포인트 t682, 등록 데이터 t647의 앞 3개 원본 clip, offset112의 실제 순환 상태, 4 ticks/decision, cached CSR, 시각·기관 연결의 순전파/역전파를 측정했다. 각 길이마다 예열 1회와 측정 2회다. optimizer 업데이트·게임 조작은 0회이며 CPU와의 수치 비교는 이번 측정에서 생략했다. 짧은 clip의 패딩은 처리량 분자에서 제외했다.

| 연속 길이 | 유효 관측/측정 | 중앙 시간 | 유효 관측/초 | 최대 텐서 할당량 |
|---:|---:|---:|---:|---:|
| 64 (t689) | 129 | 0.3973초 | 324.71 | 567,478,272 bytes |
| 128 (t690) | 257 | 0.7154초 | 359.26 | 911,754,752 bytes |
| 256 (t691) | 513 | 1.5049초 | 340.88 | 1,600,714,752 bytes |

이번 짧은 측정에서는 128이 64보다 약10.6% 높았다. 256은 메모리를 더 쓰면서 128보다 느렸다. 다른 시간 구간·패딩 비율·앱 부하가 있어 전체 epoch 속도 향상을 증명한 결과는 아니다. 연결의 전체 readout 최적화나 데이터 로딩 시간도 이 구간 처리량에 포함되지 않는다.

`configs/ac-engine-ai-registered-receipt-throughput-training.json`에 단일 worker, 길이128의 다음 실험 설정을 준비했다. **아직 이 설정으로 모델을 학습하거나 승격하지 않았다.** 길이 변경은 역전파 범위도 바꾸므로 별도 회귀·주행 검증이 필요하다. 신경 수치 상태는 chunk 사이에 유지하고 기울기만 분리한다. 기존 체크포인트와 성공 기록은 그대로 보존한다. 실시간 수집과 GPU 학습은 순서대로 실행한다.


## 최신 모델·6개 에피소드 재측정 — t792/t793/t794

2026-10-28 추가 요청에 따라 최신 후보 t751과 등록 자료 t746의 원본 에피소드 6개를 모두 묶어 비교했다. 시각·기관·readout 전부를 미분 대상으로 설정했다. 각 길이에서 예열 1회, 측정 3회이며 실제 GPU 순전파와 역전파를 수행했다. 모델 업데이트와 게임 조작은 각각 0회다. 학습 프로세스가 없는 상태에서 시작했으며 다른 앱은 종료하지 않았다.

| 길이 | 유효 관측/초 | 최대 텐서 할당량 | 실행 |
|---:|---:|---:|---|
| 64 | 742.03 | 0.881 GiB | runs/ac-resource-sixclip-chunk64-20261028-t794 |
| 128 | 724.75 | 1.522 GiB | runs/ac-resource-sixclip-chunk128-20261028-t792 |
| 256 | 719.09 | 2.805 GiB | runs/ac-resource-sixclip-chunk256-20261028-t793 |

모든 파라미터·기울기는 AMD HIP의 `cuda:0`에 있었고 기울기는 유한했다. 동일한 offset112의 원래 순환 상태에서 시작하고, 반복 사이에서만 같은 초기 상태를 복원했다. 각 길이의 처리량에는 실제 관측만 포함했다. 전체 epoch, optimizer 비용, 모델 품질을 비교한 결과는 아니다. 길이가 달라 관측 구간과 역전파 범위도 다르다.

256은 128보다 텐서 메모리를 약1.84배 쓰면서 처리량은 약0.8% 낮았다. 64의 약2.4% 우위는 짧은 측정이며 역전파 범위도 짧아진다. 따라서 기존 단일 worker·길이128·원본 에피소드 전체 배치를 유지한다. 현재 학습 설정의 `episodes_per_batch: null`은 이 자료에서 이미 6개 전체 배치를 뜻한다. GPU 사용을 제한하는 인위적인 대기나 CPU 학습 설정을 발견한 것은 아니다.

어댑터 전용 메모리는 측정 전후 10,821,533,696 bytes, 128 측정 중 한 샘플에서 13,357,522,944 bytes였다. 다른 앱과 드라이버 사용량이 포함되며 이 수치는 PyTorch 텐서 할당량과 다르다. 이번에는 GPU 사용률 백분율을 측정하지 않았다. 이전 두 학습 동시 실행의 메모리 부담을 고려해 동시 작업 수는 늘리지 않았다.

기계 판독 기록은 `configs/ac-gpu-throughput-verification-20261028.json`에 보존했다. 벤치마크에 에피소드 배치와 readout 미분 선택 옵션을 추가했고 Ruff 검사를 통과했다. 새 모델 학습·승격·주행 성능 향상은 이번 측정으로 주장하지 않는다.
