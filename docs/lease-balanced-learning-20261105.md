## 전달과 정지

- 과거 시도의 source lease 만료와 별도로, pause 자식이 manifest 전에 30초를 넘긴 실패와 명령 발행 뒤 새 heartbeat를 입증하지 못한 실패가 있었다. 매 결정의 원래 생성·capture·body first receipt 시각과 단일 tick 소유권을 유지하면서, GPU/호출자 RPC 대신 CPU 생산자 → 단일 슬롯 공유 메모리 → 독립 CPU actuator로 직접 전달한다. 읽는 중 쓰기·손상·동일 순번·종료 뒤 남은 값은 채택하지 않는다. 새로운 timestamp나 이전 결정 재전송으로 lease를 연장하지 않는다.
- 실제 SDK 호출 전에 lease·정지 신호·native guard를 검사하고 guard 뒤 다시 확인한다. source가 끊기면 정지·확인·장치 해제하며, 계획된 관측 종료와 source lease 만료를 따로 기록한다. body 50ms, view 150ms, source-render 25ms, RPC 50ms 및 1초/100결정/10km/h/1m 상한은 유지한다.
- pause는 독립 CPU에서 원래 CSP 스크립트를 미리 가져오고 해시를 확인한다. 발행 전 원본 검증, 로컬 intent 기록과 실제 요청, immutable terminal 및 새 heartbeat 증명은 원래 코드 그대로다. NAS 증거 저장만 API 경로 밖으로 옮겼다. 명령을 자동 재발행하지 않는다.

## 저속 출발과 고속 데이터의 동시 학습

기존 진단에서 native 1단과 자동클러치 동작을 확인했다. 출발 지원이 없는 학습 구간에서 생긴 낮은 구동 대비 제동을 학습 문제로 다뤘다. 기존 냉간 40°C/고온 110°C TRAIN에서 페달 제한이나 변속 타력 구간을 거치지 않은 실제 저속 라벨 131개(66/65)와 고속 5,659개(2,851/2,808)를 사용했다. 별도 명목 80°C development는 최적화나 반복 선택에 넣지 않았다. 이미 쓰던 Monza 자료이므로 새 미사용 주행에서의 일반화 증거는 아니다.

조향, 겹눈/운동 시각, 몸 감각, 비행 유래 하행·반복 회로는 고정했다. 조향 출력은 동일 입력에서 정확히 같다. 처음에는 각 계열에 affine 14계수 및 균형 근육 대리값의 국소 RBF 48계수를 따로 비교했다. RBF는 저속에 유용했지만 development 고속 제동 RMSE가 원본 대비 부모 1.61%, 후보 2.33% 늘어 실제 주행에 사용하지 않았다. (MSE는 각각 약 3.25%, 4.71% 증가.) 첫 affine의 저속 개선은 작았다.

최종 모델은 두 계수를 함께 최적화했다. 24개 중심은 TRAIN의 첫 네 균형 근육 좌표에서 뽑았다. 각 TRAIN 회차·페달의 고속 MSE가 원본의 98% 이하라는 제약을 걸고 저속 오차, 고속 라벨 오차 및 계수 이동 벌점을 함께 최소화했다. 두 SLSQP 최적화는 각각 272/285회에 수렴했다. 후보마다 sigmoid 페달을 독립 계산하며 서로 배제시키지 않는다. 파워 근육 좌표에 대한 가속 양·감속 음의 미분 **부호**를 보존했다. 크기는 학습으로 변한다. 원본 manifest의 해당 문구는 `joint-description-clarification-01.json`에서 정정했다. 세계 위치·절대 heading·지도·기어/클러치 진단을 새 actor 입력으로 넣지 않았다.

40°C 후보의 첫 시행은 `View render bound stale while waiting for new scene`에서 닫혔다. 마지막 채택 영상 45번과 다음 수신 영상 46번의 가장 이른 render bound 간격은 151.38ms, 수신 시각 간격은 150.02ms였다. 새 영상이 이전 view의 150ms 기한 전에 도착하지 못했다. 이는 제어 중 결정의 mailbox 소비/lease 만료와 다른 **무장 전 영상 신선도 실패**다. 원래 view 한도를 유지했고 SDK 요청 없이 정지·장치 반환과 pause를 증명했다. 실패 후 이미 발행한 명령을 반복하지 않고, 완전히 정리된 별도 epoch에서 같은 checkpoint로 한 차례 독립 시행을 정했다.

## 시각·몸·비행 회로의 국소 출력 기여

80°C 실제 출발 부모/후보의 마지막 SDK 결정까지 재생했다. 개입은 마지막 16결정에만 적용했다(동일 prefix 부모 37개, 후보 56개). 모든 분기에서 정상과 개입의 prefix 신경 상태 해시, 근육 및 출력이 정확히 같고 정상 분기는 원본 출력을 차이 0으로 재현했다. 같은 시계·영상 특징·몸 패킷을 계속 넣고 모델 내부 연결 지점만 끈다. 재생은 외부 장치나 CSP를 조작하지 않는다.

| 끈 경로 | 부모 출력 RMSE 변화량 (조향 / 가속 / 제동) | 후보 출력 RMSE 변화량 (조향 / 가속 / 제동) |
|---|---:|---:|
| 연결된 시각 전류: visual + 시각 하행 보정 | .00232 / .15466 / .000042 | .00401 / .15918 / .000003 |
| 미세 운동 전류: 잔차 포트 + 하행의 motion 투영 | .01263 / .06639 / .000047 | .01419 / .06886 / .000015 |
| 몸 전류: 현재 body feedback 출력 | .02228 / .18989 / .000092 | .02080 / .15988 / .000114 |
| 균형 하행 command 성분 (시각 하행 합산 뒤) | .00621 / .11024 / .000040 | .00858 / .12452 / .000007 |

위 수치는 정상 대비 **출력의 RMS 차이**이며 교사 대비 오차가 아니다. 경로가 서로 연결되어 있으므로 효과를 합산하거나 크기 순서로 생리 기능을 판정할 수 없다. 이 출발 구간의 제동은 거의 꺼져 있어 입력 차단의 제동 효과가 작은 것을 고속 제동 기여 부족으로 일반화할 수 없다. 몸 전류 개입은 모델의 다른 속도 경로까지 차단한 것이 아니다. 화학 연결 개입은 기존 모형 행렬을 0으로 만든 비교이며, 특정 실측 시냅스나 날개의 기능을 새로 검증한 것이 아니다.

초기 `parent80-components-01`은 화학 연결을 끈 첫 결정에서 CSR 캐시 재생성이 추론에 포함돼 180.3ms로 body 50ms를 위반했다. 이 실패를 남겼고 경계는 완화하지 않았다. 이후 원래 backend 초기화처럼 버릴 상수 텐서로 희소 캐시만 준비했다(회로 recurrent step 0). 정상과 개입 prefix 상태가 같음을 다시 검증한 뒤 80°C의 두 계열에서 모든 분기를 완료했다. 상세 출력과 여섯 근육 대리값은 `balanced-parent80-components-02`, `balanced-candidate80-components-02`에 있다.

구간 제한형에서도 각 16결정에 같은 개입을 별도 반복했다. 정상과 prefix는 정확히 일치했다(부모 46, 후보 35결정). 예를 들어 미세 운동을 끈 가속 RMS 차이는 .09781/.07463, 몸 전류는 .11649/.09208, 화학 전달은 .38152/.46220이었다. 초기 기록이 다른 계열 간 크기 차이로 하행/몸 회로의 생리적 기능 차이를 판정하지 않는다. 전체 분기는 `phase-parent80-components-01`, `phase-candidate80-components-01`에 있다.
