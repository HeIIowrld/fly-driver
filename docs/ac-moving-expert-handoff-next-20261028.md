# 다음 실제 데이터 수집: 주행 중 학생→AI 전환

원래 계획 문서다. 이후 별도3초 전환 모드를 구현하고 실제 t763 시험을 완료했다. 구현·실제 검증 결과는 `docs/ac-moving-expert-handoff-verification-20261028.md`에 기록한다. 아래 요구사항을 기존 준비·수집 모드나 학생의 서킷 자격으로 통과 처리하지 않는다.30초 확장은 아직 미검증이다.

## 현재 근거

source723은 실제60m를 통과했지만240m 시험 t733에서20.016874km/h로 속도 상한을 넘었다. t735에서692회 원본 입력/요청 재생 차이0을 확인했다. 정차 후 시작한20→15 AI 자료 t742는 실제 회복에 성공했고, 목표15 단계만 t745에 봉인했다. 그러나 이 AI 출발은 원래 실패 순간의 속도·조향·시각 이력과 다르다.

고정 가속 출력부 t737/t747 및6계수 비교 t749는 사전 채택 조건에 실패했다. 감각/기관 연결까지 학습한 t751도 실제 실패 입력 마지막 요청에서 가속0.07177→0.07153으로 거의 변하지 않았다(t757). 교사 자료의 평균 가속 중단 출력 개선만으로 실제 과속 해결을 주장할 수 없다.

## 필요한 별도 경로

정차 후 전문가를 출발시키는 방식을 반복하는 대신, 유한 학생 주행 도중 미리 정한 속도에서 AI로 제어권을 전환해 실제 입력·실행 제어를 수집한다. 초기 검증은 약17km/h 전환, 학생20km/h 상한 이내로 시작한다. 새 교사 전환은 기존 stationary-start expert 모드와 별도 이름·capability·영수증으로 구현해야 한다. 기존 모드를 느슨하게 바꾸거나 런처/UI로 대체하지 않는다.

필요한 순서는 다음과 같다.

1. 같은 소유 Python 프로세스가 vJoy 학생 세션·고정 카메라·실제 센서 쌍을 가진다. 학습 모델은 실제 주행을 하고, 진단 속도는 전환/중단 조건에만 쓴다.
2. 유한 카메라 lease가 AI 관측·정지까지 충분히 남아 있고, 같은 엔진·CSP generation/epoch·오프라인 차량/트랙·타이어0 상태임을 확인한다. 기존 기본 명령의 vJoy FREE·정차 조건을 전역으로 제거하지 않는다.
3. 전용 전환 요청을 한 번만 기록하고 AI 활성화/목표15/조향0.9를 소유한 lease로 실행한다. 움직이는 상태를 허용하는 것은 이 전용 데이터 수집 모드뿐이다. 초기3초 검증, 이후30초 확장은 실제 영수증과 종료 검증 후 판단한다.
4. 원래 vJoy 소유권을 입증한 같은 프로세스에서만 전환을 요청한다. AI 활성화를 확인하기 전 임의로 학생 출력을 계속 보내거나 소유자를 빼앗지 않는다. 확인 후 학생의 추가 요청을 중단하고 기존 브레이크1 close를 반환한다. AI가 사용하는 동안의 별도 제어권과 종료 후 native 브레이크 복귀를 실제로 검증해야 한다.
5. unknown/거부/카메라 손실/속도·도로·식별 위반이면 재활성화를 반복하지 않는다. 기존 안전 정지·소유 해제 경로와 한 번의 AI 종료를 사용하고 결과를 그대로 기록한다.

전환 시간·최초 AI 제어·학생 최종 요청·vJoy 해제·AI 종료를 따로 기록한다. 초기17km/h 전환이 정확히 원래20km/h 실패 상태의 질의라고 주장하지 않는다. 유한 초기 시험이 입증되면 실패에 더 가까운 상태의 데이터 수집 범위를 별도 검토한다.

## 데이터·신경 상태

원래 카메라·retina history·네이티브 시간계를 전환 사이에 다시 시작하지 않는다. 학생 구간의 관측 prefix를 보존하고, 전문가 표적은 실제 AI 소유가 확인된 시간창에만 붙인다. 학생 요청을 AI 정답으로 복사하지 않는다. 오프라인 신경 재생은 원래 에피소드 시작에서 출발해 prefix까지 이어가며 전환 시 numerical state를 임의로 리셋하지 않는다. prefix의 전문가 action mask는0이다.

현재 sealer/load_episodes는 봉인 에피소드 전체에 적어도 하나의 유효 표적을 요구한다. 전문가 구간이 없는 실패 전환은 보존만 하고 학습 데이터로 봉인하지 않는다. 새 schema가 필요하면 기존 미래 수신값 계약을 묵시적으로 재해석하지 말고 실제 raw hash·제어 role·시각창·누락을 명시적으로 검증한다. 실행 제어는 내부 AI 요청 시각을 안다는 뜻이 아니다.

## 검증 범위

실제 Lua 흐름에서 소유 카메라·lease·속도·타이어·generation/epoch·중복/unknown·종료 경로를 검사한다. 학생 중 추가 AI 액션 혼합이 없고, 전환 후 학생 요청이 더 나오지 않음을 확인한다. 원본 영상/기관 배열·prefix·AI 시간창·제어 범위/코덱을 재생 감사한 뒤에만 학습에 쓴다. GPU 학습과 live 영상 수집은 순서대로 수행한다.

이 경로는 학습 데이터를 얻는 수단이다. AI 주행을 학생의 서킷 완주로 세지 않는다. 최종 검증에는 전체 서킷 동안 학생의 연속 신경 상태, 실제 유효 랩/코스 진행, 교사 미사용, 영상·기관 입력과 실행 제어가 별도로 필요하다. 일반 제동·타이어/하중/셋업 최적화도 계속 미검증이다.
