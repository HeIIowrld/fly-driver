# FlyBrain 프로젝트 현실성·진행 상태 검토

검토일: **2026-10-27, Asia/Seoul**. 현재 기본 브랜치 `9b8b45f`, 별도 critic 연구 커밋 `0cd8a5f`, 2026-10-05~10-18 실험 산출물을 확인했다. 이번에는 추가 학습·원격 작업·실차 출력을 실행하지 않았다. 아래의 과거 성능 수치는 보존된 결과를 재집계한 것이며, 이번에 같은 학습을 재현한 결과는 아니다.

이후 같은 날 사용자가 **초파리의 감각기관·신경회로와 차량의 몸 피드백을 사용하는 비전 기반 Assetto Corsa 완주**를 최종 목표로 확정했다. 아래 성능 검토는 근거로 보존하고, 앞으로의 범위·우선순위는 [갱신된 연구 계획](research-plan.md)과 [설계안](assetto-fly-design.md)을 따른다. 작은 과제는 이 최종 목표를 향한 검증 단계다.

## 판단

**연구용 시뮬레이터와 RTL 구현은 상당히 진행됐다. 하지만 센서 기반 자율주행은 아직 성공하지 못했고, 초파리 연결 구조의 효과나 새로운 회로의 우월성도 입증되지 않았다.** 프로젝트를 접을 단계라고 보지는 않지만, 현재 방향에서 실험 규모와 기능을 계속 늘리는 것은 효율이 낮다. 먼저 성공해야 할 작은 과제를 정해야 한다.

| 목표 | 현재 판단 | 근거 |
|---|---|---|
| 저속 차량 시뮬레이션·학습 실험 기반 | 구현 성과 있음 | MuJoCo 차량, 양안 영상, 순환 정책, BC/DAgger/PPO, 실패·해시 기록 |
| 센서만 사용하는 안정적인 자율주행 | 미달 | 본학습과 재시도의 최종 평가 총 63회에서 완주 0회 |
| 실제 초파리 회로가 GRU보다 유리함을 검증 | 아직 본 실험 전 | 실제 기능 그래프·포트 매핑 미확보, 주행 결과는 주로 CNN/GRU |
| 상태 전처리+다중 카메라 CNN의 자체 RTL 설계 | 구현 성과 있음 | RTL 검증과 Vivado routed 보고서 보존 |
| 보드에 탑재해 카메라부터 행동까지 실행 | 미완료 | 카메라 수신·DMA·GRU·센서융합·행동 출력과 보드 검증이 범위 밖 |
| 회로의 새로운 기법·확실한 저전력 우위 | 미입증 | 강한 일반 기준과 동일해진 후보가 있고, 전력 차이의 근거도 약함 |

이 표의 구현 성과와 성능 미달은 함께 성립한다. 테스트 통과, 학습 종료, 정수 출력 일치는 각각 소프트웨어 계약·실행·산술 구현의 증거이며 실제 주행이나 인지 성공을 대신하지 않는다.

[critic 후속 연구](../runs/20261006-critic-followup/complete-study/summary.json)에서도 후보 `history_privileged_anchor`는 seed 7301에서 control보다 약15.7% 멀리 갔지만, seed 7302에서는 약12.8% 짧아졌다. 해당 시드의 초기31.08 m → 최종29.10 m였다. 각 실험의 최종4조건도 완주0/4이며, [최종 판정](../runs/20261006-critic-followup/result.json)은 `selected: []`, `remote_proposal: false`다.

따라서 현재 자료에서 확인되는 것은 **정책 보존 장치가 일부 시드의 성능 붕괴를 줄일 가능성**이다. 안정적인 개선이나 완주 성능은 확인되지 않았다. 가치 함수 설명 분산도 마지막 update에서 대체로 0 근처이거나 음수다. 이것만으로 실패 원인을 가치 함수 하나로 확정할 수는 없다.

## 우선 해결할 문제

### 1. BC+DAgger가 독립 주행에 실패한 상태에서 PPO와 변형 실험이 커졌다

[연구 계획](research-plan.md)은 BC+DAgger가 별도 구간을 안정적으로 주행한 뒤 선택적으로 PPO를 적용하도록 정했다. 실제 결과는 그 진입 조건을 충족하지 못했다. 교사 주행 성공과 작은 지도학습 MSE는 학생 단독 주행 성공과 다르다.

현재는 카메라·운동 특징·이전 명령 입력·DAgger 혼합·TV·critic을 동시에 다루고 있다. 이 상태에서 학습 예산만 늘리면 어느 부분이 문제인지 판단하기 어렵다. **평지·저속·고정 속도·조향 하나부터 완주하는 기준선**이 우선이다. PPO의 원인 규명 전까지 BC-only와 BC+반복 DAgger를 분리해 측정하는 편이 낫다.

DAgger는 학생이 방문하는 상태를 반복 수집해 교사 정답을 붙이는 방법이다. 현재 구현의 한정된 round 수가 성공을 보장하지는 않는다. 분포 변화가 실제 원인인지도 센서 입력 제거, 교사/학생 분포, 시간 정렬과 반복 수집 실험으로 확인해야 한다. [DAgger 원 논문](https://proceedings.mlr.press/v15/ross11a.html).

### 2. 회로로 옮긴 CNN은 학습된 양안 정책과 같은 모델이 아니다

[통합 CNN 보고서](../_related_research/FlyBrain_통합CNN_PPA_검증_20261018/report.md)는 기존 18채널 Conv1의 왼쪽 9채널 가중치를 잘라 네 카메라가 공유하도록 했다고 명시한다. 새 4카메라 인지 과제에 재학습한 모델이 아니다. 원래 양안의 채널을 함께 처리하던 모델과 동등한 동작이라고 볼 수 없다.

RTL과 독립 정수 기준이 정확히 일치해도, 그것은 **변경한 계산의 정확한 구현**을 뜻한다. 장애물 인지·방향 분류·차량 주행의 정확도를 뜻하지 않는다. 따라서 현재 CNN을 곧바로 차량의 인지 코어로 채택할 근거는 부족하다.

실제 사용할 과제와 label, 독립 시험 데이터, float 기준의 성능부터 정하고 그 모델을 고정해야 한다. 그다음 고정소수점과 RTL이 그 과제 성능을 얼마나 유지하는지 확인해야 한다.

### 3. 실차 이식의 출발 조건이 아직 없다

[control.py](../src/flybrain_drive/control.py)의 차량 설정은 `illustrative_unvalidated`다. [env.py](../src/flybrain_drive/env.py)는 이상적인 센서, 단순한 휠 접촉·마찰, 잠정 중력 추정과 하중 추정을 사용한다. 실제 타이어, 조향 응답, 센서 지연·bias·누락, 제동·구동 한계와 보정된 모델은 아직 아니다.

이 환경은 정보 흐름과 연구 가설을 시험하는 데 쓸 수 있다. 실차 성능이나 고속 안정성을 예측하는 용도로 해석할 근거는 없다. 특히 현재 실패를 생물학적 구조의 한계로 돌리거나, 반대로 시뮬레이터의 개선을 실차 효과로 확대하면 안 된다.

### 4. 초파리 회로 자체의 유효성은 아직 시험하지 않았다

현재 구현은 일반 CNN/GRU와 합성 희소 회로를 포함한다. 실제 커넥톰 기능 부분 그래프, 주석에 근거한 입출력 포트, 감각·운동 회로 대응은 [구현 현황](implementation-status.md)에서도 미확보·미구현이다. 따라서 현재 결과로 “초파리 뇌가 차량에 유리하다/불리하다”를 판단할 수 없다.

커넥톰을 구조 제약으로 사용해 시각 기능을 연구하는 접근에는 선행 근거가 있다. 하지만 시각 신경 활동·운동 추정의 결과를 차량 주행 성공으로 확장하는 데에는 별도 검증이 필요하다. [Lappalainen 등, Nature 2024](https://www.nature.com/articles/s41586-024-07939-3).

향후에는 같은 센서·전처리·decoder·학습 예산의 GRU와, 실제 부분 그래프 및 차수 보존 재배선 대조군을 비교해야 한다. 지금은 그 비교보다 센서 기반 기준선 완주가 먼저다.

## 회로 쪽은 어디까지 현실적인가

**학부 회로 설계 프로젝트로는 구체적인 성과가 있다. 새로운 저전력 가속기의 우위는 아직 미확정이다.** 보고서 서술만 읽은 것이 아니라 통합 40 MAC의 routed utilization과 내부 setup 보고서도 확인했다. 5,497 LUT와 내부 setup slack +2.490 ns가 기존 보고서와 일치한다.

| 구성 | 클록 | 4카메라 전처리+CNN 지연 | LUT | BRAM36 타일 | DSP |
|---|---:|---:|---:|---:|---:|
| 32 MAC · 작은 버퍼 | 52.632 MHz | 38.115 ms | 5,006 | 86 | 38 |
| 40 MAC | 50 MHz | 32.870 ms | 5,497 | 90 | 46 |
| 48 MAC | 50 MHz | 32.870 ms | 5,366 | 94 | 54 |

출처: [통합 비교](../_related_research/FlyBrain_통합CNN_PPA_검증_20261018/report.md), [40 MAC 자원 원본](../_related_research/FlyBrain_통합CNN_PPA_검증_20261018/vendor/mac40/implementation/utilization.rpt), [내부 setup 원본](../_related_research/FlyBrain_통합CNN_PPA_검증_20261018/vendor/mac40/implementation/internal_setup.rpt).

40 MAC은 50 MHz에서 처리 여유를 갖는 선택이다. 그러나 클록 조정을 허용한 32 MAC도 25fps를 충족한다. 48 MAC은 전처리 병목 때문에 40 MAC보다 빨라지지 않는다. **40이라는 연산기 개수 자체를 새로운 핵심 기법으로 내세우기는 어렵다.**

보드 전체 타이밍은 아직 통과하지 않았다. OOC 경계의 외부 입력 hold 위반이 남아 있고, 카메라 수신·샘플링·DMA·GRU·센서융합·행동 출력은 제외됐다. 32.870 ms를 카메라 촬영부터 차량 명령까지의 전체 지연이라고 해석하면 안 된다.

비슷한 여유의 32/40 비교에서 동적 전력 추정 차이는 약 1 mW다. 직접 활동 주석 매칭은 약15~16%, 도구 신뢰도 Medium이며 보드 실측이 아니다. 현재 증거로 이 작은 차이를 확실한 저전력 우위라고 부르기는 어렵다. [전력 비교·제한](../_related_research/FlyBrain_통합CNN_PPA_검증_20261018/report.md).

[상태 전처리 연구](../_related_research/FlyBrain_전처리_RTL_검증_20261018/report.md)는 강한 일반 기준에도 같은 최적화를 허용한 뒤 후보와 일반 회로가 동일해졌다고 기록한다. 이는 공정한 검토 결과지만, 독립적인 우월성의 증거는 아니다.

최신 [stride-2 희소 Winograd 선별](../_related_research/FlyBrain_메모리주제_사전검증_20261018/topic_results.json)은 3,548,928개 중간 값의 수치 일치와 곱셈 감소 가능성을 확인했다. 반면 `new_RTL_implemented`, `new_PPA_executed`, `new_power_estimated`는 모두 false다. 변환 가중치 계수도 약2.28배 늘어난다. 곱셈 감소율을 전체 에너지 감소율로 바꾸어 말할 수 없다. 제한된 추가 검증 후보로는 의미가 있지만, 지금 새로 RTL 전체를 확장할 확정 근거는 아니다.

## 재현성·이전 시 확인한 사항

- 기본 브랜치는 `9b8b45f`이며, critic 후속 실험은 등록된 별도 작업 폴더의 `0cd8a5f`를 사용한다. 두 소스를 구분해야 한다. 최신 실험 manifest와 기본 브랜치는 critic 관련 소스 5개가 다르며 그중 `critic_features.py`는 기본 브랜치에 없다. 결과 소스가 모두 소실된 상황은 아니다. Git 객체와 별도 작업 폴더가 존재한다.

## 다음 작업의 권장 순서

아래 기준은 **이번 검토의 제안**이며, 이미 달성한 결과나 외부 대회의 규정이 아니다.

1. **하나의 주목표 선택.** 자율주행·생물학적 구조 비교가 목표라면 회로 확장을 잠시 멈춘다. 회로 설계 제출이 목표라면 저속 주변 장애물 유무/방향 인지처럼 작고 측정 가능한 과제로 범위를 고정한다. 현재 둘의 성능 검증을 동시에 끝내려는 범위는 넓다.
2. **자율주행 경로: 쉬운 기준선 먼저.** 평지, 고정 저속, 조향만 학습하고 TV·복잡한 지형·운동 특징 추가를 차례로 분리한다. BC-only와 반복 DAgger의 학생 단독 평가를 비교한다. 예를 들어 3개 학습 시드와 사전 선언한 10개 별도 조건에서 완주율90% 이상을 연속 확인한 뒤 다음 난도로 간다. 이는 실차 안전 기준이 아니라 연구 진행용 기준이다.
3. **실패 원인 측정.** 같은 소스에서 초기/최종 모델의 시간 정렬, 경로·횡오차 추이, 교사 대비 행동 오차, 센서 제거, 영상을 고정하거나 제거한 대조를 확인한다. 카메라가 실제로 필요한 정보를 주는지와 정책이 그 정보를 쓰는지를 나누어 검증한다.
4. **그다음 PPO.** BC+DAgger 기준선이 성공한 상태에서만 고정 예산의 PPO와 no-PPO 대조를 비교한다. 초기 모델을 최고 checkpoint로 다시 고른 결과를 RL 개선으로 계산하지 않는다. 여러 시드에서 유지·개선되지 않으면 RL을 필수로 고집하지 않는다.
5. **회로 경로: 사용할 모델의 정확도부터.** 공유 4카메라 모델을 실제 과제에 학습하고, 데이터 분할과 float/Q14의 과제 성능을 고정한다. 그 뒤 기존 direct 회로와 후보의 전체 지연·자원·배치당 에너지를 동일 입력과 deadline에서 비교한다.
6. **보드 연결과 최종 효과.** 비동기 카메라·누락 처리·입출력 timing closure·실제 보드 전력과 촬영부터 출력까지의 지연을 확인한다. Winograd는 전체 회로 이득이 있을 때만 채택한다. 실제 커넥톰 비교와 실차 이식은 각 앞단 조건을 충족한 뒤 별도 단계로 진행한다.

현재의 가장 중요한 성공 지표는 실험 개수나 MAC 감소율보다 **독립 시험에서 반복되는 작은 과제의 성공**이다.
