# 고속 제동 오차 분리와 다음 실차 조건 준비 — 2026-11-05

초파리의 겹눈/운동 시각과 비행 유래 균형·운동 회로를 자동차라는 가상 몸에 연결한다. 차체 기울기·회전·하중·타이어 상태를 몸 감각으로 되먹임하며 조향·가감속과 빠른 레이싱 라인/랩타임을 학습한다.

이전 [저속 실제 폐루프](lease-balanced-learning-20261105.md)의 구간 제한형 계보를 이어서 조사했다. 새 원본 루트는 `runs/braking-corner-learning-20261105/`다. AC 데스크톱 입력과 임의 페달 보정은 사용하지 않았다. 아래에 실제 학생 권한 전환과 조기 종료까지 기록했다. 후보 승격은 보류했다.

## 남은 오차

원본 decision/QPC 시각과 보정되지 않은 교사 요청만 사용했다. 같은 회차에서 연속 승인된 라벨 사이가 100ms 이내이고 교사 brake가 .1 경계를 넘는 때를 시작/해제로 정의했다. 이후 250ms를 별도로 검사했다. `phase-error-audit-01`의 기존 명목 80°C 개발 기록에서 제동 시작 81표본, 해제 87표본이다. 값은 0~1의 정규화 페달 단위다.

- 시작 직후 가속은 교사보다 부모 +.201/후보 +.202, 제동은 −.212/−.206이었다. 제동이 진행 중일 때도 −.130/−.134였다. 해제 직후에는 제동 +.091/+.085로 반대 방향의 오차가 남았다.
- 같은 81표본의 교사 라벨에 이후 40~80ms의 이미 기록된 출력을 진단용으로 대조하면 제동 RMSE가 줄었다. 원래 시계를 바꾸거나 미래 입력을 actor에 넣지 않았다. 제동 반응 지연과 맞는 관측이며, 지연의 단일 원인이나 최적 제동 타이밍을 확정하지 않는다.
- 기존 전체 고속 오차는 줄었지만 25~40m/s 가속과 40m/s 이상 제동의 국소 퇴행은 남았다. 제동 초기 가속 과다와 제동 부족, 해제 때 남는 제동을 구분해서 다음 목적함수에 반영한다.

## 추가 학습

구간 제한형 두 가중치를 고정한 채, 첫 네 균형 근육 좌표의 유한 지지 영역에서만 두 pedal logit을 추가로 학습했다. TRAIN 고속 표본에서 40개 중심을 결정했다. 지지 반경은 원래 저속 TRAIN 131개와 실제 80°C 출발을 재생한 근육 좌표에 닿지 않도록 제한했다. 조향·시각·비행 하행·근육·반복 상태를 유지한다. 독립 페달과 파워에 대한 부호는 그대로다. 속도, 교사 페달, 시계, 진단 위치는 actor의 새 입력이 아니다. 개발 데이터와 새 교사 회차를 최적화에 사용하지 않았다.

고속 전체·속도대·가속/제동·제동 시작/해제 각 TRAIN 그룹의 두 MSE를 기존 구간 제한형보다 높이지 않는 제약으로 풀었다. 저속 원본 출력 최대 차 0(부모 193·후보 182개 보존 표본), 조향 차 0이다. 이 결과는 표본에서의 동일성을 증명한다. 새 가중치의 다른 출발 상태나 40°C 실제 폐루프를 검증하지는 않았다.

## 고속 시각·비행 회로 비교

기존 개발 기록의 첫 세 분리된 고속 제동 시작(73.87/69.62/51.31m/s)에 대해, 에피소드 처음부터 8,864결정을 순서대로 재생했다. 저장 출력과 최대 차는 부모 3.28e-7, 후보 3.88e-7이며 각 정상 분기는 전체 재생과 정확히 같다. 실제 몸·영상·시각을 고정한 offline 분기에서 회로 상태를 동일하게 맞추고 시각 전류, 미세 운동 시각, 몸 전류, 균형 하행, 파워 하행, 화학 전달을 각각 차단했다. 실제 actor의 실시간 시간 제한은 바꾸지 않았다.

세 구간에서 몸 전류를 끄면 정상 대비 제동 출력 RMS 차이는 부모 .119~.155, 후보 .131~.162였다. 연결 시각 전류 제거는 .021~.098 / .024~.103, 미세 운동 제거는 .002~.018 / .002~.020이었다. 원자료는 `parent-high-causal-01`, `dual_guard-high-causal-01`에 있다. 이는 고속 기록의 국소 모델 의존성과 표본별 교사 오차를 분리한 결과다. 실제 차량에서 경로를 제거한 제동·안정화 효과, 미사용 코너 판단, 측정된 생리 기능을 증명하지 않는다.

## 새 실제 제동 평가 기록

`fresh-monza-develop-01`은 수집 전에 **새 epoch, 동일 Monza, 평가 전용, fit 금지**로 고정했다. 검증된 배경 교사 제어가 한 바퀴(112.602초), 최고 266.06km/h, SDK 교사 요청 3,487회를 기록했다. 학생 요청은 0이다. 원본 속도·페달을 대조해 100km/h 이상에서 보정 없는 교사 제동 351요청과 이후 native brake>.1의 351 관측 창을 검증했다. 이것은 교사 기록이며 학생의 고속 제동 결과가 아니다.

## 이동 정지 계측 전의 실제 시험 계획

새 데이터는 동일 Monza라 미사용 코너의 대체 증거로 쓰지 않는다. 기존 정차 출발 pilot은 10km/h 및 1m 경계이며 moving actor 접수를 지원하지 않는다. 미사용 코너 후보로 설치된 Magione을 읽기 전용 확인했다. 현재 검증된 CSP lifecycle은 BMW/Monza에 묶여 있어 당시 실제 변경/활성화는 수행하지 않았다. 진입 원점·전방축·속도 범위의 정합, 한 SDK 소유자 내부에서 주행 준비와 학생 권한 분리, 높은 초기 속도에서 실제 정지까지 안전 여유가 있어야 한다. 좌표·경로 기준은 진단에만 둔다.

`live-admission-02`는 설치된 Lua SHA를 재확인하고 실제 코드의 Monza 고정 및 외부 race.ini를 받지 않는 restart 조건을 직접 확인했다. repo Lua와 설치 Lua의 해시는 다르므로 repo 텍스트만으로 실제 capability를 판정하지 않았다. Magione은 직접 페달 학습의 기록에는 없지만 전체 부모 계보와 새 세션의 유효한 진입 조건은 아직 검증하지 않았다.

실제 교사 원본에서 `monza-moving-reference-03`의 접근점(133.09km/h·native brake .07, 약 .282초 뒤 122.12km/h의 제동)을 골랐다. 앞선 두 탐색 결과 중 265km/h 접근과 더 낮은 속도대에 도달하기 전에 이미 제동 중인 표본은 첫 이동 권한 시험에 쓰지 않는다. 기준 좌표는 교사 SDK 원본이며 native graphics와의 좌표 등록 및 안전 정지 corridor는 아직 필요하다.

실제 고속 합격 판정은 원본 학생 제동 요청 3개 이상, 초기 100km/h 이상, 안전 정지 전 native 감속 5km/h 이상과 세 distinct 제동 패킷을 요구한다. AI·타이어 이탈·새 damage는 탈락이고 안전 정지 명령의 감속을 세지 않는다. 가장 빠른 개발 오차를 검증하려면 별도 144km/h 이상 조건이 필요하다. 기존 3.61km/h 출발 원본을 넣은 음성 대조는 고속 제동 불합격이다. 진입 pose·방향·속도의 검사와 원본 안전 정지 분리 검사를 추가했다. 실제 고속 학생·미사용 코너 부모/후보 비교 및 차량에서의 경로별 기여 검증은 이어서 진행할 항목이다.

단일 SDK owner의 이동 권한 코어를 추가했다. 원래 시계의 pacing 요청을 유효한 동안만 받고, native 진입 검사와 원래 학생 envelope를 확인한 뒤 한 번만 권한을 넘긴다. 이전 pacing 요청의 기한이 학생 첫 SDK 호출 전에 지나면 정지한다. 학생 전환 뒤 교사 요청은 다시 받지 않는다. 이 단계에서는 가짜 SDK와 원본 저속 결과의 고속 음성 대조까지 검증했다.

`focused-tests-03.log`에서 29검사를 통과했다. 실제 세션은 원본 API로 paused·AI off·camera idle·vJoy FREE를 확인했다. 다음은 133km/h 기준점의 실제 native 좌표 등록·정지 거리 계측 및 단일 owner 연결, 같은 초기 상태의 부모/후보 시험, 이후 더 높은 속도와 새 코스로 이어간다. 미사용 코너·회로 개입의 실제 차량 효과와 유효 반복랩은 목표에 남아 있다.

## 실제 이동 중 안전 정지 및 권한 전환 준비

`native-stop-calibration-01`에서 진입 속도 135.91km/h, 정지 거리 56.36m, 소요 3.489초를 측정했다. 손상 증가는 없었지만 타이어 4개가 코스 밖으로 나가 이 지점을 탈락시켰다. SDK와 native 좌표 등록에서 사용한 변환은 native = [SDK y, SDK z, SDK x]다. 독립 감사는 원본 graphics/physics 바이트에서 위치와 이동 거리를 다시 계산했다.

기존 실제 교사 주행의 직선 여유를 새로 계산했다. `corridor-screen-01/02/03`은 임박한 실제 제동 또는 120~145km/h 범위의 직선 여유 기준에서 탈락했다. `corridor-screen-04`의 105~120km/h 페이싱 탐색은 87개 중 5개가 기하학 기준을 통과했다. 선택 지점의 교사 기록은 109.04km/h이며 원래 교사 제동 직전 지점으로 분류되지 않는다. 이 지점은 권한 전환 검증에 사용한다.

`native-stop-calibration-02`는 같은 지점에서 107.61km/h부터 33.39m 만에 실제 정차했다. 코스 이탈 타이어 0개, 추가 손상 0, 진단상 차체 중심의 최소 경계 거리 2.65m다. 독립 감사에서 native 정차와 거리, CSP 최종 pause를 대조했다. 두 정차는 교사 페이싱에서 안전 정지 명령으로 전환한 기록이다.

운영 시험 경로는 같은 vJoy owner 안에서만 교사 권한을 회수한다. 동일 구간의 정차 원자료와 SHA, native 위치·진행 방향·속도, 원본 학생 mailbox·감각 시계가 맞아야 최대 0.35초의 학생 관측으로 넘어간다. 안전 정지와 학생 제동 판정은 별도 로그를 쓴다. 기존 50/150/25ms 한도는 유지한다. Magione 전환은 기존 배경 CSP를 기반으로 두 트랙만 허용하는 LuaJIT 후보와 가드 검사를 만들었다. 당시 증거는 LuaJIT 검사까지였다.

## 고속 지연 후속 계측

고속 교사 페이싱 원본 978결정에서 Torch CSR의 0 항목만 없애면 출력은 같았지만 p95와 최대 지연이 개선되지 않았다. 같은 구조에서 CPU 스레드를 1·2·4개로 번갈아 재생했다. 4개 스레드 두 실행의 p95는 9.27/9.31ms, 최대 13.01/13.05ms였다. 1개 스레드 p95는 15.86/16.15ms였다. 모든 조합이 원본 출력과 최종 9,728원소 상태를 정확히 재현했다(`torch-thread-circuit-timing-01`).
