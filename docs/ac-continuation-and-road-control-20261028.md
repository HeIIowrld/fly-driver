# GPU 병렬 학습과 240m 주행 검증

작성: 2026-10-28 (KST). 목표 진행 상태: 진행 중. 전체 서킷 완주 및 일반적인 제동·셋업 적응은 미검증.

## GPU 사용 확대 결과

AMD Radeon RX 9070 XT에서 고정 연결 행렬의 CSR 연산과 역전파를 사용한다. PyTorch의 `cuda:0` 표기는 이 환경에서 AMD ROCm 장치다. 연결 수·부호·회로 동역학은 유지한다. 실제 배포 추론은 CPU CSR이다.

동일 조건 비교에서 평균 epoch 시간은 9.418초에서 5.078초로 줄었으며 저장된 모델 텐서 차이는 0이었다. 연산 단위 비교에서는 CSR 0.369초, COO 1.108초였다. 서로 다른 범위의 측정이므로 두 속도 향상을 곱하지 않는다. 근거: `runs/ac-gpu-fixed-csr-training-20261028-t412`, `runs/ac-gpu-fixed-csr-benchmark-20261028-t408`, `runs/ac-gpu-coo-matched-benchmark-20261028-t409`.

이번 추가 실험은 후보 3개씩 두 묶음, 후보당 16 epoch로 총 96 epoch를 완료했다.

| 실험 | 동시 작업 | 총 epoch | 묶음 소요 시간 | 결과 |
|---|---:|---:|---:|---|
| 이어지는 실패 구간 보정 (t446) | 3 | 48 | 113.425초 | 기존 성공 구간에서 불필요한 제동 증가, 모두 채택 보류 |
| 성공 정책 보존 항 추가 (t457) | 3 | 48 | 277.308초 | 절충 후보 t459 선택, 실제 240m 검증 실패 |

각 작업의 최대 PyTorch 할당 메모리는 약 1.98~2.01GB였다. 이것은 장치 전체의 실제 상주 메모리나 지속 사용률을 뜻하지 않는다. Windows GPU 카운터에는 비정상 값도 있어 지속적인 90% 이상 사용을 주장하지 않는다. 다른 프로그램은 종료하지 않았다. 두 묶음 모두 작업 3개가 정상 종료했으며 시간 지연 때문에 재시작한 작업은 없다.

근거: `runs/ac-continuation-gpu-suite-20261028-t446/result.json`, `runs/ac-continuation-anchor-gpu-suite-20261028-t457/result.json`. 실행기: `scripts/run_ac_gpu_experiments.py`. 추가 병렬 수를 늘리기 전에 처리량과 다른 앱의 응답성을 함께 비교한다.

## 학습 안정화와 데이터

기존 t414는 120.163m의 제한된 구간을 통과했다. 같은 위치에서 이어 간 t439는 55.477m 후 도로 여유 폭이 0.960m가 되어 중단했다. 두 구간을 정차 없이 연결한 완주 증거로 취급하지 않는다.

기존 데이터 1,807개와 성공 구간 528개, 후속 실패 구간 237개를 합쳐 2,572개 결정·9개 원본 에피소드로 학습했다. 교사는 기하학적 복구 정책이며, 추가 라벨은 실제 실행되지 않은 반사실적 요청이다. 최적 레이싱 행동이나 실제 제동 안전성의 정답은 아니다.

`policy_anchor.py`는 성공한 원본 에피소드 전체를 초기 정책의 고정 출력과 비교하여 `교사 손실 + λ × 성공 구간 출력 MSE`를 사용한다. λ=1,3,10을 비교했다. 수치 신경 상태는 청크 사이에 유지하고 에피소드 경계에서만 초기화한다. 이 보존 항과 교사 정보는 실제 주행 actor에 들어가지 않는다. 연결 구조와 부호는 고정이다.

λ=3인 t459는 성공 구간 제동 RMSE를 보존 항 없는 후보의 약 0.083에서 0.031로 낮췄다. 후속 실패 구간 조향 RMSE는 원본 t414의 0.289에서 0.164로 낮아졌다. 모두 학습 구간 적합도이며 독립 평가 성능이 아니다. 별도 개발 기록도 후보 선택에 사용했으므로 최종 미사용 시험으로 부르지 않는다.

향후 epoch 평가에서는 이미 계산한 배치 예측으로 보존 오차를 함께 집계하도록 중복 순회를 제거했다. CPU/GPU 수치 시험은 통과했지만 새 방식의 전체 학습 소요 시간은 아직 다시 측정하지 않았다. 위 277.308초는 이전 평가 경로의 실제 기록이다.

## 실제 240m 시도

| 기준 | 결정 수 | 시작점에서 마지막 피드백까지 변위 | 중단 이유 |
|---|---:|---:|---|
| 기존 기준선 추종, t467 | 993 | 205.524m | 기준선 간격 −3.013m가 3m 제한 초과 |
| 별도 도로 유효성 기준, t473 | 883 | 201.935m | 도로 여유 폭 0.964m가 1m 제한 미만 |

첫 시도의 중단 시 도로 여유 폭은 5.136m였다. 따라서 두 번째 시도는 기준선 간격을 진단값으로 두고 도로 여유 폭 1m 이상·바퀴 이탈 0·게임 랩 무효화 0을 요구하는 별도 `course_240m` 프로필을 사용했다. 기존 실패 기록을 성공으로 바꾸지 않았다. 두 시도 모두 240m 목표를 달성하지 못했다. 최고 속도는 각각 25.824km/h, 25.320km/h였다.

두 시도의 실제 픽셀·몸 감각으로 모델 출력을 재생했을 때 최대 차이는 0이었다. 마지막 200개 표본의 요청 조향 대비 native 조향 RMSE는 각각 0.00268, 0.00248이었다. 조작기 고착의 뚜렷한 증거는 없지만, 이 값은 지연 보정이나 실제 바퀴 각도의 SI 단위 검증을 뜻하지 않는다.

카메라는 최대 2,000그룹으로 확장했으며 60초 상한은 유지했다. 해당 프로필은 1,650그룹·54.5초·1GiB로 제한한다. t467은 1,303그룹을 실제 수신했다. 두 시도 모두 카메라 오류 없이 종료·정차 확인 후 CSP API로 일시 정지했다. 전면 창 조작은 하지 않았다.

근거: `runs/ac-240m-student-trial-20261028-t467`, `runs/ac-240m-student-audit-20261028-t468`, `runs/ac-road-course-trial-20261028-t473`, `runs/ac-road-course-audit-20261028-t474`.

## 시각 입력과 시간 지연 진단

t473의 883개 기록에 대한 t478 오프라인 분석:

| 입력 변경 | 교사 조향 RMSE |
|---|---:|
| 실제 입력 | 0.17965 |
| 시각 입력 없음 | 0.27942 |
| 첫 화면으로 픽셀 고정 | 0.44112 |
| 유효 영상의 나이만 0으로 변경 | 0.17485 |

실제 픽셀 내용은 조향에 영향을 준다. 정규화 평균으로 픽셀을 바꾸면 시각 입력 제거와 같은 결과였다. 영상 나이는 별도의 선형 상수 입력이 아니라 시각 반응을 지수 감쇠한다. 영상 나이만 0으로 변경하면 평균 절대 출력 변화는 조향 0.0700, 가속 0.0797이었다. 이것은 합성 방식의 민감도이며 실제 최신 영상이나 원인 확정의 증거가 아니다.

기존 시간 대비 대비도는 이미 dt로 정규화한다. 같은 노출을 재사용하면 이전 미분 추정치를 유지한다. 이를 dt 누락 버그나 검증된 방향성 광류라고 부르지 않는다. 프레임 재사용 비율은 두 시도에서 약 0.30%, 20.39%였지만 이것만으로 주행 실패 원인을 단정할 수 없다.

제동도 미해결이다. 새 기록의 교사 제동 양성 199개에서 평균 교사 요청은 0.461, 모델 요청은 0.030이었다. 제동 분리 AUC는 0.840이지만 양·음성 출력이 겹치고 마지막 복구 상태에서는 제동이 거의 없었다. 단순 임계값 보정으로 해결됐다고 주장하지 않는다. 근거: `runs/ac-road-pixel-timing-audit-20261028-t478`, `runs/ac-road-course-expert-labels-20261028-t476/halt-separation-diagnostic.json`.

## 다음 작업과 현재 상태

1. 하드 영상 신선도 기준과 시각 신뢰도 감쇠를 분리하여 검토하고, 실제 기록의 시간 지연·노출 재사용에 대한 강건성을 비교한다. 안전 기준을 낮추거나 실제 받지 않은 영상을 만들지 않는다.
2. 새 도로 실패 883개를 포함한 3,455개 결정·10개 원본 에피소드 데이터(t479)로 학습한다. 이 데이터는 준비만 됐으며 아직 새 학습에 사용하지 않았다. 사용 후에는 t476을 미사용 평가로 부르지 않는다.
3. 성공 구간 보존과 실패 구간 제동·복구를 동시에 평가한 뒤 같은 제한의 240m 시험을 반복한다. 다음 실제 시험은 도로 가장자리의 현재 위치를 이어 쓰지 않고 시작 위치로 재시작한다.
4. 그 이후 더 긴 제한 계측과 세션·신경 상태 연속성, 게임 랩 카운터·진행률·무효화 값을 함께 사용해 전체 랩을 증명한다. 타이어 온도·하중·셋업 최적화는 그 이후의 과제다.

마지막 읽기 전용 확인(t480): 일시 정지, 가속 0, 브레이크 1, 카메라 비활성, 오류·미처리 영수증 없음. 런타임은 `ac-pixel-timing-runtime-20261028-t477` 스냅샷이다. 원본 영상·센서·명령·해시·실패 이유는 각 runs 폴더에 보존했다. 75개 관련 시험과 Ruff 검사, 추가 픽셀/시간 진단 시험 3개가 각각 통과했다. 전체 서킷 완주는 아직 달성하지 않았다.
