# AC 창 모드와 백그라운드 계측

2026-10-27 KST. 사용자 요청: 게임 조작 재개, 전체화면을 피하고 다른 작업 중에도 실행.

## 최신 상태: 실제 주행 엔진 실행, 센서 앱 수정 배치

추가로 네트워크/SDK 앱 없이 기존 네이티브 공유메모리를 읽어 하중·온도 등250표본을 기록했다.
정지 메뉴 상태에서 packet ID의 증가를 확인했으며, 이것만으로 비활성 창의 주행·영상 생성·
제어 적용을 검증했다고 주장하지 않는다. 아래 SDK 재로딩 대기와 별개로 원시 계측은 성공했다.
[네이티브 계측과 범위](ac-native-physics-20261027.md).

후속 작업에서는 창 활성화가 가능해져 BMW Z4 GT3·Monza 연습을 실행했다. 런처의 첫 비디오
검증을 처리하고 Single Screen·전체 화면 해제 상태에서1280×720 설정을 저장했다.
`acs.exe`와 제목 표시줄이 있는 실제 연습 창을 확인했다. 단, Windows 방화벽 확인창의
사용자 직접 처리를 기다리고 있어 차량 주행 입력과 창 가림/최소화 시험은 하지 않았다.
수정 전/후 설정은 `runs/ac-video-valid-20261027-t27/`에 보존했다.

실제 게임 로그에서 센서 앱의 `import socket` 실패를 확인해 네트워크 의존성을 지연 로딩하고,
불러올 수 없으면 사용자 폴더의 최신 값 파일로 전달하는 방식을 추가·배치했다. 새 코드 적용에는
주행 엔진 재시작이 필요하며 실제 수신은 아직0개다. [계측 수정·학습 결과](multiview-photometry-20261027.md).
아래 활성화 오류·Esc 기록은 이 후속 실행 이전의 이력이다.

## 적용한 설정

실제 사용자 Documents/Assetto Corsa/cfg에서 다음을 저장했다. 원본은
`runs/ac-window-mode-20261027-121952/`에 보존했다.

| 파일 | 설정 | 확인 범위 |
|---|---|---|
| video.ini | VIDEO/FULLSCREEN=0, WIDTH=1280, HEIGHT=720 | 파일 읽기 대조 완료, 엔진 적용 미확인 |
| launcher.ini | WINDOW/FULLSCREEN=0 | 파일 읽기 대조 완료, 현재 런처 적용 미확인 |
| python.ini | FLYBRAIN_TELEMETRY/ACTIVE=1 | 설정 저장 완료, 앱 실행·수신 미확인 |

설치 경로는 `C:/Program Files (x86)/Steam/steamapps/common/assettocorsa`다.
런처 창은 존재하지만 이번 두 번의 활성화 요청이 모두
`GetCursorPos failed: 액세스가 거부되었습니다. (0x80070005)`로 실패했다.
창 연결을 새로 잡아도 같았다. UI 입력은 중단했고 사용자에게 잠금·절전·권한 확인 창
상태를 확인해 달라고 요청했다. 오류 원인은 확정하지 않았다. 보안 설정은 변경하지 않았다.
후속으로 사용자가 게임 창이 열린 것을 확인했다고 알려주어 연결을 다시 시도했으나,
Computer Use가 사용자의 물리 Esc 입력으로 중지됐다고 보고했다. 해당 차수의 화면 조작은 중단했다.
설정 저장만으로 게임 첫 세션 실행, 영상 캡처 또는 센서 수신 성공을 주장하지 않는다.
실행 중 런처가 설정을 다시 저장할 가능성이 있어 다음 조작 때 값과 화면을 함께 확인한다.

## 백그라운드 실행의 구분

- **센서:** 수정 앱은 가능하면 localhost TCP, 네트워크 확장이 없으면 로컬 최신 값 파일로
  발행한다. 수정 앱의 실제 재로딩·수신은 미검증이다. 기록기는 키보드 입력이나
  foreground 창에 의존하지 않는다. 다만 AC가 비활성 상태에서도 앱 콜백·물리를
  계속 실행하는지는 실제 세션에서 확인해야 한다.
- **영상:** 현재 `ac_capture.py`의 MSS 경로는 화면상의 client 영역을 읽는다.
  foreground 검사와 표시·최소화·화면 경계 검사를 유지한다. 다른 창에 가린 상태를
  지원한다고 표시하거나 검사를 제거하지 않는다.
- **목표 구성:** 작은 창에서 렌더링을 유지하고 게임 창 자체를 취득하는 별도 캡처
  backend를 연결한다. 가림·포커스 소실·최소화는 각각 시험한다. 최소화·잠금·절전
  상태의 새 프레임 생성이나 렌더링 없는 비전 주행은 현재 보장하지 않는다.
- **제어:** 메뉴 조작을 끝낸 뒤에도 조향·페달 전달이 포커스와 무관하게 적용되는지는
  별도 적용값 피드백으로 검증해야 한다. 현재 배치한 앱은 읽기 전용이다.

[AC Gym 설치 안내](https://github.com/dasGringuen/assetto_corsa_gym/blob/main/INSTALL_Linux.md)도
학습 시 낮은 해상도와 전체화면 회피를 안내한다. 해당 안내는 이 Windows 설치에서
백그라운드 렌더링·캡처·제어까지 동작한다는 증거는 아니다.

## 다음 실제 시험

1. UI 접근 복구 후 창 모드 값을 확인하고 기본 연습 세션에 진입한다.
2. 센서 기록을 유한 표본으로 수집하고 타이어 온도·네 바퀴 하중의 누락·단위·순서를 확인한다.
3. foreground와 비활성 상태의 기록 구간을 분리해 콜백 sequence·시각 증가를 비교한다.
   콜백 시각 증가만으로 물리 시간이 진행된다고 판단하지 않는다.
4. 게임 창 전용 캡처를 연결한 뒤 가림 상태의 실제 새 프레임과 센서 대응을 확인한다.
   캡처 횟수 증가나 정지 화면의 중복 취득을 새 엔진 프레임으로 세지 않는다.

이번 작업에서 실제 게임 세션 시작·실제 센서 수신·실제 영상 취득·제어 전송은 확인하지 못했다.
