# AC 연결부: 원본 프로토콜 조사와 읽기 전용 기록

갱신: 2026-10-27, Asia/Seoul. **실제 AC 네이티브 물리 매핑에서250개 원시 센서 표본을
기록했다. 주행 제어·단위/축·시계/영상 동기는 미검증이다.**
[새 계측과 근거](ac-native-physics-20261027.md). 아래는 초기 통신·기록·데이터 계약 검증과
SDK 앱 경로의 이력이다. 기존 MuJoCo V+body12/12 결과를 실제 AC 랩으로 승격하지 않는다.

후속으로 실제 Z4 GT3·Monza 연습 엔진을 실행했다. SDK 앱은 native Python의 socket import
실패를 확인해 로컬 파일 전달 대체 경로를 추가·배치했다. 방화벽 확인창의 사용자 처리와 앱
재로딩을 기다리고 있으며 실제 센서 수신·제어는 미검증이다. [최신 계측 상태](multiview-photometry-20261027.md).

## 구현한 부품

- `ac_transport.py`: eval 없는 strict JSON UDP reader. 중복 키·비유한 값·과대 패킷·
  sequence 역행을 거절한다. close는 로컬 소켓만 닫는다. 조작은 dry codec만 있으며 송신기는 없다.
- `ac_telemetry.py`: 명시한 channel/key/변환/근거만 BodySample로 바꾼다.
  pose·진행률은 허용하지 않고 관측되지 않은 축은 invalid다. 수신 시각은 그대로 보존한다.
  랩 시계 복원기는 합성 rollover 시험만 통과한 후보이며 native clock이 아니다.
- `ac_image_buffer.py`: 기존 Windows named map을 읽기 전용으로 열고 없는 map을
  만들지 않는다. 검은 픽셀을 보존한다. active0/1을 노출 ID로 둔갑시키지 않는다.
- `integrations/ac/flybrain_telemetry`: 표준 라이브러리만 사용하는 읽기 전용 TCP 앱.
  SDK 호출을 주 스레드에 두고 별도 스레드가 최신 표본을 전송한다. 학습기와 분리하며
  조작·초기화 코드는 없다. Python3.3 문법 검사는 실제 embedded runtime 실행을 대신하지 않는다.
- `ac_tcp.py`와 `record_ac_tcp.py`: producer session·sequence·프레임 크기 검증,
  정확한 wire bytes·SHA256·수신 시각 기록, 표본 수 제한, 실패 시 부분 결과 보존.
  `simulation_clock_verified=False`, `actor_stream_created=False`를 유지한다.

설치 준비와 기록 명령은 [앱 안내](../integrations/ac/README.md)에 있다.

## 실제 수행한 검사

Windows localhost의 UDP는 Python과 .NET에서 모두 시간 초과였다. 원인은 아직 특정하지
못했다. 방화벽이나 보안 설정은 바꾸지 않았다. TCP loopback은 수신에 성공했다.
기존 AC physics/graphics/image mapping은 모두 없었으며 probe가 생성하지 않았다.
등록된/default Steam 경로에서 엔진을 찾지 못한 점검은 다른 경로의 설치 여부를 부정하지 않는다.

Windows 선택 검사22개는 통과했다. 여기에는 실제 Windows named map과 실제 TCP
publisher/reader가 포함된다. UDP loopback1개는 알려진 실패로 이 성공 집계에서 제외했다.
분할 프레임·producer 변경·sequence reset·크기 초과·원값 누락·SDK 읽기만 수행하는지도 검사했다.
SDK 없는 합성 producer→별도 CLI 프로세스 기록20표본도 완료했다.

WSL CPU 전체 검사는 **184통과·Windows 전용2건 건너뜀**이며 정적 검사도 통과했다.
WSL UDP3표본 수신·원본 bytes 재생과 TCP20표본 CLI 기록도 성공했다. Windows UDP
실패를 숨기거나 WSL 성공을 Windows/실제 AC 연결 성공으로 취급하지 않는다.

검사 결과·시험 소스·실패 로그 등 **198파일을 수집해 SHA256 대조**했고,
현재 Python 소스119개도 시험한 snapshot과 동일하다. 기록은 `runs/ac-bridge-20261027`에 있다.
Windows native probe와
TCP CLI 결과는 각각 `runs/ac-native-probe-20261027-t14`,
`runs/ac-tcp-fixture-windows-20261027-t14`에 있다. 모든 결과의 실제 게임 검증은 false다.

## 다음 관문과 현실성

1. 실제 AC가 있는 PC·설치 경로에서 앱100표본을 읽기 전용으로 기록한다.
2. 정지/좌우 조향/직진 가속/제동/좌우 회전/요철에서 축·단위·조향 의미를 교정한다.
   pause/reset/replay와 랩 경계에서 clock/session을 검증한다.
3. 캡처 생산 단계에 exposure ID·노출 시각·카메라 교정을 넣고 눈/몸 재생 계약을 봉인한다.
   영상이 없거나 새 프레임을 증명하지 못하면 actor 스트림을 만들지 않는다.
4. 요청과 실제 적용을 구분하는 조작 응답 시험 후 저속 구간 BC→새 시작 조건→전체1랩을 진행한다.
   지금의 고정 전진 의도에서 자율 속도·제동·회복 조작으로 확장해야 한다.

이 구조의 저속 완주 연구는 추진할 만하지만, 감각 계약·실제 게임 동역학 이전에
완주 가능성을 확정할 수 없다. 또한 FC2 입력 누락, 겹눈→MeTu 등록, 수용체별 부호와
생리학적 동역학은 별도 과제다. 실제 랩 성공과 파리 신경계 재현은 각각 증거를 요구한다.
