# 대시뷰·후방 미러와 엔진 다중 카메라

후속 작업에서 CSP 설치와 독립4카메라의 실제 백그라운드 수신을 완료했다.
최신 결과는 [엔진4카메라 실측](ac-csp-four-camera-20261028.md)을 따른다.
아래 내용은 그 이전의 기본 화면 crop 검사와 당시 계획이다.

2026-10-28 KST. 현재 BMW Z4 GT3 / Monza 세션에서 기본 카메라를 대시뷰로 바꾸고
가상 후방 미러를 켰다. 차량은 정차 상태다. 운전 제어 요청을 보내지 않고 카메라만
변경했다. 전체화면 설정은0이며, 설정 확인 후 Alt+Tab으로 작업 창 뒤로 돌렸다.

## 실제로 확인한 입력

![대시뷰와 가상 후방 미러](../runs/ac-dash-rear-view-probe-20261028-t137/dash-rear-preview.png)

원본3프레임은 t137에, 새 설정 검사는 t138에, 백그라운드3프레임은 t139에 저장했다.
설정은 `configs/ac-native-dash-rear-retina.json`이고 이전 설정 파일은 보존했다.

| 입력 슬롯 | 현재 소스 | 원본 전체창 픽셀 범위 x0,y0,x1,y1 |
|---|---|---|
| front | 대시뷰 전방 도로 | 350,325,1200,510 |
| mirror_rear | 화면 위의 가상 후방 미러 | 473,233,811,317 |
| mirror_left | 없음 | 결측 |
| mirror_right | 없음 | 결측 |

실측 전체창 RGB는1284×784다. 두 crop은 겹치지 않으며 전방에서 미러와 아래 HUD를
제외했다. 새 망막 전처리로 실제3프레임을 통과시켰고 전방/후방 각각1709개 유효 수용기,
좌/우0개를 확인했다. 후방 영상은 화면에 표시된 방향 그대로이며 물리 시선·반사 변환은
미보정이다. 높은 수용기 수가 원본 미러의 실제 해상도를 늘리지는 않는다.

현재 전방 crop은 미러 아래의 도로를 사용하는 임시 선택이다. 독립 엔진 카메라로
전환하면 HUD·미러가 전방 영상에 들어오는 문제 없이 더 넓은 전방 영상을 쓸 수 있다.

`configs/ac-live-view-contract.json`에 이번 시점 변경을 선언했다. 학생 실제 제어와
읽기 전용 추론은 선언된 설정과 망막 설정이 다르면 시작 전에 거부한다. 현재 시점용으로
학습한 체크포인트는 아직 없다. 이 검사는 선언된 설정 불일치를 막으며, 사용자가 이후
F1/F11을 눌렀는지 영상에서 자동 판별하는 기능은 아니다. 시작 전 원본 영상 확인은 필요하다.
기존 조종석 영상과 새 대시뷰·후방 영상을 동일한 calibration으로 섞지 않는다.

## 엔진에서 직접 영상을 받을 수 있는 경로

기본 AC는 F1 운전 시점·F6 온보드·F11 가상 미러 전환을 지원한다.
[공식 배포사 조작 설명](https://assettocorsa.games.dmm.com/game/keyboard).
현재 물리·graphics shared memory 수집기는 RGB를 내보내지 않는다. 카메라를 돌려서
차례대로 캡처하는 방식은 동시 다중 시점 수집과 구별해야 한다.

CSP의 공개 Lua 소스에서 다음 기능을 확인했다. 이 PC에는 CSP를 설치하지 않았으며,
아래 내용은 소스에서 확인한 가능성이다. 실제 엔진 텍스처 수신 성공으로 보고하지 않는다.

| 기능 | 확인한 API | 사용할 목적 |
|---|---|---|
| 별도 카메라 렌더링 | `ac.GeometryShot` + `update` | 차량에 고정한 전방/좌/우/후방 시점 |
| view/projection 조회 | `viewMatrix`, `projectionMatrix` | 실제 투영행렬·카메라 계약 보존 |
| 프로세스 간 GPU 텍스처 공유 | `sharedHandle(true)` + `render.TextureFlags.Shared` | OS 화면 캡처를 거치지 않는 영상 전달 |
| 비동기 GPU→CPU 읽기 | `accessData` | CPU 기반 망막 전처리의 대안 |
| 가상 미러 텍스처 | `ui.drawVirtualMirror`, `dynamic::mirror` | 기존 후방 렌더를 재사용하는 경로 |
| 별도 통신 메모리 | `ac.writeMemoryMappedFile` | 프레임 번호·카메라 ID·준비 상태 전달 |

원본: [CSP scene API](https://github.com/ac-custom-shaders-patch/acc-lua-sdk/blob/7cf60f5a406820ee4e39f3a62ed121fa36274001/lib_scene.lua),
[미러 API](https://github.com/ac-custom-shaders-patch/acc-lua-sdk/blob/7cf60f5a406820ee4e39f3a62ed121fa36274001/ac_apps.lua),
[공유 메모리 API](https://github.com/ac-custom-shaders-patch/acc-lua-sdk/blob/7cf60f5a406820ee4e39f3a62ed121fa36274001/common/ac_extras_connectmmf.lua).
소스·MIT 라이선스·파일 해시·commit은 `assets/external/csp-camera-api-20261028/`에 보존했다.
공개 API 버전과 실제 설치 버전의 기능 차이도 설치 후 확인해야 한다.

## 다음 구현 순서

1. 현 대시뷰·후방 미러는 정차 영상 검증용으로 유지한다. 시점 변경으로 생긴 영상 분포
   차이를 반영해 새 교사 수집과 학생 학습 자료를 별도 calibration으로 만든다.
2. 독립 좌/우/후방이 필요한 본 구조는 CSP Lua 카메라 → 공유 GPU 텍스처/비동기 읽기
   → 소스별 망막 → 기존 파리 회로 경로로 설계한다. 카메라별 ID·좌표·FOV·좌우 반전·
   투영행렬·수신 시각을 기록한다. 차량 자세는 렌더러 내부의 카메라 배치에만 사용하고
   actor의 숫자 입력으로 넘기지 않는다. 깊이·지도·차선 정답도 actor에 추가하지 않는다.
3. 초기 성능 예산은 전방320×180/25Hz, 보조3개160×90/10Hz를 제안한다. 이는 실측
   성능이 아니다. 각 소스의 나이·결측을 따로 유지하고 늦은 영상을 현재 프레임으로
   가장하지 않는다. 카메라 방향과 화각은 영상·투영 검증을 마친 뒤 확정한다.
4. 화면이 다른 창에 가려진 상태에서 프레임 증가, GPU 렌더 시간, 전송/전처리 시간,
   센서 수신과 영상 시각 차이를 측정한다. 렌더 타깃을 직접 받아도 추가 시점의 GPU
   렌더 비용은 남는다. 최소화·Windows 연결 끊김·무화면 실행까지 지원된다고 가정하지 않는다.
5. 실제 소스가 준비된 뒤 입력 포트와 전처리를 맞추고 재학습한다. 완주 검증, 타이어 온도·
   하중 적응, 셋업 적응과 랩타임 최적화는 전체 목표로 유지한다.

기존 모델의 가속 유지 진단도 보존했다. t135에서 기존 정차150관측의 마지막25결정은
정답 가속0.25에 예측 약3.31e-38이었다. 새 출발 관측150개는 t134에 원본 실행값으로,
t136에는 같은 고정20km/h 교사의 미실행 질의 라벨로 보존했다. 학생 자신의 출력을
전문가 정답으로 학습시키지 않는다. 이 turn에서 새 학습은 실행하지 않았다.
