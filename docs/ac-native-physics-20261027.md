# 실제 AC 네이티브 물리 센서 계측과 전체 모형 도로 시험

갱신: 2026-10-27, Asia/Seoul. 최종 목표는 겹눈·파리 신경회로·몸 감각으로 실제 Assetto Corsa
서킷을 비전 기반 주행하는 것이다. 이번에는 실제 센서 기록을 확보했고, 긴 주행의 실패도 확인했다.

## 실제 게임에서 받은 값

Windows의 기존 `Local/acpmf_physics`·`Local/acpmf_static` 매핑을 `FILE_MAP_READ`로 연다.
센서 앱·네트워크 연결·추가 Python 확장이 필요하지 않으며, 없는 매핑을 만들지 않는다.
Windows 방화벽 설정을 변경하거나 보안 확인창을 조작하지 않았다.

구조는 버전을 고정한 [AC Gym의 sim_info.py](https://github.com/dasGringuen/assetto_corsa_gym/blob/ef0fa502bdd257fc2affad9361c02b3dbdfe1632/assetto_corsa_gym/AssettoCorsaPlugin/plugins/sensors_par/sim_info.py)를
근거로 삼았다. 원본 Git blob `a0f4c7d66f621d0ebc604ae437deba39829fdaf2`와7,023바이트를
검증해 `assets/external/ac-native-memory-20261027/`에 보존했다. 외부 모듈은 실행하지 않았다.
원본 필드 목록과 새308바이트 little-endian 물리 prefix를 AST로 대조한다.

정적 매핑은 처음200바이트만 읽어 공유메모리 버전·게임 버전·차량·트랙을 확인한다.
그 뒤에 있는 운전자 이름은 읽거나 기록하지 않는다. 실제 확인값은 공유메모리1.7·AC1.16.4·
`bmw_z4_gt3`·`monza`로, 눈으로 확인한 연습 화면과 일치했다.

| 첫 표본의 바퀴 | wheelLoad 원시값 | tyreCoreTemperature 원시값 |
|---|---:|---:|
| FL | 3344.031 | 27.2744 |
| FR | 3443.133 | 27.2744 |
| RL | 3194.458 | 27.4603 |
| RR | 3154.829 | 27.4108 |

타이어 압력·서스펜션 이동·바퀴 각속도·차체 각속도·가속도·속도·조향·페달 값도 기록했다.
위 숫자는 **네이티브 원시값**이며 단위와 축을 독립 검증해 actor의 K/N/rad/s 계약으로
변환한 결과가 아니다. 정지한 연습 메뉴 상태라 조작에 따른 하중이동·타이어 열 변화는
아직 검증하지 않았다. 원시 binary에는 진단용 필드도 있으나 actor용 decoder는 명시한
몸 감각·속도·조작 필드만 내보내며 heading·pitch·roll·world velocity를 제외한다.

두 번에 걸쳐50+200=**250표본**을 받았다. 첫50표본의 packet ID는245,968→246,306으로
증가했고, 두 번째200표본도 모두 고유하고 증가했다. 각 표본의 원시308바이트와 SHA-256,
호스트 수신 시계를 보관·대조했다. 물리 매핑에는 노출/시뮬레이션 시각이 없으므로
`source_time_seconds=null`, `simulation_clock_verified=false`를 유지한다.

반복 복사 두 번이 같을 때만 표본을 받아 메모리 변경 중 읽기를 줄인다. 이는 엔진이 제공한
원자성 보장이 아니므로 `atomicity_verified=false`다. 같은 packet ID의 재사용은 기다리고,
수신 기한 초과와 ID 역행은 명시적으로 실패한다. 이 감각 스트림을 영상과 동기화한
actor 입력으로 아직 승격하지 않았다. 차량 조작은0건이다.

- 첫 기록: `runs/ac-native-physics-20261027-t28/`,50표본·요약·원시 해시.
- 두 번째: `runs/ac-native-physics-20261027-t28b/`,200표본·187파일 소스 스냅샷·검증 영수증.
- 새 reader의 ABI·필드 경계·동일 복사·ID 역행/정지·정적 정보 검사5개와 평가 설정 검사2개가
  Windows에서 통과했고 전체 소스 Ruff 검사도 통과했다.

## 전체100m 모형 도로의 실패

앞선24초 개발2구간의 [정규화 모델 개선](multiview-photometry-20261027.md)을 전체 도로로
확장해 같은 체크포인트를 평가했다. 입력·가중치는 바꾸지 않았고 새 시드820301, 시작x=3,
최대2,000결정·80초를 사용했다. 이 길은 시작과 끝이 있는 모형 도로로, 닫힌 서킷 랩이 아니다.

| 제어 | 결정 수 | 진행 거리(m) | 종료 |
|---|---:|---:|---|
| 경로 기반 교사 | 1675 | 96.74 | completion |
| 파리 회로 학생, 시각 정상 | 355 | 18.55 | track_exit |
| 같은 학생, 시각 제거 | 414 | 22.68 | track_exit |

학생은14.2초 뒤에 이탈했다. 교사는 끝까지 진행했으므로 현재 조건에서 물리 환경 자체가
완료 불가능한 것은 아니다. 정상과 시각 제거의 종료 시점이 달라 전체 RMS를 그대로 비교해
시각 우위를 주장하지 않는다. **짧은 개발 구간 개선을 일반 주행 능력으로 확대하면 안 된다.**
이 결과만으로 실패 원인을 확정하지 않지만, 교사 궤적512결정만으로는 학생이 벗어난 상태의
복귀 행동을 충분히 배우지 못했을 가능성을 다음에 검사한다.

다음 학습은 경로 전체를 덮는 다양한 교사 구간과, 학생이 실제로 도달한 상태에 교사 정답을
붙이는 DAgger 수집을 우선한다. 위치·지도는 교사에게만 주고 학생의 비전·몸 감각 입력 경계를
유지한다. 기존 개발 구간은 조정용으로 남기고 새로운 곡선·시작 조건을 따로 평가한다.

원본은 `runs/multiview-full-road-20261027-t28/`에249파일을 회수해 해시 대조했다.
관련8검사·Ruff 통과, 체크포인트 SHA-256은
`a9baddb6413c77948f292a2882ff5ad098fb3990aa606b36165b9259f3aa2262`다.
평가 시나리오별 도로 형상 override를 명시적으로 적용하고, 다음 사례로 설정이 새지 않는지
검사하도록 평가기를 보강했다.

## 남은 실제 게임 단계

공유메모리 계측은 앱 재로딩을 기다리지 않고 성공했다. 파일 전달 방식의 SDK 앱 수정은
별도 대안으로 보존하지만 실제 재로딩은 미검증이다. 현재 Windows 방화벽 확인창은 사용자
직접 처리를 기다리고 있다. 확인창 처리 뒤 실제 차량 화면·몸 센서 동기, 단위·부호·지연,
안전한 조향/페달 적용값을 검증해야 한다. 공개 교사와 함께 영상·기관 감각·정답 행동을 모아
오프라인 학습으로 연결하는 전체 목표는 계속 남아 있다.
