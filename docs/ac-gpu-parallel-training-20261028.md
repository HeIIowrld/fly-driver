# GPU 희소 연산과 병렬 학습 확대

기록일: 2026-10-28 KST. 실제 GPU는 RX 9070 XT 16GB, PyTorch 2.9.1+ROCm 7.2.1이다. 이 작업은 오프라인 학습만 수행했으며 UI·게임 조작은 0회다. 파리 회로 전체 서킷 주행 목표는 미완료다.

## 바뀐 기본 학습 경로

GPU 학습의 기본 sparse backend를 `cached_csr_gpu`로 바꿨다. 명시적인 `coo` 설정은 과거 실행을 재현할 때 계속 사용할 수 있다. 고정 연결의 CSR 행렬과 전치 행렬을 GPU에 캐시하고, 입력에 대한 정확한 adjoint를 이용해 역전파한다. 측정 그래프·연결·부호·정규화·상태 방정식·FP32 정밀도는 바꾸지 않는다. 캐시는 체크포인트에서 제외하며 실제 주행은 기존 CPU cached CSR와 tick 단위 검사를 유지한다. GPU sparse matrix가 학습 대상이면 이 backend는 거부한다.

독립적인 유용한 학습 조건을 최대 3개 함께 실행할 수 있도록 `scripts/run_ac_gpu_experiments.py`를 추가했다. 각 실행은 자체 optimizer·수치 상태·체크포인트·로그·고유 출력 경로를 갖는다. 기존 출력 경로 재사용은 거부한다. 중단 정리는 이 실행기가 만든 프로세스 트리에만 적용한다. 다른 앱이나 기존 GPU 작업을 중단하지 않는다.

## 같은 연산/학습 비교

| 비교 | 기존 GPU COO | 새 GPU cached CSR |
|---|---:|---:|
| 실제 회로 64개 결정×4 에피소드×4 ticks 순/역전파 중앙값 | 1.107875초 | 0.368986초 |
| 같은 자료·초기값·seed·손실·optimizer의 8 epoch 평균 | 9.417633초 | 5.078399초 |

첫 비교는 warmup 제외 3회, synchronize 포함(t409/t408)이며 약 3.00배 빠르다. 두 GPU 경로 모두 CPU 기준 출력 최대 차이 8.94e-8이다. 두 번째는 t401/t412이며 약 1.85배 빠르고 저장 모델 tensor의 최대 차이는 **0**이다. 그래프와 배포 constructor도 같다. t412는 다른 두 실험과 동시에 실행됐으며, 다른 앱 부하도 있어 통제된 하드웨어 성능 보장은 아니다. 전체 실행 시간에는 로딩·초기 평가가 추가된다.

## 실제 병렬 실험

`t411`에서 아래 세 실험을 동시에 시작해 모두 정상 종료 코드 0과 완료 체크포인트를 확인했다. 8+16+16=40 epochs를 시작부터 최종 결과 수집까지 101.447초에 처리했다. 직렬로 같은 세 실험을 재실행하지 않았으므로 병렬 처리만의 속도 향상 배수는 주장하지 않는다.

| 실행 | 학습 내용 | epoch 수 | PyTorch peak allocation |
|---|---|---:|---:|
| t412 | 이전 학습과 동일 조건의 CSR 검증 | 8 | 1,546,967,040 bytes |
| t413 | t401에서 출력 codec만 학습 | 16 | 1,499,731,456 bytes |
| t414 | t401에서 감각 adapter와 출력 codec 학습 | 16 | 1,580,527,616 bytes |

후자의 두 실험은 같은 초기값·seed 862931·자료 1807개/7개 에피소드·브레이크 가중치 1·출력 gain 학습률 0.03을 사용한다. 감각 adapter 학습률은 0.00005다. readout의 학습 가능한 양의 gain/가중치는 차량 codec이라는 공학적 가설이며 측정 파리 생리 상수로 해석하지 않는다. 실제 actor 경로는 계속 감각→고정 파리 회로→지정 출력 뉴런→codec이다. 지도·위치·진행률을 actor에 추가하지 않았다.

## GPU 계측의 범위

다른 Ollama 프로세스도 같은 GPU에서 연산 중이므로 학습 파일에 기록된 실제 PID만 모아 Windows GPU Engine/Process Memory counter를 수집했다. 학습 프로세스 전용 메모리 계측 합계는 최대 6,849,691,648 bytes(약 6.38GiB)였다. WDDM 할당 계측이며 물리 VRAM 상주량의 증명은 아니다. 표의 PyTorch 각 프로세스 peak를 단순 합친 값과도 다르다.

Compute counter 32개 표본 중 13개에 100% 초과/비정상적으로 큰 값이 있어 제외했다. 남은 19개 표본의 평균은 45.53%, peak는 94%였다. 이는 이 프로젝트 프로세스들의 계측값이며 전체 GPU 또는 지속 94% 활용의 증명이 아니다. raw 표본은 보존했고 `t411/gpu-counter-summary.json`에 제외 기준을 기록했다. 실행기는 앞으로도 비정상 counter에 표시를 남긴다.

## 별도 기록에서의 모델 평가

| 모델 | 다음 구간 RMSE 조향/가속/제동 | 이전 개발 구간 RMSE 조향/가속/제동 |
|---|---|---|
| 초기 모델 t401 | 0.072510 / 0.060939 / 0.087815 | 0.137581 / 0.087754 / 0.328130 |
| 출력 보정 t413 | 0.072490 / 0.061404 / 0.058462 | 0.137913 / 0.086961 / 0.246813 |
| 감각+출력 t414 | 0.071962 / 0.059789 / 0.028455 | 0.139010 / 0.088100 / 0.272729 |

CPU 주행용 경로로 t415~t418의 평가를 완료했다. 회로와 구조는 고정이며 의도한 그룹만 학습했다. 제동 오차는 초기 t401보다 줄었지만, 다음 구간의 제동 정답은 전부 0이고 새 모델도 불필요한 제동을 출력한다. 기존 개발 구간의 오류와 조향 회귀도 남는다. 새 모델은 실제 주행용으로 승격하지 않았다. 두 구간은 계속 gradient에서 제외했지만 이미 설계에 활용한 개발 평가이므로 독립 최종 시험이 아니다.

CPU/GPU 출력·입력 기울기·캐시 변경 검증을 포함해 관련 20개 테스트가 정상 종료 코드 0으로 통과했다. GPU 시험의 마지막 kernel 완료도 synchronize로 확인한다. Ruff도 통과했다. GPU 더 활용하기는 구현·실행·측정됐지만, 전체 서킷·제동 일반화·타이어/셋업 적응은 별도 남은 과제다.
