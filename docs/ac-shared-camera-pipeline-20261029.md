따라서 저장·전처리·해시·스케줄링 지연이 공유 텍스처 보유 시간을 늘릴 수 있었다.
원래 계측으로 그 공백 중 특정 파일 쓰기나 GPU 경쟁의 기여를 분리할 수는 없다.
호스트 코드 순서의 병목 근거이며 모든 장애 원인이 확정됐다는 뜻은 아니다.

## 바꾼 순서와 유지한 계약

`src/flybrain_drive/ac_csp_vision.py`의 `copy_shared_group`은 4개 시점을 먼저 독립 CPU 배열로
복사하고 전부 성공한 경우에만 원래 request/generation/capture ID의 ack를 쓴다.
그 뒤 BMP·전처리·해시를 처리한다. 저장과 검증이 끝나기 전에는 actor 캐시에 공개하지 않고,
`received`는 실제 처리 완료 시각으로 유지한다. 빠른 ack 시각을 영상 수신 시각으로 바꾸지 않는다.
복사 실패/잘못된 픽셀 형태는 ack를 보내지 않는다. 원본 텍스처에는 쓰지 않는다.

단위/회귀 검사50개와 관련 Ruff가 통과했다. 새 검사에는 부분 실패의 미해제와,
ack 이후 원본 재사용에도 이미 복사한 CPU 픽셀이 보존되는 조건이 포함된다.
