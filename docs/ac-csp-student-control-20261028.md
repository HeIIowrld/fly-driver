# 네 방향 겹눈 학생의 실제 제어와 속도 조절 개선

2026-10-28 KST. 목표는 파리 감각·신경회로를 사용한 AC 자율 서킷 주행과 이후 최적화다.
아래 짧은 주행이나 오프라인 학습을 완주로 판정하지 않는다.

후속30km/h 과제에서는 교사400개 자료를 추가한 뒤 학생30m 시험에 도달했다.
최신 근거와 조향 오차의 한계는 [30km/h 연속 교사·학생 기록](ac-30kmh-continuous-teacher-20261028.md)을 따른다.

## 관측과 학습 경로

전방은 차량 대시 위치, 좌·우·후방은 독립 엔진 카메라다. 각320×180 영상에서 방향별
1,709개 수용기를 만들고, 타이어 온도·하중·서스펜션·휠 회전 감각을 함께 연결한다.
세계 위치·맵·진행률은 교사와 외부 정지 검사에만 사용한다. 모델은 측정 연결 자료의
6,557개 노드·644,512개 에지를 유지하지만 감각/운동 매핑과 동역학은 공학적 모델이며
실제 파리 생리와 동등하다는 주장은 하지 않는다.

t160의 실제 SAC 교사200개 관측은 t162에서 픽셀·몸 감각·정책 요청 재생 오차0으로
봉인했다. 별도75개는 t168 개발 자료다. t164는 전자를8에포크·104회 업데이트로 학습했다.
회로 연결은 고정하고 시각·기관 어댑터와 운동 출력을 학습했다. t169 개발 평가 조향 RMSE는
약0.179로 영 출력 기준약0.051보다 나빴다. 따라서 조향 편향과 일반화 문제는 남아 있다.

## 전달 시계와 촬영 주기

Windows Python의 `monotonic`은 이 환경에서 약15.625ms 해상도인 GetTickCount64였다.
초기 측정의 작은 왕복 불확실성만으로 정밀 시각 정렬을 주장하지 않는다. 양자화 여유를
명시한 뒤 실제 제어 경로의 카메라·native·SDK 수신과 actor 시각을 QPC `perf_counter`로
통일했다. 소스별 가장 이른 렌더 시각과 보수적인 영상 나이를 사용한다. 물리 노출 동기화는
미검증이며 현재 전달은 PNG/JSON이다. GPU 공유 텍스처 소비는 아직 없다.

30FPS 백그라운드 렌더에40ms 촬영 요청을 보냈을 때 일부 촬영 간격은 약67ms였다.
t184는17개 학생 요청 뒤110ms 영상 선택 예산을 넘어서 정지했다. 약2.18m의 최대 기록
변위와 약14.98km/h를 기록했다. t185의 영상·몸 입력→모델 출력 재생 오차는0이었다.

이를 해결하기 위해 촬영 요청 주기를30ms로 바꿨다. 렌더 틱마다 최대 한 묶음만 처리하며
제어/신경회로 주기는40ms로 유지한다. 요청은 최대1000묶음·60초로 유한하며 자료 수집
프레임 예산도 촬영/제어 주기 비율에 맞췄다. 영상 선택110ms, 요청 직전 전체 입력150ms
제한은 늘리지 않았다.

t186은 수정 후 백그라운드 읽기 전용 추론150회를 완료했다. 모든 관측에서 네 소스가
유효했고 실제 결정 간격 중앙값40.39ms,99백분위44.44ms였다. 처리 시간은 중앙값32.29ms,
99백분위40.25ms였다. 이 수치는 경성 실시간 보장이나 GPU 전력 측정이 아니다.

## 실제 학생 주행

| 시험 | 학생 요청 | 최대 기록 변위 | 최대 기록 속도 | 종료 |
|---|---:|---:|---:|---|
| t176/t177 | 8 | 0.269m | 5.002km/h | 첫 시험 속도 제한 |
| t184/t185 | 17 | 2.178m | 14.979km/h | 영상 선택 지연 |
| t187/t188 | 38 | 8.465m | 25.445km/h | 속도 제한 |

변위와 최대 속도는 정지 피드백도 포함한다. t187의 제한 초과를 처음 감지한 속도는
25.365km/h였으며 정지 과정에서25.445km/h가 기록됐다. 목표15m를 달성하지 못했다.
제어 구간 마지막 진단 gap은 약0.743m, 측면 여유는약2.957m, tyres_out은0이었다.
모든 학생 요청은 교사 혼합 없이 모델3출력과 선언한 조향 축 변환만 사용했다.
각 감사에서 입력→출력 재생 오차0, 게임 비전면, 실제 정지와 vJoy 해제를 확인했다.
SDK는 비동기 출판 때문에 즉시 응답 오차 기준을 통과하지 못했다. 이를 숨기거나
도로 바퀴 각도의 독립 물리 보정 완료로 해석하지 않는다.

현재 주행은 제한된 직선 구간 시험이다. 코너·지속 속도 유지·완주는 증명되지 않았다.

## 학생 상태를 다시 교사에게 질의

t190은 t187의38개 actor 관측을 원본 PNG·native prefix에서 다시 만들고 전체 재귀 출력
재생과 정지 상태 검증 후 봉인했다. 학생 제어는 `expert_labels_available=false`로 기록해
정답으로 학습하지 못하게 했다. t189는 개발 중 manifest의 decisions 필드 누락으로 검증이
실패한 시도이며 후속 입력으로 사용하지 않는다.

t192는 같은38개 상태를 고정20km/h 기하 교사에게 오프라인 질의했다. 관측·마스크·시각은
바꾸지 않고 행동 라벨만 교체했다.19개 상태에서 제동>0.05,14개에서>0.3을 제안했다.
이는 실행하지 않은 교사 제안이며 실제 제동 응답 검증을 대신하지 않는다.

기하 교사의 조향 이득은 t180의 실제 교사 주행57개 샘플에서 맞춘
약-0.09867 curvature/canonical steering이다. 관측 속도 범위는 약17.49~19.85km/h이며
더 낮은 속도로의 외삽 검증은 없다. 경로와 위치는 교사 내부에만 남는다.

기존200개도 같은 교사 계약으로 질의한 t191과 t192를 t194의238개 학습 자료로 합쳤다.
75개 개발 자료는 t193에서 같은 계약으로 별도 질의해 학습에서 제외했다. 서로 다른
SAC/기하 교사 계약을 그대로 섞지 않았다. t195는 이 자료로8에포크·104회 업데이트를 마쳤다.
학습 RMSE는 조향/가속/제동 순서로 약[0.06168,0.03343,0.09003]이었다.

t196의 별도 개발 평가 RMSE는 약[0.18371,0.05531,0.17279], 영 출력 기준은
약[0.24323,0.10629,0.42349]였다. 회로5개 고정 텐서와 그래프를 원본과 대조했다.
그러나 t197 정차 shadow에서는 가속이 시간이 지나며 거의0으로 줄었다.

t198은 실제150개 요청을 완료했지만 제어 종료 시 변위는 약0.061m뿐이었다.
목표15m를 달성하지 못했고, t199에서 픽셀·몸 입력과 모델 출력 재생 오차0 및 정지를
검증했다. 따라서 t195를 기존 모델보다 주행 성능이 좋은 모델로 채택하지 않는다.
정차/출발 구간의 지속 가속 학습이 부족하다는 다음 행동의 근거로 사용한다.

t200은 이150개 실제 관측에도 같은 기하 교사를 질의했다. 제동>0.05 라벨은0개였다.
관측·마스크·시각은 그대로 유지했다. t201은 기존238개와 이를 합친388개 자료이며,
t202는 출발 유지와 속도 초과 제동을 함께8에포크·104회 업데이트로 학습했다.
학습 RMSE는 약[0.04687,0.02837,0.05512]였다. t203 개발 RMSE는
약[0.19129,0.04639,0.15981]로 제동·가속은 t196보다 낮았지만 조향은 조금 높았다.
고정 회로와 자료 분리 검사를 통과했고 t204는75회 읽기 전용 추론을 완료했다.

t205의 실제150개 제어 종료 시 변위는 약0.944m였다. t206의 정지 과정 포함 최대 기록
변위는 약0.948m, 최대 속도는약1.281km/h였다. 영상 지연 중단은 없었고 모델 입력→출력
재생 오차0, 게임 비전면, 실제 정지 및 장치 해제를 확인했다. 하지만 목표15m는 실패했다.
후반 가속은 대체로0.01~0.06이고 제동도약0.01~0.02로 남아 있었다. 출발을 충분히 유지하는
모델이나 지속 주행 모델로 채택하지 않는다. t207은 이150개 실제 저속 관측에 대한 같은
교사 계약의 미실행 질의다.

다음 학습에서는 실패 구간만 반복하는 것과 함께 실제 교사의 지속 출발→저속 주행→감속
연속 관측을 보강해야 한다. 교사 주행을 추가하면 실행 요청과 관측의 재생 검증도 다시 한다.
현재 카메라 구성과 회로를 유지하며 이 문제를 먼저 확인하고, 그 뒤 코너 자료를 늘린다.

다음은 후속 모델의 분리된 개발 평가와 실제 가감속 검증이다. 이어 코너/회복 자료,
지속 주행과 완주, 타이어 열·하중 변화와 셋업 적응, 랩타임 최적화가 남는다.
