# 30km/h 목표의 연속 교사 자료와 학생 학습

2026-10-28 KST. 사용자 요청으로 교사 목표 최대 속도를20→30km/h로 높였다.
중단 기준은40km/h이며, 경로 오차·측면 여유·영상/센서 검사와40ms 제어 마감은 유지했다.
이것은 교사 수집 및 제한된 학생 시험 준비다. 학생의30km/h 유지나 자율 서킷 완주를
검증한 결과가 아니다.

후속 재시험에서는 조향 교정 후보가 백그라운드에서 실패했고 시간 조건의 반복성 문제도
확인했다. 최신 채택 여부와 제약은 [조향 교정·실행 시간 기록](ac-steering-correction-20261028.md)을 따른다.

## 화면 조작과 실제 제어

t224는 API 재개, t225는 정차 조향 보정, t226은 vJoy1단 연결이다. 창 활성화·클릭·키 입력은
사용하지 않았다. 수집 종료 후 t233의 API로 다시 일시정지했다. 모든 다음 에피소드 준비도
`scripts/control_ac_session.py`를 사용하며 화면 조작으로 자동 우회하지 않는다.

`pilot_ac_teacher.py`에 `--geometric-target-speed-kmh`를 추가했다. 기하 교사의 목표는
gap과 방향 오차에 따라30km/h보다 낮아질 수 있다. 목표30 설정은 실제로30에 도달했다는
뜻이 아니다. 교사 조향 이득은 기존 실제17.49~19.85km/h 관측에서 추정한 t180을 사용했다.
현재 더 높은 속도의 제어 실험이며, 조향 이득의 전 속도 영역 물리 보정을 주장하지 않는다.

## 시간 초과와 현재 확인 범위

t227은20km/h 수집에서361개 요청 뒤40ms 마감 초과로 중단됐다. 동기식 NAS 기록을
로컬 SSD spool로 옮겼지만 이것만으로 문제가 해결되지는 않았다. t228의30km/h 수집도
358개 요청 뒤 중단됐다. 추가 계측에서 마지막 영상 단계54.22ms, 전체57.51ms를 기록했다.
해당 마지막 요청에는 완전한 후속 피드백이 없으므로 완료 자료로 학습에 넣지 않았다.

t229는 실제 정차 이미지의 합성 반복800회로 망막 처리 시간을 측정한 오프라인 성능 실험이다.
중앙값9.75ms, 최대11.69ms였고20ms 초과는 없었다. 실제 차량 수집이나 학습 자료가 아니다.
이 결과만으로 실제 지연 원인이 해소됐다고 판단하지 않았다.

t230은 cache/망막 처리 단계와 Python GC 시각을 추가로 기록하며 같은30km/h 목표로
400개 제어를 완료했다. 이 run의 망막 처리 시간은 중앙값12.55ms,95백분위15.52ms,
99백분위16.99ms, 최대19.03ms였다. 기록된 GC generation2 수집은 없었다. 이전54ms
지연의 원인을 GC로 확정하지 않으며, 한 번의 성공을 경성 실시간 보장으로 해석하지 않는다.

통합 검증이다. 과거 SAC 분기의 성공으로 대신하지 않았다.

## 30km/h 학생 자료

t234~t237은 과거 실제 관측200+38+150+150개에 같은30km/h 교사를 질의한 자료다.
관측·결측 마스크·시각은 원본과 같고 라벨만 바꿨다. 이538개 라벨은 실행된 제어가 아니다.
t232의 실행 교사400개와 합친 t239는 총938개,5개 연속 에피소드다.20km/h와30km/h
정답을 같은 과제로 섞지 않았다. 별도75개 개발 관측은 t238에서 같은30km/h 기준으로
질의하고 학습에서 제외했다. 같은 차·트랙·세션의 개발 자료이며 독립 최종 시험은 아니다.

t240은 t202의 네 방향 학생에서 시작한다. 회로 연결을 고정하고 시각·기관 어댑터와 운동
출력만 학습한다.4에포크 예산, 길이16의 역전파 구간, 결정당4개 신경 틱,40ms 결정 주기를
사용한다. 길이가 같은 에피소드끼리 최대2개씩 묶어 불필요한 padding을 줄인다. 각 연속
에피소드 안에서 구간 분리 시 수치 상태는 유지한다.

학생 시험에는 별도 `tracking_30kmh` 프로필을 만들었다.30km/h 과제 계약이 일치하는
체크포인트만 허용하며, 최대300개 결정·30m 계획 변위·40m 강제 제한·40km/h 강제 제한을
적용한다. 기존20km/h 모델이 이 프로필로 들어갈 수 없도록 검사한다. 경로 오차3m·측면
여유1m·입력 나이150ms 검사는 그대로다. 프로필 구현이 주행 성공의 증거는 아니다.

## 학생 모델 결과와 실제30m 시험

t240은4에포크·204회 업데이트를 완료했고4번째 회차를 선택했다. 학습 RMSE는
조향/가속/제동 순서로 약[0.10617,0.07427,0.03258]이었다. 체크포인트 SHA-256은
`4f8e66a97f1e8f6bd03b37b523656e3eb82de475cc29c7ce9bff7d18e3c808c0`이다.
t241의75개 개발 관측 RMSE는 약[0.10457,0.06224,0.04174], 영 출력 기준은
약[0.24323,0.13353,0.03453]이었다. 제동 오차는 영 출력 기준보다 크므로 모든 출력이
개선됐다고 하지 않는다. 그래프와5개 고정 회로 텐서가 t202와 같음을 검증했다.

t242의 API로 재개한 뒤 t243에서75회 읽기 전용 추론을 완료했다. 마지막 정차 입력의
출력은 조향약0.0225,가속약0.2087,제동약0이었다. 이전 모델의 가속 소실은 이 검사에서는
나타나지 않았다. 물리 주행에서의 지속 가속은 이어지는 시험으로 별도 확인했다.

t244는 교사를 섞지 않은 학생 출력144개로 계획 변위30m에 도달한 뒤 자동 정지했다.
제어 종료 시 변위는30.177m, 정지 과정 포함 최대 기록 변위는 t245 감사에서32.020m였다.
최고 기록 속도는24.417km/h다.30km/h 목표로 학습했다는 것과 실제30km/h 도달은 구분한다.
주행 피드백의 최대 절대 gap은2.629m, 최소 측면 여유는1.920m, tyres_out 최대값은0이었다.
정지 후 gap은약-2.770m였다. 종료 쪽으로 경로 오차가 커져 조향 개선이 필요하다.

t245에서 원본 픽셀·몸 감각으로 재귀 출력144개를 다시 만들어 최대 오차0을 확인했다.
정지와 vJoy FREE, foreground 기록0, UI 입력0도 확인했다. SDK 즉시 응답 오차 기준은
비동기 출판 때문에 여전히 통과하지 못했다. native 응답과 요청 재생 검사와 구분해 보존한다.
학생 입력에 진단 위치나 경로가 들어가지 않았으며 이 시험의 성공은 제한된30m 구간이다.

t246의 API로 게임을 다시 일시정지했다. t247은 실제144개 관측에 같은30km/h 교사를
질의한 다음 조향 교정 자료이며, 미실행 교사 라벨이라는 구분을 유지한다. 다음은 이 자료를
보강하고 다른 시작점·구간에서 지속 속도와 경로 추종을 검증하는 것이다.

전체 목표인 코너·지속 서킷 주행·완주와 타이어/하중/셋업 적응·랩타임 최적화는 남아 있다.
