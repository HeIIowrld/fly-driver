# 비행 회로용 실제 기록 확대 — 2026-10-29

[대전제](PROJECT_CHARTER.md)는 유지한다. 자동차를 초파리의 가상 몸으로 삼아 시각·비행
감각운동 회로로 조향·가감속·레이싱 라인과 랩타임을 학습하는 연구다.
이번에는 평균 출력에 머문 초기 후보를 다시 학습하기 전에 실제 입력 자료를 확대했다.
새 회로의 가중치 변경과 차량 제어기 승격은 하지 않았다.

## 기존 좌회전 기록의 재사용 조건

`t1044`는 기존 13개 봉인 에피소드의 **12개 전체 원본 기록**을 검사했다.
원본 센서 prefix의 해시·packet, 첫 수신 시각, 전체 관측 간격, 네 시점 노출 시각,
차량/버전 식별 파일과 봉인 에피소드의 원래 slice 시각을 대조했다.
기록 공백을 자르거나 인계 시 신경 상태를 초기화하지 않았다.

- `t788`: 전체 292관측, 최대 간격 72.16ms. 봉인 표적 7개 중 좌조향 4개.
- `t799`: 전체 977관측, 최대 간격 63.79ms. 봉인 표적 37개 중 좌조향 4개.
- 나머지 10기록은 현재 계약에 필요한 원래 차량/정적 버전 식별 파일이 없다.
  다른 동시 기록으로 출처를 입증할 가능성은 남지만 현재 식별값으로 소급 채우지 않았다.
  `t629`는 추가로 원래 86.74ms 공백이 있어 현재 80ms 계약을 넘는다.

이는 재생 전 필요한 조건 검사이며 RGB 번들 전체 bytes 검증은 아니다.
원자료를 삭제하거나 기존 비교용 데이터의 역사적 결과를 바꾸지 않았다.

`t1045/t1046`에서 두 기록의 모든 1,269관측을 새 몸 v1으로 변환했다.
기울기2·yaw·하중비율4·native 온도4는 유효하며 회전 두 축/선형가속도는 미등록 상태다.
`t1047`은 긴 기록의 전체 네 시점을 고정 저자 시각망으로 GPU 재생했다.
원래 40.2659초/977관측을 41.8821초에 재생했고 내부 8,709tick, 반복 capture 1회다.
카메라마다 상태를 유지했으며 인계 reset·저자 가중치 변경·차량 조작은 0회다.

`t1051`에서 몸/시각 시각과 단계 일치, 반복 capture 입력 일치, 모든 망막별 반응의
유한값을 검사했다. 8tick 분할 상태 전달 오차는 4.77e-7, 카메라 batch 순서 오차는
5.96e-7, 중간 reset 반례 차이는 0.5053이다. 실제 비행 기능이나 운전 성공을 증명하지 않는다.

## 새 백그라운드 교사 수집

`t1043`에서 API의 실제 heartbeat/차량/일시정지 상태를 다시 확인했다.
`t1048`은 기존 검증된 `expert-collect30-speed30` 프로필을 실행했다.
AI 속도 힌트30km/h·조향 multiplier0.9·30초 lease와 기존 속도40km/h/변위360m/
이탈/카메라 신선도 가드를 유지했다. 창 활성화·클릭·키 입력·vJoy 명령은 0회다.

| 최대 속도 / 최대 위치 차이 | 30.959km/h / 230.051m |
| 관측 / 네 시점 유효 관측 | 742 / 742 |
| 최대 관측 간격 / 80ms 초과 | 41.387ms / 0회 |
| 카메라 대기 실패 | 0회 |

수집기에 원래 비개인 static identity 저장을 추가했다. AC1.16.4/SHM1.7/BMW Z4 GT3/
Monza를 기록하고 확인한 뒤 수집한다. 선택 옵션 `--local-event-spool`은 이벤트를 로컬에
먼저 기록하고 종료 후 NAS에 원본 bytes를 복사·해시 확인한다. 원본 로컬 파일도 남긴다.
네 시점 이미지는 공유 GPU texture를 읽고 원본 BMP를 보존했다.

`t1050`은 RGB/센서 원본과 기존 actor packing의 재생 오차가 모든 필드에서 0임을 확인했다.
5,738개 보관 파일의 해시를 검사했다. 몸 v1 전체 재생은 `t1049`다.

## 표적과 학습 경계

`t1052`는 기존 독립 조향 보정과 원래 API/센서 receipt를 사용해 미래40ms의 적용 제어값을
표적으로 만들었다. 허용 지연25ms, AI 활성/속도 힌트가 확실한 시간 창만 사용한다.
내부 AI 명령을 읽었다거나 정확한 물리 명령 시점을 검증했다고 주장하지 않는다.

유효 표적은 각 head **737개**다. 모두 우조향이며 canonical 조향 범위는
0.03540–0.38300이다. **유효 제동 표적은 0개**다.
원본 관측에는 시작/종료 과정의 brake>0.01 값 4개가 있지만 유효 교사 표적에는 들어가지 않는다.
그 값을 경로 판단에 따른 제동 성공으로 바꾸어 부르지 않는다.

`t1054`에 전체 742관측을 한 에피소드로 봉인했다. 표적 없는 시작/끝 관측도 보존했다.
이는 **AI30km/h 과제**이며 기존 AI15km/h와 별개다. 목표 조건을 구분하는 계약 없이 합치지 않는다.
새 비행 구조의 고정 명령 `[0,0.2]`를 임의로30km/h 목표라고 재명명하지 않는다.
기존 초기 학습 스크립트의 단일 기록/분할 조건을 무력화해서 이 자료를 끼워 넣지 않는다.

`t1053`은 새 기록을 네 개의 독립 시각 상태로 GPU 재생했다. 전체 30.1026초를
29.2688초에 재생했고 내부6,669tick, 반복 capture102회다. 반복 capture를 새 영상으로 세지 않는다.
몸/시각의 원래 시각·packet은 일치하며 저자 가중치는 바꾸지 않았다.
`t1055`의 전체 정렬/반복 입력 검사를 통과했다. 분할 상태 오차4.77e-7,
카메라 순서 오차7.15e-7, 중간 reset 반례 차이0.5016이다.
최종 읽기 전용 상태 `t1056`도 paused/AIoff/cameraoff/gas0/brake1, 창 비전면이었다.

## 이어서 할 일

1. t788의 짧은 기록도 시각 재생하고 원래 희소한 좌조향 표적을 보존해 변환한다.
   이 8개 좌조향만으로 좌우 균형 자료가 확보됐다고 판단하지 않는다.
2. 더 많은 좌우 커브와 실제 제동을 확보한다. 기존 저속 AI가 제동 없이 감속하는 점을 고려해
   제동이 필요한 조건/교사 과제를 명시한다. 종료용 제동을 주행 정답으로 섞지 않는다.
3. 시각/몸/교사/과제 명령을 버전이 있는 다중 에피소드 계약으로 묶는다. 속도 목표와 운동
   의도의 의미를 구분하고 에피소드마다만 상태를 초기화한다. 미사용 기록의 평가를 별도로 둔다.
4. 그 뒤 비행 후보를 학습하고 평균 기준·커브별 응답·시각/몸/경로 제거와 균형 반응을 검증한다.
   완주·반복 안정성·레이싱 라인/랩타임 검증은 계속 필수다.

관련 코드 검사: 기록기 7검사, 비행 회로 6검사, 수정 Python 파일 Ruff 통과.
이 문서의 데이터 확대는 새 후보의 운전 검증이나 전체 목표 완료를 뜻하지 않는다.
