기록일: 2026-10-29, Asia/Seoul. 목적과 성공 조건은 [프로젝트 대전제](PROJECT_CHARTER.md)를 따른다.
이 문서는 t1171 이후의 실행 증거를 정리한다. 전체 목표와 운전 후보는 여전히 미완료·미승격이다.

## 유지할 목표

> 초파리의 겹눈/운동 시각과 비행 유래 균형·운동 회로를 자동차라는 가상 몸에 연결한다.
> 차체 기울기·회전·하중·타이어 상태를 몸 감각으로 되먹임하며 조향·가감속과
> 빠른 레이싱 라인/랩타임을 학습한다.

## 실패와 운영 경계

- t1173: 상태 JSON의 원자적 교체 중 파일이 잠깐 없어진 경우 실패했다. 같은 파일 읽기의 재시도를 10ms로 제한해 처리하며, 오래된 관측으로 대체하지 않는다.
- t1174: 기본 대기 방식의 펄스 폭 편차가 기준을 넘었다. Windows 고해상도 대기 타이머로 변경한 뒤 t1182/t1183에서 다시 검증했다.
- t1184의 yaw0 trial-01: 교란 전 원본 입력 나이 167.3ms로 신선도 기준 150ms를 넘었다. 실패를 보존하고 제동·일시정지를 확인했다.
- [t1186 후속 실행](../runs/flight-timed-yaw-block0-continuation-20261029-t1186/result.json): yaw0가 1관측 뒤 승인된 명령의 80ms 유효기간을 넘겨 제동·일시정지했다. 성공한 full 시험은 원본 경로와 해시로 보존했다.
- 입력 신선도 150ms는 각 새 요청의 원래 영상 시각 기준이다. 명령 유효기간 80ms는 마지막 승인된 드라이버 요청 기준이다. 둘을 혼동하거나 입력 시각을 다시 매기지 않는다.

예정된 12회/3블록 실제 비교는 미완료다. 성공 사례만 골라 안정화 성능을 주장하지 않는다.
마지막 실제 제어 실행 t1186의 종료 기록은 worker 종료·중립/제동·pause 확인이다.
이는 기록 당시 상태이며 다음 실행 전에는 실제 프로세스·게임·장치 소유 상태를 다시 확인한다.

## 추가 진행: 새 계산 경로의 실제 적용과 실패 분석

- `configs/flight-physical-yaw-frozen-tail-v2-20261029.json`에 t1187/t1188 인증을 명시했다.
  실행과 독립 감사 모두 같은 backend를 설치하며, 원본 코드 해시·전체 뉴런 대조·양 모드 결합 재생 증거를 요구한다.
  이전 v2 계획과 실제 시험은 합치지 않는다. 관련 상태·교란·warmup 검사 13개와 Ruff 검사를 통과했다.
- [t1189](../runs/flight-frozen-tail-preflight-20261029-t1189/result.json)는 읽기 전용 점검을 통과했다.
- [t1190](../runs/flight-frozen-tail-block0-20261029-t1190/result.json)의 첫 full 시험은 정차 prefix에서 실패했다.
  첫 요청 뒤 두 번째 추론 64.341ms 동안 승인 명령의 80ms 유효기간이 만료되어 제동했다.
  actor 입력과 추론은 각각 2개, 적용 완료 관측은 1개이며 이동 조향 출력은 적용하지 않았다.
  worker 종료·중립/제동·일시정지와 원본 영상 보존을 확인했다. 새 계획의 실제 반복 비교는 미완료다.
- [t1191](../runs/flight-frozen-tail-failed-prefix-profile-20261029-t1191/result.json)은 실패 prefix의
  원래 2관측 전부를 같은 시각·픽셀·몸 값·상태로 재생하고 의도 출력을 대조했다.
  두 번째 계측 재생은 59.829ms, 시각 호출 2개의 GPU event 구간은 39.556/7.693ms였다.
  계측 오버헤드가 있는 오프라인 결과이며 실제 주행 지연 통과 증거가 아니다.
- 실패 후 첫 GPU 표본에서 별도 llama-server PID45856의 compute 사용률 약85.61%를 관측했다.
  이후 [t1192의 5개 표본](../runs/flight-gpu-contention-20261029-t1192/result.json)에는 해당 프로세스의
  0.5% 초과 항목이 없었다. 부하가 일정하다고 가정하지 않으며 실패 순간의 원인으로 확정하지 않는다.
  다른 프로세스는 종료·변경하지 않았다. 첫 수집의 invalid counter 오류도 기록했다.

## 재개 지점

1. 새 backend는 실제 실행에 연결했지만 지연 가드로 실패했다. t1190/t1191의 시각 연산 구간과 자원 경합을 구분하고 처리 시간의 여유를 확보한다. 같은 실패 조건에서 무작정 재실행하지 않는다.
2. 기존 v2 설정의 scratch 인증은 t1177을 가리키므로 그대로 실행하지 않는다. 새 실행에는 별도 frozen-tail 계획과 해당 원본 인증을 사용한다.
3. 신선도·명령 유효기간·속도 가드를 유지하고 새 에피소드에서 양방향 full/yaw0 반복 비교를 수행한다. 원래 관측·시간·회로 상태와 모든 실패를 보존한다.
4. 이후 시각 경로 추종과 학습한 가감속, 타이어·접지·셋업 대응, 학생 단독 유효 완주·반복·레이싱 라인/랩타임 개선을 검증한다.

창 활성화·클릭·키 입력으로 우회하지 않는다. 검증된 CSP 수명주기 API와 백그라운드 센서·vJoy를 사용한다.

앞선 문서 정리 단계에서는 제어를 시작하지 않았다. 이후 목표 계속 작업에서 t1190을 실행했고,
정차 가드 중단 뒤 종료했다. UI 조작과 새 optimizer 학습은 없었다.
