# 파리 회로 학습 자원 사용 개선

기록일: 2026-10-28 KST. 전체 서킷 주행은 아직 검증되지 않았다.

GPU 학습은 RX 9070 XT의 ROCm/PyTorch `cuda:0`, FP32 sparse COO를 사용한다. 여섯 에피소드를 이미 함께 처리하고 있으며, 파리 회로는 6,557개 뉴런·644,512개 연결이다. GPU 사용률이나 메모리를 억지로 채우기보다 CPU 동기화 대기를 줄였다.

## 변경과 검증

기존 오프라인 학습은 neural tick마다 상태와 readout의 유한값·범위를 확인하면서 GPU 검사 결과를 CPU로 가져왔다. 새 `chunk_validated_training` 옵션은 청크 진입 시 감각 입력·상태·고정 연결·시간상수·상태 마스크를 검사하고, 청크 종료 시 상태와 제어 출력을 검사한다. 신경망 수식, 연결, readout 계산은 그대로다. 초기 상태와 alpha 및 mask의 범위에 의해 중간 상태도 [0,1]을 유지한다.

기본값은 꺼짐이다. 실제 주행의 `advance()`는 이 옵션과 관계없이 기존 tick 단위 검사를 사용한다. 체크포인트 배포 constructor에 이 옵션을 넣지 않는다. 원래 에피소드 경계에서만 수치 상태를 초기화하고, 청크 경계에서는 detach만 한다. padding mask도 유지한다.

CPU·GPU 단위 검증에서 출력·최종 상태·기울기가 기존 경로와 정확히 같았다. 비정상 상태, 잘못된 alpha, 실제 주행 검사의 유지도 확인했다. 관련 테스트 19개 및 Ruff 검사를 통과했다.

## 실제 모델 측정

같은 t373 체크포인트, 같은 4개 기록 에피소드, offset 112의 동일 prefix 상태에서 4 neural ticks/결정의 순전파·역전파를 측정했다. 각 조건은 warmup 1회 후 3회, GPU synchronize 포함이며 optimizer/game 명령은 0회다. 시드와 소스·데이터 해시는 각 manifest에 기록했다.

| 학습 검사 방식 | 결정 수 | GPU 중앙값 | 결정당 시간 | GPU peak allocation |
|---|---:|---:|---:|---:|
| 기존 tick 검사 t382 | 16 | 0.39619초 | 24.76ms | 325,250,048 bytes |
| 청크 검사 t383 | 16 | 0.25240초 | 15.77ms | 325,250,048 bytes |
| 청크 검사 t384 | 64 | 0.94360초 | 14.74ms | 668,579,328 bytes |

같은 길이에서 약 1.57배 빨라졌다. 64개 구간은 기존 16개 조건보다 결정당 약 1.68배 빠르지만, 역전파 시간 범위도 달라지는 학습 설정이다. 모든 조건에서 CPU 대비 출력 최대 차이는 1.19e-7, GPU 기울기는 유한했다. 순간 GPU 사용률은 측정하지 않았으며 이 수치를 사용률 향상으로 해석하지 않는다.

## 전체 학습 실험

`configs/ac-gpu-resource-training.json`은 t373과 같은 초기 체크포인트 t368, 시드 862903, 1,542개 결정/6개 에피소드, 8 epochs, 학습률 0.00015와 epoch 단위 optimizer update를 사용한다. 청크 검사를 켜고 길이를 16에서 64개 결정으로 늘렸다. 학습하지 않은 t347 구간은 계속 평가에만 사용한다. 긴 청크는 성능과 일반화에 영향을 줄 수 있으므로 학습 결과와 평가를 따로 확인한다.

현재 실제 게임은 일시정지 상태다. 마지막 t378의 30.14m 주행은 t379에서 원본 픽셀·몸 감각 기반 정확 재생이 확인됐다. 이 짧은 구간이 전체 회로, 제동 일반화 또는 최적화 완료를 뜻하지 않는다.

실제 학습 t386은 8 epochs/8 optimizer updates를 완료했다. 평균 epoch는 18.63922초에서 10.32646초로 1.805배 빨라졌다. Peak GPU allocation은 766,753,280 → 1,343,350,272 bytes다. 전체 epoch 평균에는 기록에 남긴 학습·해당 epoch 평가가 포함되며 최초 로딩과 초기 평가는 포함되지 않는다. 학습된 모델 SHA256은 `f23ca9527440077b31ff023e2a29e717e663fd2780f13de51118dbc1242c8b1e`이고 선택 epoch는 8다.

## 배포 경로와 별도 기록 평가

GPU 모델을 CPU cached CSR 주행 경로로 불러와 두 평가를 완료했다. 모든 저장 모델 tensor는 CPU이며 배포 constructor에는 청크 검사 옵션이 없다. 연결·신경망 상태 방정식·readout은 바뀌지 않았고, 학습한 값은 선언된 시각/기관 adapter weight뿐이다. `t386/deployment-validation.json`과 t387/t388에 검증 결과를 남겼다.

| 평가 기록 | 기존 t373 RMSE 조향/가속/제동 | 새 t386 RMSE 조향/가속/제동 |
|---|---|---|
| 다음 구간 500개, t347 | 0.094800 / 0.066144 / 0.000011 | 0.095762 / 0.065531 / 0.000000 |
| 이전 개발 구간 75개, t303 | 0.125341 / 0.084319 / 0.320763 | 0.123191 / 0.083602 / 0.319999 |

다음 구간 조향은 소폭 나빠졌고, 다른 수치는 비슷하거나 조금 개선됐다. 이전 구간의 잘못된 제동은 여전히 크다. 따라서 학습 실행 속도 개선은 확인됐지만 새 체크포인트를 실전 주행용으로 승격하지 않았다. 학습·개발 데이터가 적고 같은 차/서킷에서 수집됐으므로 전체 서킷 일반화의 근거로 사용할 수 없다. 긴 청크의 효과와 검사 동기화 절감 효과를 전체 epoch에서 완전히 분리한 실험은 아니다. 같은 길이의 t382/t383 측정으로 검사 변경의 독립 효과를 확인했다.

다음 학습은 청크 검사를 활용할 수 있다. 우선 추가 제동·회복 상황을 수집하고, 긴 구간의 반복 성공을 확인한 뒤 전체 서킷으로 확장한다. 온도·하중·셋업별 최적화는 후속 과제다. GPU 메모리에 여유가 있어도 같은 데이터를 중복 계산하거나 학습 횟수만 늘리는 것은 우선순위가 낮다.
