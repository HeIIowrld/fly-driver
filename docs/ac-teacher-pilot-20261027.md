# AC 교사 모델의 짧은 주행 실행 경로

2026-10-27. 구현 및 단위 검사 완료, 실제 주행 미실행.

`scripts/pilot_ac_teacher.py`는 공개 SAC 교사가 원본 AC에서 짧게 주행하는 경로다.
파리 학생 모델은 아니다. 이 단계의 목적은 이후 비전 학생에게 제공할 실제 교사 요청과
차량 피드백을 얻는 것이다. 실행 모드에서는 원본 창 영상도 별도 작업으로 저장한다.
학생 학습·랩 리셋은 하지 않는다. 실제 영상 수집 상태는 아래 추가 점검을 따른다.

기본 실행은 읽기 전용이다. `--execute`가 있어도 다음 조건을 먼저 검사한다.

- 원본 엔진 창 하나, BMW Z4 GT3 / Monza, 고정된 모델·지도·조작 프로필 해시.
- 새 SDK 교사 필드와 서로 이어지는 실제 센서 이력 3개. 누락·세션 변경·시간 간격 오류는 중단.
- 같은 엔진 세션과 같은 프로필·DLL·축 설정에서 얻은 정차 조향 보정 결과.
  요청 보정 후 SDK 조향 배율이 공개 기록의 약 270과 2% 이내로 맞아야 한다.
  약 450인 값을 보정 없이 사용하는 것은 거부한다.
- 정차한 차량이 전진 기어이며 기준 경로 3m 이내. 내장 AI 제어가 꺼져 있어야 한다.
- 실제 장치 연결 후 센서로 조향 0·가속 0·제동 1을 확인하고 이력을 다시 채운다.

초기 절대 요청은 장치의 정지 요청과 같은 `[0, -1, +1]`이다. 이후 공개 모델의 상대 요청을
고정된 변화율로 누적하고, 페달을 각각 `(요청+1)/2`로 변환한다. 요청과 다음 실제 피드백은
별도 이벤트로 기록한다. 장치가 요청을 수락했다는 사실을 게임 적용 확인으로 표시하지 않는다.

기본 50회, 최대 250회 결정이며 명목 주기는 40ms다. 최초 실험의 속도 한도는 60km/h다.
경로 이탈·센서 중단·프로필/엔진 변경·실행 폴더의 `stop` 파일·시간 초과는 중단 사유다.
종료 시 정지 요청 후 장치를 해제한다. 이 요청의 실제 제동 적용을 보장하는 하드웨어 감시기는
없으며, 호스트 수신 시각은 영상 노출 동기 검증이 아니다. 창 활성화나 키보드 조작은 하지 않는다.

## 실행 순서

새 수집기가 로드된 뒤 읽기 전용 점검:

```powershell
python -m scripts.pilot_ac_teacher --output runs/새로운-점검-폴더
```

LOCK540 후보를 적용하고 게임에서 다시 로드한 뒤, 정차 상태에서 측정:

```powershell
python -m scripts.calibrate_ac_sdk_steering --config runs/ac-teacher-collector-deployment-20261027-t44c/proposed-axis-probe.json --output runs/새로운-보정-폴더
```

이 보정은 실제 정차 조향 명령을 보낸다. 현재 후보는 적용되지 않았으며 이 명령을 실행하지 않았다.
새 보정 결과와 전진 기어·트랙 위 시작 상태를 확보한 다음에만 `--execute`를 사용한다.
공개 교사가 이 차·시작 상태에서 운전 가능한지는 그 실제 실험으로 판단해야 한다.

  KeyboardInterrupt 시 정지 요청과 해제, 450 배율·다른 세션·프로필 거부를 확인했다.
  실제 이동이나 주행 성능을 증명하는 검사가 아니다.
- `runs/ac-teacher-pilot-readiness-20261027-t45/`: 실제 엔진을 읽었으나
  `SDK privileged_teacher extension not loaded`로 `not_ready`. 차량 제어 명령과 UI 조작은 0건.

다음 실제 단계는 새 SDK 로딩 → 읽기 전용 추론 → 조향 배율 보정 → 짧은 교사 주행이다.
그 뒤 실제 다중 시점 영상과 몸 감각·교사 요청을 연결하고, 오프라인 파리 학생 학습과
AC 검증으로 이어간다. 파리 학생의 실제 서킷 완주는 아직 미검증이다.

## 추가: 비동기 영상 연결과 현재 실패 상태

`ac_teacher_vision.py`는 정확한 AC 창의 WGC 원본 RGB를 별도 작업에서 저장하고 해시를 남긴다.
조향 루프는 파일 쓰기를 기다리지 않는다. 각 교사 요청에는 센서 수신 전에 콜백이 끝났으며
이미 저장된 영상 중 가장 최근 것을 연결한다. 호스트 기준 나이 한도는 200ms다.
그런 영상이 없거나 저장 작업이 실패하면 교사 요청을 보내지 않는다. 원본 영상은 창 전체이며
카메라 영역·FOV·미러 보정과 노출 동기가 미검증이므로 `training_admissible=false`다.

`scripts/probe_ac_background_collection.py`는 조작 없이 센서 루프의 기본 상태와 비동기 영상
저장 상태를 비교한다. 현재 실행 결과는 성공이 아니다.

- `runs/ac-background-paired-collection-20261027-t46/`: 첫 200ms에 영상이 없어 실패.
- `...-t46b/`: 초기 대기를 3초로 분리해도 영상 0장으로 실패.
- `runs/ac-wgc-thread-comparison-20261027-t46c/`: 기존 메인 작업의 WGC 수집기도
  3초 동안 콜백 0건으로 실패. 새 비동기 작업만의 오류라는 증거는 없다.
- 같은 시점 창은 최소화 false, visible true, DWM cloaked 0, foreground false였다.
  graphics 패킷 4763307→4763541, SDK 164109→164114로 엔진은 계속 동작했다.
  새 SDK 교사 필드는 여전히 로드되지 않았다.

이전 백그라운드 영상 수집 성공을 현재 조건에서 재현하지 못했다. 따라서 백그라운드 비전 주행이
준비됐다고 표시하지 않는다. 표준 게임·사용자 설정에서 focus/background 관련 스위치를
검색했지만 관련 설정을 찾지 못했고, 추정한 설정을 추가하지 않았다. 원인은 미확정이다.
이번 세 번의 실제 점검 모두 창 활성화·차량 조작은 0건이다.

## 추가 진단: Windows 세션 연결 끊김

`runs/ac-background-paired-collection-20261027-t46b/windows-session-diagnostic.json`에서
게임과 수집기는 모두 Windows 세션 1, WTS 상태 4였다. 입력 데스크톱 열기는 오류 5
(접근 거부)였고, 캡처 관련 사용자 설정 두 개는 Allow였다. 개인 계정명이나 데스크톱 화면을
수집하지 않았으며 로그인·원격 연결·설정 변경도 하지 않았다.

Microsoft의 [WTS 상태 정의](https://learn.microsoft.com/en-us/windows/win32/api/wtsapi32/ne-wtsapi32-wts_connectstate_class)에
따르면 상태 4는 WTSDisconnected다. 로그인 정보는 남아 있지만 클라이언트가 연결되지 않은
상태이며 잠금 화면으로 나간 경우도 예시에 포함된다. 이 값만으로 잠금·원격 접속 종료 중
어느 동작이 있었는지는 확정하지 않는다. [OpenInputDesktop 문서](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-openinputdesktop)의
데스크톱 접근 검사도 함께 사용했다. 연결 복구가 캡처를 해결하는지는 복구 후 재검증해야 한다.

`ac_windows_session.py`에 수집기·엔진의 세션 일치, active 상태, 입력 데스크톱 접근 검사를
추가했다. 실제 WGC 시작 전에 호출하므로 이 상태에서 빈 화면을 반복 수집하지 않는다.
active 판정은 캡처 시도를 허용할 뿐 영상 수신 성공을 보장하지 않는다. 합성 캡처 테스트는
주입한 가짜 캡처를 쓰므로 Windows 네이티브 상태 검사를 수행하지 않는다.

`runs/ac-session-readiness-20261027-t47/`에서 현재 두 프로세스의 disconnected 상태와 접근
거부를 재확인했고, WGC 시작이 구체적인 세션 오류로 중단되는 것을 확인했다. UI·차량 명령은 0건.
PC 직접 로그인 또는 원격 세션 재연결을 요청했으며, 연결 후에도 전면화 없이 캡처부터 검사한다.

## 연결 복구 후 실제 재검증

사용자의 연결 복구 응답 후 세션은 collector/engine 모두 active(0), 입력 데스크톱 접근 가능으로
변했다. 게임을 전면으로 올리지 않고 아래 두 짧은 기록을 얻었다. 따라서 현재 백그라운드 캡처
실패는 재현되지 않는다. 연결 끊김/잠금 상태에서도 수집된다는 뜻은 아니다.

| 저장 위치 | 센서만 수집 | 영상 병행 센서 수집 | 저장 영상 | 영상 쓰기 중앙값 | 40회 중 영상 후보 연결 |
|---|---:|---:|---:|---:|---:|
| NAS 직접 | 25.35Hz | 22.86Hz | 13장 | 141ms | 9회 |
| 로컬 디스크 | 24.39Hz | 24.38Hz | 28장 | 약 16ms | 40회 |

각 단계 센서 표본은 40개이며 2초 미만의 짧은 단일 비교다. 실행 순서·부하 통제 실험이나
지속 성능 보장이 아니다. Windows 기본 monotonic 시계 해상도 영향으로 0ms 작업 표본도
있으므로 세밀한 지연 비교에 쓰지 않는다. 센서 루프 주파수는 영상 FPS가 아니다.

- NAS 기록: `runs/ac-background-paired-collection-reconnected-20261027-t48/`
- 로컬 기록 및 프로젝트 회수본: `runs/ac-background-local-spool-20261027-t48b/`
- 두 기록 합계 센서 160쌍, 영상 41장. 센서·영상의 foreground 기록은 모두 0이었다.
  SDK wire/native prefix 해시, NPY 파일·픽셀 해시, 영상 후보의 호스트 시각 선후 관계를
  재검증했다. 각 기록에서 RGB 해시는 모두 달랐다. 노출 동기·카메라 보정은 미검증이다.
- 로컬 기록은 종료를 확인한 뒤 NAS에 복사하고 전체 파일 해시를 검증했다. 원본은 유지했다.
  회수본의 `collection-receipt.json`과 두 기록의 `integrity-audit.json`에 근거를 남겼다.
- 실제 저장 영상을 열어 정차한 AC 조종석·전면·좌측 및 중앙 미러와 우측 메뉴를 확인했다.
  우측 외부 미러는 이 화면에서 확인되지 않았다. 이를 임의의 4시점 관측으로 표시하지 않는다.

실행 모드의 영상 저장 경로를 로컬 임시 기록 폴더로 바꿨다. 종료 후에만 NAS 실행 폴더의
`vision/`으로 복사하고 모든 파일 해시를 확인한다. 원본은 삭제하지 않으며 복사 실패는 별도
오류로 남긴다. 영상/교사 주행 관련 검사 8개를 통과했다. 실제 교사 주행은 여전히 미실행이며,
새 SDK 로딩·조향 배율 보정·전진 기어의 트랙 위 시작 상태가 필요하다.

## 조향 요청 보정으로 설정 재로딩 줄이기

현재 LOCK900 설정을 바꾸는 대신, 공개 교사의 절대 조향 요청에 **0.6**을 곱해 vJoy로
전달하는 경로를 추가했다. 교사의 상대 요청 누적과 125개 관측은 그대로 두고 장치 입력만
보정한다. 페달에는 이 계수를 적용하지 않는다. 기본값은 1이므로 반드시
`--steering-request-scale 0.6`을 명시하고 같은 세션의 보정 기록을 전달해야 한다.

실제 `runs/ac-steering-remap-calibration-20261027-t49/`에서 정차한 채
vJoy 요청 0, +0.6, -0.6, 0을 각 8회 기록했다. SDK 조향 중앙값은
0, +269.999969, -269.999969, 0이었다. 따라서 현재 설정에서 공개 교사의 ±1 끝점에
해당하는 SDK 약 ±270을 재현했다. 과거 ±0.1 요청에서도 배율 약450을 측정했다.
샘플 사이의 연속 선형성이나 이동 중 응답은 아직 검증하지 않았다.

이번 32개 SDK wire/native prefix 해시와 native 디코딩을 재검증했다.
최대 속도는 0.02158km/h, 모든 요청의 가속 0·제동 1, foreground 표본 0개였다.
종료 후 실제 센서에서 조향 0·가속 0·제동 1을 확인했다. 장치 요청은 초기·종료 포함 34건이며
모두 조향 보정용이었다. 프로필 파일 변경이나 창 활성화는 하지 않았다.

보정 검사는 같은 세션·프로필·DLL·축 설정과 함께 요청 끝점까지의 측정 범위를 요구한다.
좁은 ±0.1 검사만으로 ±0.6 입력 범위를 검증했다고 취급하지 않는다.
교사 요청 누적값이 장치 보정 계수에 의해 다시 축소되어 다음 단계에 들어가지 않는지도 검사했다.

새 교사 SDK 필드는 아직 실행 중인 앱에 로드되지 않았다. 고정해 검토한 기존 공유메모리 ABI에는
필요한 SlipAngle·LocalVelocity 필드가 없어 그것만으로 전체 교사 관측을 복원하지 않았다.
wheelSlip을 SlipAngle로 대신 넣거나 누락값을 0으로 채우지 않는다. 이 조사 범위는 고정된 ABI이며
다른 확장 SDK 버전 전체에 대한 부재 증명은 아니다.

따라서 현재 조향 문제 때문에 LOCK540 프로필을 로드할 필요는 줄었지만, 새 수집기 로딩과
트랙 위 시작 상태 준비는 남아 있다. 실제 교사·파리 학생의 AC 주행은 아직 미검증이다.
