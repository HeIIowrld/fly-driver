# 다중 시점 비전에서 주행 행동으로: 첫 학습 실험

갱신: 2026-10-27, Asia/Seoul. 목표는 전면·좌우·후방 시각을 파리 회로 안에서 통합하고,
차량 감각과 함께 조향·가속·제동을 결정해 Assetto Corsa 서킷을 완주하는 것이다.

## 이번 구현

`collect_multiview_teacher.py`가 MuJoCo에서 네 시점 영상과 몸 감각을 함께 기록한다.
각 시점은 독립된 노출 ID·시간·유효성·보정 해시를 유지한다. 전면은25Hz, 나머지는12.5Hz다.
영상은 시점별 겹눈 방향으로 표본화하고, RGB·시간 대비·유효성·나이를 회로에 입력한다.
시간 대비는 RGB 변화량이며, 검증된 생물학적 운동 검출기나 광류라고 부르지 않는다.

각 시각 입력 포트의 학습 어댑터는 한 시점의 가까운12개 방향만 읽는다. 시점 간 상호작용은
6,557뉴런·644,512연결의 공유 재귀 회로 안에서 발생한다. 이번에는 시각 어댑터만 학습하고,
연결 행렬·몸 감각 어댑터·운동 출력 경로는 고정한다. 시점의 뉴런 배정과 회로 시간상수는
공학적 가정이며 실제 파리에서 검증된 카메라 대응이 아니다.

교사는 지도·차량 위치를 이용해 정답을 만들지만, 학생의 입력에는 지도·정답 경로·위치·
진행률을 넣지 않는다. 저장된 시퀀스를 여러 번 재사용하고32결정마다 역전파를 끊는다.
이때 신경 상태의 숫자는 계속 유지하며 새 에피소드에서만 초기화한다.

원래 미학습 회로의 조향 출력이 매우 작아 학습 입력의 출력 RMS로 조향 이득을 먼저 맞춘다.
정답 조향은 이 이득 계산에 쓰지 않는다. 초기값·이득 보정 직후·학습 후 오차를 모두 남긴다.

## 실험 범위와 평가

- 수집: 네 출발 조건×128결정, 총512결정. 시뮬레이션 시간20.48초.
- 학습: 3epoch,32결정 단위, 총12회 최적화. 회로 내부는 결정마다10ms씩4회 진행한다.
- 평가: 수집에 쓰지 않은 두 출발 조건, 각각 최대160결정(6.4초).
- 비교: 정상·시각 제거·몸 감각 제거와 별도의 경로 기반 교사 기준값.
- 지표: 진행 거리, 횡방향 RMS 오차, 종료 이유, 조향 RMS. 짧은 구간 생존을 서킷 완주로
  계산하지 않는다. 학습 오차가 줄어도 주행 성공으로 판정하지 않는다.

후속 실험은 같은512결정에 학습률0.0002·8epoch(32회 갱신)을 적용하고, 학습 시퀀스의
조향 RMS 오차가 가장 작은 epoch를 저장한다. 개발 주행 결과로 체크포인트를 선택하지 않는다.
추가 `front_only` 평가는 다중 시점으로 학습한 모델의 미러 입력을 평가 때 끄는 제거 실험이다.
전면만으로 별도 학습한 모델과의 공정한 효율 비교는 아직 아니다.

## 학습 결과

| 조건 | 학습 정답에 대한 조향 RMSE |
|---|---:|
| 원래 초기화 모델, 조향 출력 거의0 | 0.15918 |
| 입력 RMS로 조향 이득 보정 직후 | 0.22601 |
| 첫 실험, 학습률0.001·3epoch 마지막 | 0.17244 |
| 후속 실험, 학습률0.0002·8epoch 중 선택한5epoch | 0.15870 |

RMSE는 무차원 곡률 의도에 대한 값이며 실제 핸들 각도 오차가 아니다. 후속 실험은32회
갱신을 실행했고, 저장 모델은5epoch 종료 시점(20회 갱신)의 가중치다. 이득은약58,078이다.
후속 학습 모델의 조향 RMS는0.00724로 매우 작다. 이득 보정 직후에 비해 손실이 줄었으나,
거의 조향하지 않던 초기값에 대한 개선은약0.3%여서 유용한 주행 학습의 근거로 부족하다.

첫 실험의 정상 주행 횡오차 RMS는 개발A0.3942m·B0.5666m였고, 시각 제거는
A0.1954m·B0.1976m였다. 몸 감각 제거는A0.3942m·B0.5665m로 정상과 거의 같았다.
모든 경우160결정의 시간 제한까지 진행했으며 완주한 경우는0개다. 실패한 시각 해석을
학습 파이프라인의 실행 성공과 혼동하지 않는다.

첫 실행 전체는 `runs/multiview-learning-20261027-t26/`에259파일을 회수해 해시를 대조했다.
후속 체크포인트 SHA-256은
`7eda3c176aae7a91a5044af6dcd49647e29c074d4dfe35b70025d3ad457a79ff`다.

후속 실행도 `runs/multiview-learning-20261027-t26b/`에261파일을 회수해 모두 해시를 대조했다.
두 실행에서 각각 관련28검사·전체 소스 Ruff 검사를 통과했다. 모델·수집 자료·설정·실행 로그·
단계별 결과·소스 스냅샷이 각 실행 폴더 안에 있다. 체크포인트는 후속 폴더의
`runs/training/checkpoint.pt`, 주행 원본은 `runs/evaluation/evaluation.json`이다.

| 후속 개발 주행 조건 | A 횡오차 RMS(m) | B 횡오차 RMS(m) | 두 조건 평균(m) |
|---|---:|---:|---:|
| 경로 기반 교사 기준값 | 0.15225 | 0.15213 | 0.15219 |
| 다중 시점 정상 | 0.17916 | 0.21908 | 0.19912 |
| 시각 제거 | 0.19536 | 0.19757 | 0.19646 |
| 몸 감각 제거 | 0.17918 | 0.21907 | 0.19913 |
| 평가 때 전면만 유지 | 0.23003 | 0.17538 | 0.20270 |

각 조건은6.4초·약8.4m의 짧은 구간이며 모두 시간 제한으로 종료됐다. 표의 평균은 조건별
RMS의 산술평균이다. 정상 시각은 A에서 개선되고 B에서 악화돼 시각 제거보다 평균 오차가
약1.4% 크다. 미러 제거 대비 작은 평균 차이는2조건으로 일반화할 수 없고, 몸 감각의 기여도
입증하지 못했다. **학습·주행 평가 코드는 실행됐지만 유용한 다중 시점 운전은 미검증**이다.

재현할 때는 저장한 소스 스냅샷과 해시가 일치하는 초기 체크포인트·view-map을 사용한다.
출력 폴더는 매번 새 이름으로 지정한다. 예를 들어 후속 설정의 학습은 다음과 같다.

```bash
python -m scripts.train_multiview --config configs/multiview-steering-pilot-refined.json --teacher runs/multiview-learning-20261027-t26b/runs/teacher --output runs/multiview-next-training
python -m scripts.evaluate_multiview_steering --config configs/multiview-steering-pilot-refined.json --checkpoint runs/multiview-next-training/checkpoint.pt --output runs/multiview-next-evaluation
```

이 명령은 의존성·`PYTHONPATH=src`·MuJoCo EGL 렌더링이 구성된 WSL 환경 기준이다.
현재 Windows에서 MuJoCo DLL이 차단되어 이번 실행은 WSL의 CPU 학습·EGL 렌더링으로 진행했다.

설정은 [첫 학습 설정](../configs/multiview-steering-pilot.json)에 있다.
시점별 무효화는 센서 검증 뒤에 적용하는 제거 실험이며 실제 고장 검출 능력과 구별한다.
원본 기록의 해시·출발 시드·소스 스냅샷·학습 체크포인트·실패 결과를 보관한다.

## AC로 이어지는 단계

이번 행동은 **1.5m/s 고정 속도에서의 곡률 의도**다. 시뮬레이터 저수준 제어기가 이를
차량 조작으로 바꾼다. 따라서 AC 조향각·스로틀·브레이크 세 조작을 학습한 결과가 아니다.
가속·제동 정답은 유효하지 않다고 기록하고 학습 손실에서 제외한다. MuJoCo에는 타이어 열
모델이 없으므로 온도 판단을 배웠다는 결론도 내리지 않는다.

다음 AC 데이터에는 동기화된 실제 전면·미러 영상, 각 영상의 보정/반사/지연 정보, 차체·휠
감각, 타이어 온도·네 바퀴 하중, 검증된 교사 조작을 함께 기록해야 한다. 확보한 공개 AC 교사는
재사용할 수 있지만 공개 표본에는 동기 영상이 없어 그대로 시각 학생의 학습 자료가 되지 않는다.

첫 AC 목표는 저속으로 경로를 유지하는 것이고 이후 제동 지점·코너 진입 속도·탈출 가속을
최적화한다. 랩타임 목적함수에는 트랙 이탈·충돌·불안정한 조작을 함께 반영한다. 차량 셋업과
타이어 상태는 에피소드별로 바꾸고 미사용 조건에서 검증한다. 최종 효율 비교에는 같은 영상과
학습 예산의 일반 재귀 모델·연결 재배선 대조군·전면만 쓰는 모델이 필요하다. 현재는 겹눈 회로가
일반 모델보다 효율적이라는 결과가 없다.

## 다음 실험의 통과 조건

현재 평가 출발점은 개발·조정 조건이다. 이후 최종 성능을 낼 때는 새로운 출발 위치와 코스를
따로 고정해야 한다. 짧은160결정 시험에 이어, 적어도 한 곡선을 온전히 지나는 긴 구간에서
정상 모델이 시각 제거 모델보다 경로 오차·이탈률을 줄이는지 먼저 확인한다. 단순 직진이
유리한 짧은 구간을 통과했다는 이유로 다음 단계의 제동·랩타임 최적화를 승인하지 않는다.

시각의 이득이 확인되지 않으면 학습 데이터를 더 다양하게 모으고, 시점별 국소 명암·방향·시간
특징의 정규화와 입력 포트 대응을 조정한다. 큰 조향 이득으로 작은 회로 신호를 증폭하는 현재
조건도 다시 점검한다. 후방은 유효한 겹눈 방향이59개로 전면538개보다 적으며, 네 시점의
입력 포트를 거의 동일 수로 배정한 것이 적절한지도 비교해야 한다.

개발 조건을 바꿔 개선한 결과는 개발 성능으로 기록한다. 같은 입력·같은 학습 예산의 일반
재귀 모델보다 나은지 확인하기 전에는 겹눈이나 커넥톰 구조의 효율성 우위를 주장하지 않는다.
