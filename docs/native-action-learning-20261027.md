# 실제 AC 조향·가속·제동 학습 연결 점검

갱신: 2026-10-27, Asia/Seoul. 목표는 세 조작과 몸 감각을 함께 사용하는 실제 AC 비전 주행이다.
이번 결과는 학습 경로 수정과 고정 체크포인트의 감도 측정이며 실제 AC 운전 성공이 아니다.

## 수정한 문제

기존 `train_multiview.py`는 시각 어댑터만 학습하고 조향 RMSE로만 모델을 선택했다.
고정 속도 조향 과제에는 맞지만, native AC의 세 조작 정답을 넣을 경우 페달 오차가 커진 모델을
조향이 좋아졌다는 이유로 선택할 수 있었다. 또 고정된 몸 감각 어댑터와 pedal gain을 그대로
두면 처음 만드는 온도·하중·가감속 정책을 충분히 학습할 수 없다.

- `trainable_groups`로 `visual`, `organs`, `readout`을 명시적으로 선택한다.
  그 외의 모델 파라미터는 고정하며 측정 회로 연결은 학습 대상으로 풀지 않는다.
  proxy 설정의 기본값은 기존과 같은 `visual`이다. native AC 설정은 선택을 생략할 수 없다.
- 체크포인트는 정답이 있는 각 조작의 MSE 평균으로 선택한다. 조향만 정답이 있는 기존
  proxy에서는 조향 RMSE 선택과 같은 순서를 유지한다. 정답 없는 페달을0점으로 넣지 않는다.
- 선택한 파라미터 전체를 optimizer와 gradient clipping에 사용하고, 이름·개수·선택 기준을
  실행 결과와 체크포인트에 저장한다. 교사/경로 truth는 actor에 추가하지 않는다.

확보한 AC 공개 교사의 수치 재현은 이미 완료했지만 동기 네 시점 영상이 없다.
현재 정차·메뉴 영상에 교사 주행의 조작을 임의로 붙여 학습하지 않았다.

## 현재 모델의 실제 감도

`runs/native-action-reachability-20261027-t34/`에서 체크포인트
`14c8b79ac124ddfe9b704480aae8c6501e8e70d4315437bd0cfe707da7235f87`를 읽어,
봉인된 MuJoCo 감각 에피소드의 처음64결정·256신경 tick을 재생했다. 상태는 중간에 초기화하지
않았다. 각 조작 평균의 파라미터 미분을 계산했으며 optimizer 갱신과 실제 게임 전송은0건이다.

| 조작 | 시각 어댑터 미분 최대 절댓값 | 몸 감각 어댑터 | readout |
|---|---:|---:|---:|
| 조향 | 3.527 | 16.451 | 2.70×10⁻⁷ |
| 가속 | 6.81×10⁻⁷ | 3.44×10⁻⁶ | 3.09×10⁻⁸ |
| 제동 | 5.53×10⁻⁷ | 6.75×10⁻⁵ | 1.13×10⁻⁸ |

이 구간의 가속 최대는6.65×10⁻⁸, 제동 최대는3.06×10⁻⁸이었다.
미분 경로는 있지만 출력과 감도가 매우 작다. 미분 크기는 파라미터 단위와 현재 이득에
의존하므로 신경 경로의 생물학적 영향력이나 학습 성공률 비교로 해석하지 않는다.
온도/하중이 빠진 MuJoCo 관측에서 얻은 값으로 실제 AC 감각 반응을 검증한 것도 아니다.

두 pedal positive gain은1이며, 출력 뉴런을 최대 활동1로 가정해도 각 페달의 독립 상한은
`1-exp(-1)=0.63212`다. 가속 상한에는 제동0 조건도 필요하다. 따라서 초기 gain을 고정한 채
최대 페달 요청을 증류할 수는 없다. gain을 학습 가능하게 하는 것만으로 작은 초기 미분 문제가
해결됐다고 주장하지 않는다.

## 다음 실제 학습 조건

1. 보정된 실제 AC 감각/조작 시퀀스에서 출력 활동과 감도를 다시 측정한다.
2. 교사 정답을 입력하지 않는 gain conditioning과 관측 단위/출력 스케일을 검토한다.
   회로 연결량을 임의로 생리학적 전도도로 해석하거나 내부/운동 뉴런에 직접 우회 입력하지 않는다.
3. 교사의 상대 조작→절대 요청, 실제 적용 축·반전·단위를 검증한다. 현재 brake가 throttle을
   억제하는 codec이 교사 페달 동시 요청을 표현할 수 있는지도 원본 요청과 대조한다.
4. 몸 감각·시각·readout의 허용된 학습 그룹을 고정하고 세 조작 오차와 실제 구간 주행을
   각각 검증한다. 고정 속도 MuJoCo 조향 완료를 native AC의 가감속 성공으로 취급하지 않는다.

관련 학습 검사7개와 Ruff를 통과했다. 실제 AC 동기 학습 데이터·페달 학습·제어 적용·서킷
완주는 아직 남아 있다. 기존 학습 체크포인트는 변경하지 않았다.

## 교사 페달 영역과 출력 스케일 보정

이후 고정한 [원본 car_control.py](https://github.com/dasGringuen/assetto_corsa_gym/blob/ef0fa502bdd257fc2affad9361c02b3dbdfe1632/assetto_corsa_gym/AssettoCorsaPlugin/plugins/sensors_par/car_control.py)를
읽었다. 각 페달 요청은 독립적으로 `(request+1)/2`로 정규화한다. 외부 모듈이나 DLL은
실행하지 않았으며 `assets/external/ac-control-codec-20261027/`에 원본·MIT license와
Git blob/SHA-256을 보존했다. 자체 변환 함수는 상대 delta 뒤의 절대 요청에만 적용한다.
원시 delta에 바로 적용하거나 요청값을 실제 적용 피드백으로 취급하지 않는다.

검증된 공개 교사 재생231요청을 변환한 `runs/ac-pedal-codec-audit-20261027-t35b/` 결과:

- 가속/제동 각각의 요청 범위는0~1이고, 둘의 합 최댓값은1.91574였다.
- 94요청이 기존 결합 출력의 제약 `throttle+brake<=1` 밖에 있었다.
- 이 제약만으로도 두 페달을 합친 RMSE의 수학적 하한은0.12837이다. 이는 실제 학습 오차가
  아니며, 각 요청을 두 페달의 합이1인 영역에 가장 가깝게 투영하는 이상적 한계다.
- gain1의 개별 상한0.63212를 넘는 요청은 가속84개·제동60개였다.

따라서 `pedal_mode='independent'`를 선택할 수 있게 했다. 기존 모드와 체크포인트 기본 동작은
유지한다. 새 모드는 출력 뉴런의 전진/정지 활동에서 각각 독립적인 페달을 만들고, 제동 때문에
가속을 자동으로 줄이지 않는다. sensory→motor 우회로·출력 bias·새 회로 연결은 추가하지 않았다.
native AC 학습 설정은 모드를 명시해야 하며 constructor와 함께 저장한다.

또한 독립 모드의 두 gain을 **학습 감각을 재생한 출력 활동만으로** 보정하는 선택 경로를
추가했다. 신경 상태를 이어 재생하고 결정의 마지막 tick·활성 에피소드만 사용한다.
목표 RMS·최대 gain을 명시하며, 한쪽이 도달 불가능하면 둘 다 변경하지 않는다.
교사 조작 정답을 사용하지 않고 scalar gain만 이분 탐색한다.

`runs/pedal-conditioning-20261027-t35/`의 실제6,557뉴런 체크포인트·동일64결정에서는
가속 gain 약3.70×10⁶·제동 gain 약8.43×10⁶으로 RMS 각각0.15를 얻었다.
조향 출력은 bit 단위로 같았고, 회로·감각 어댑터·원본 체크포인트는 변경하지 않았다.
이득이 큰 이유는 현재 출력 활동이 작기 때문이며 생리학적 이득이나 안정성을 뜻하지 않는다.
새 감각·누락·노이즈에 대한 포화/민감도는 실제 native 데이터에서 검증해야 한다.
보정된 native 주행 체크포인트는 만들지 않았다.

이 보정은 native 학습기에서 실제 AC action profile을 명시할 때만 선택할 수 있다.
위 MuJoCo 재생은 별도 진단 경로이며 가속/제동 정답이나 주행 평가를 만들지 않는다.
후속 검사26개 통과·SciPy 부재 검사1개 생략·Ruff 통과다. CSR 실험적 지원 경고는 유지했다.

## 세 조작 학습 전체 경로의 합성 통합 검사

`tests/test_native_action_training_pipeline.py`에서 합성10노드 회로·4시점 입력8결정으로
실제 학습 CLI를 실행했다. normalized AC action codec은 사용하지만 데이터는 실제 AC가 아니다.
가속/제동 독립 모드와 출력 보정, 시각·기관·readout 학습을 켜2epoch·4회 optimizer 갱신을
끝냈다. 세 조작 각각8개 정답을 처리했고 설정/constructor/선택 기준이 저장됐다.
원본 체크포인트·측정 연결 역할의 고정 행렬은 바뀌지 않음을 비교했다.
검사1개와 Ruff를 통과했다. 실제 AC 학습 성공·생물학적 회로 성능의 근거로 사용하지 않는다.

사용자의 재개 승인 뒤 첫 게임 클릭에서 Computer Use가 다시 물리 Esc 중단을 보고했다.
조작을 중단하고 `runs/ac-axis-preflight-after-second-stop-20261027-t37/`에서 읽기 전용으로
재확인한 결과 엔진 창은 남아 있었고 현재 controls.ini는 여전히 vJoy 후보와 달랐다.
장치 획득·축 전송0건이며 재개 여부의 새 질문을 제시했다.
