## 거리 예산 오류와 수정

기존 `course_480m` / `game_valid_480m`은 시작점과 현재 위치의 평면 직선 변위480m를 목표로 했다. t567은 해시로 고정된 참조 경로에서 이 지점까지 **약1003.67m의 경로**가 필요하고, 실제480m의 참조 경로 진행 후 직선 변위는약259.18m임을 확인했다. 이는 참조 경로 계산이며 실제 주행거리 측정은 아니다. 30km/h로1003.67m를 가는 데 최소120.44초가 필요하므로,96초 제어/102.5초 카메라 예산과 맞지 않았다. 설정 오류다. 세 실제 실패는 그보다 먼저 경계를 위반했으며 실패로 유지한다.

두 직선변위480m 프로필은 코드에 과거 재생용으로 남기고 새 live 실행 허용 목록에서 제거했다. 새 `game_valid_route_480m`은 **(LapCount+NormalizedSplinePosition−원래 시작값)×고정 SDK 트랙 길이**로 코스 진행480m를 판단한다. 지도는 actor에 제공하지 않는다. 2400결정·카메라3250그룹/102.5초/2GiB·속도40km/h·입력150ms·추론80ms·바퀴 이탈 최대2개·LapInvalidated0은 명시적으로 유지한다. 좌표 변위640m는 별도 비정상 이동 제한이다.

`RouteProgress`는 유한한 카운터/진행률/길이/시간, 고정 길이,250ms 이하의 연속 피드백, 카운터 초기화/역행과 부자연스러운 wrap·순간 이동을 검사한다. SDK 진행량과 누적 평면 이동도 대조한다. 소스 누락을 추정으로 메우지 않는다. 허용 오차는 투영/센서 오차를 고려한 공학적 검사이며 정확한 주행계 증명은 아니다. 엔진·세션 식별과 신경 상태 연속성은 별도로 검증해야 한다. 임의 위치에서 랩 카운터가 한 번 증가한 것만으로 완주를 인정하지 않는다.

새 실행은 원래 센서 쌍에 연결된 `route_origin`을 기록하고, 오프라인 감사기는 원본 피드백에서 코스 목표를 다시 계산한다. 성공을 주장한 실행의 거리/목표가 재현되지 않으면 거부한다. 새 프로필의 실제 주행 성공은 아직 없다. 실제 기존 세 기록을 첫 제어 피드백부터 검토한 연속성 검사는 모두 통과했고, 코스 진행과 누적 평면 경로는 각각356.41/356.83m,283.19/283.47m,337.42/337.23m였다. 이 검사는 실패를 통과로 재분류하지 않는다.

관련 검사75개와 Ruff가 통과했다. 합성 곡선에서 직선 변위가400m 미만이어도 코스 진행480m를 올바르게 판정하고, 카운터 초기화·타임스탬프 공백·위치가 멈춘 상태의 가짜 진행 누적·불완전한 lap wrap을 검토했다. 실제 전체 랩의 wrap은 아직 검증하지 않았다.
