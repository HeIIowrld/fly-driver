# 이어지는 트랙 구간 수집과 GC 지연

기록일: 2026-10-28 KST. 파리 모델의 전체 서킷 주행은 미완료다. 이 기록의 실제 운전자는 기하 교사이며 학생 성능으로 표시하지 않는다.

## 확인한 런타임 중단

t331에서 API 재시작·정차 보정을 한 뒤 t332에 500회 교사 주행을 요청했다. 요청 424개, feedback 423개 시점에서 40ms 처리 제한을 초과해 중단됐다. index 423의 처리 시간은 41.0523ms이며, image 단계에 38.2784ms가 걸렸다.

동일 프로세스의 GC trace에서 generation 2 수거가 156079.4362251–156079.4731072 QPC초에 실행됐다. 이는 약 36.8821ms이며 해당 image 단계 안에 들어간다. 이 경우의 지연에는 전체 순환 참조 수거가 실제로 기여했다. 과거 다른 중단까지 같은 원인이었다고 확대 해석하지 않는다. 원시 영상·센서·명령을 보존했고 이 실패 런은 학습용으로 봉인하지 않았다.

## 변경

- 제한된 제어 루프에 들어가기 전에 필요한 전체 수거를 실행한다. 최대 500회인 제어 범위에서는 자동 순환 참조 수거를 끄고, 런타임의 finally가 장치를 해제한 뒤 이전 GC 상태를 복구한다. 참조 카운팅은 계속 동작하며 명시적 `gc.collect()` 호출까지 차단하는 기능은 아니다. 이 변경이 40ms 마감을 보장하지는 않는다.
- 교사 수집기에도 명시적인 retina 설정과 `--require-background`를 추가했다. 창을 전면으로 바꾸지 않고, 전면 감지 시 중단한다.
- `prepare_ac_episode --preserve-position`은 출발점 재설정 없이 정차 상태·첫 기어·같은 엔진의 조향 보정을 확인한다. 이미 주행 세션 안이면 start 명령을 보내지 않는다. t333에서 중복 start가 false를 반환한 사실을 보존했고, 이를 수정한 t334가 위치 보존 준비를 마쳤다. API epoch는 12를 유지했고 restart 요청은 없었다.
- 카메라 보관은 기존의 반복 NAS 해시 읽기와 metadata 복사를 줄이고, 최대 4개 worker가 파일 복사 후 해시를 한 번씩 검증하도록 바꿨다. 해시 검사·원본 보존·살아 있는 consumer 거부·파일명 충돌 거부는 유지했다. 진행 중인 기존 보관 작업에는 새 구현을 주입하지 않는다. 실제 NAS 속도 개선치는 아직 측정하지 않았다.

## 이어서 수집한 구간

t335의 로컬 이벤트에는 연속 요청 500개와 feedback 500개, 장치 해제 close 영수증 1개가 있다. 요청 구간의 deadline overrun 0회, foreground 이벤트 0회, 첫 요청부터 close까지 generation 2 수거 0회를 확인했다. 최고 속도 27.673km/h, 마지막 gap 0.25233m다.

교사 전용 경로 arc는 5043.134m에서 5173.031m까지 진행했다. 앞선 t332의 마지막 요청 arc는 5039.510m였다. 사이의 정지 이동과 정차 보정을 거쳐 다음 구간으로 이어졌으며, 같은 출발점의 자료를 다시 수집한 것이 아니다. 위치와 arc는 교사·진단용이고 actor 입력에 추가하지 않는다. 이 구간에는 제동 >0.05인 실행 요청이 없으므로 새로운 적극 제동 사례라고 부르지 않는다.

로컬 이벤트 SHA256: `87c25ed1a479564acd214b96f0e214fedd43809a9d51d097cfbf95975373c531`. 수치와 증거 범위는 `runs/ac-extended-yaw-teacher-continuation-20261028-t335/runtime-summary.json`에 기록했다.

현재 영상 파일의 NAS 보관이 진행 중이다. 따라서 위 500개는 아직 학습에 사용할 수 있는 것으로 판정하지 않았고, 기존 738개와 합치지 않았다. 기존 프로세스를 확인하며 기다린 뒤, 최종 보관 해시·독립 정지/vJoy 해제·원시 영상/몸 감각 재구성·교사 명령 재생을 모두 확인해야 봉인할 수 있다. 수집을 다시 시작하지 않는다.
