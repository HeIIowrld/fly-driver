사용자 지시에 따라 과거 중복 사본도 유지하지 않고 삭제했다. 중복 검토 대상 281개 파일을 전부 새로 SHA256 검증한 뒤, 고유 내용 67종은 원본 한 벌씩 남기고 **사본 214개, 10,342,437,708 bytes(약 10.34GB)**를 NAS와 PC OneDrive 동기화 폴더 양쪽에서 삭제했다. 214개는 같은 논리 파일의 양쪽 사본이므로 확보량을 두 배로 합산하지 않는다.

참조표를 반영한 파일 용량 감소분은 **10,342,381,030 bytes(약 10.34GB)**다. 코드·문서·작업 영수증의 작은 추가 용량은 별도다. 이 수치는 NAS·PC 동기화 폴더의 파일 목록 기준이며 OneDrive 서버 사용량 화면이나 NAS 휴지통·스냅샷의 물리적 회수까지 확인한 수치가 아니다. 휴지통은 비우지 않았다.

## 보존한 것과 바꾼 것

고유 NPZ 내용 67종과 그 원본 경로, 기존 dataset.json, 실행 manifest.json, result.json 등 실행 기록을 보존했다. 참조 대상 원본 67개는 삭제 후에도 내용 SHA256을 전부 다시 확인했다. 점검한 기존 manifest·결과 기록의 해시 변경은 0건이다. 과거 소스 스냅샷은 수정하지 않았다.

각 데이터셋의 `.episode-links.json`에 삭제한 논리 파일명, 보존 원본 상대 경로, 내용 SHA256·크기와 소유 dataset.json의 해시를 기록했다. 기존 dataset.json의 파일명이나 바이트를 재작성하지 않으므로 과거 기록에 저장된 manifest 해시를 유지한다. 데이터 내용이 같은 것을 공유할 뿐, 학습 에피소드 수·순서·중복 표본 가중치·라벨·시간·분할을 제거하거나 변경하지 않는다.

수정한 공통 로더와 직접 NumPy/해시 읽기는 사라진 옛 경로를 참조표의 원본으로 해석한다. 소유 manifest가 바뀌거나 원본 내용이 다르거나 경로가 프로젝트 runs 트리를 벗어나면 거절한다. 기존 파일과 파일 객체의 읽기 동작은 유지한다. 참조표는 저장 경로 보존 자료이므로 지우지 않는다. 원본 67개는 참조가 남아 있는 동안 보존한다.

## 과거 소스를 수정 없이 실행할 때

현재 프로젝트 코드는 기존 데이터셋 경로를 그대로 사용한다. 참조표를 모르는 과거 소스 스냅샷의 원래 파일 열기를 재현하려면 다음 도구를 사용한다.

```powershell
python scripts/with_materialized_episodes.py --dataset runs/해당_과거_데이터셋 -- python 과거_스크립트.py 원래_인자
```

필요한 데이터셋마다 `--dataset`을 반복할 수 있다. 도구는 원래 경로에 같은 바이트를 일시 복원하고 자식 명령 종료 후 그 임시 사본만 제거한다. 임시 사본 내용이 바뀌면 삭제하지 않고 오류로 남긴다. 원본 소스·원본 manifest의 바이트는 바꾸지 않는다. `--restore-only`는 수동 재현이 필요할 때 명시적으로 실물 사본을 다시 만드는 옵션이며, 평상시 중복 정리 상태에서는 사용하지 않는다. 직접 파일을 여는 모든 과거 소스에 운영체제 차원의 가상 파일이 제공되는 것은 아니므로, 과거 소스를 그대로 쓸 때는 이 도구를 거친다.
