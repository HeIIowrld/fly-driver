# native 바퀴 회전수를 몸 감각에 추가

2026-10-28. 기존 학생이 정차에서도 제동을 유지하는 실패를 보여, 기록되어 있지만 actor에
없었던 wheelAngularSpeed를 고유감각 입력으로 추가했다. 월드 속도·위치나 지도 값을
actor에 넣은 변경은 아니다. 입력 변경만으로 출발이나 속도 조절이 해결됐다고 하지 않는다.

## 신호와 입력 슬롯

원본 native physics prefix에 이미 있는 네 바퀴 신호를 사용한다. FL/RL과 FR/RR의 절댓값
평균을 좌·우 회전량으로 선언한다. 독립적인 SI 단위 검증 전까지 native 게임 값이며 실제
파리 수용기의 물리 튜닝이나 다리/바퀴 대응을 측정했다고 하지 않는다. 전진 기어 시험에서
사용할 공학적 크기 표현으로, 회전 방향은 이 표현에 포함하지 않는다.

기존 미보정 조향 때문에 유효성0이던 기관0–17 슬롯을 재사용한다. 좌우 각각9개씩으로,
처음7개는 `tanh(max(magnitude-center,0)/15)`이며 중심은0/10/20/30/40/60/80이다.
뒤2개는 실제 native 수신 간격에서 계산한 증가·감소율을50으로 나눈 tanh 값이다.
정차 회전량0은 값0·수준 유효성1이고, 센서 결측은 값0·유효성0이다. 최초 표본이나
stale 이후 재개 표본은 변화율을 유효하게 만들지 않는다.

native 네 값 중 하나가 비정상이면 해당 좌/우 쌍을 결측으로 표시한다. 같은 수신 시각에
개별 바퀴 값이 바뀌면, 평균이 같더라도 재사용 표본 변조로 거부한다. 신호 부재·나이 초과·
시간 역행은 명시적으로 처리한다. 바퀴 입력을 선언한 실제 제어에서는 수준 신호를 쓸 수
없으면 새 동작 전송 전에 중단한다. 이전3종 기관 모델은 종전 calibration과 동작을 유지한다.

이 슬롯을 읽는 measured chordotonal 입력 그룹은 기존0–53 특징을 읽는다. 입력 수132와
그래프6557노드·644512연결·포트 ID는 바꾸지 않았다. Gate-only 유효성을 사용해 유효성
자체를 동작 구동 상수로 추가하지 않는다. 마지막6개 haltere 슬롯과 실제 roadwheel angle
보정은 여전히 지원하지 않는다.

설정은 `configs/ac-native-wheel-retina.json`에 별도로 저장했다. 기존 파일을 바꿔 과거
체크포인트를 다른 의미로 로딩하지 않는다. body calibration digest도 새 설정에 맞춰 달라진다.

## 기존 실측 관측의 재처리

`scripts/augment_ac_wheel_organs.py`는 원본 source 계보·NPZ·SDK wire/native prefix 해시를
확인하고 prefix bytes에서 바퀴 값을 직접 해독한다. 원래 학습에 선택한 관측의 결정 시각과
수신 시각을 그대로 사용한다. 기존18–131 기관이 이전과 정확히 재현되는지 먼저 검사한다.
영상 배열·정답·action validity·관측 시각은 그대로 복사하고0–17 기관 값/마스크만 바꾼다.
이미 유효한 다른 기관을 덮어쓰지 않도록 종전 슬롯이0·무효였는지도 확인한다.

| 새 자료 | 실제 관측 수 |
|---|---:|
| t113, 원래 출발 | 50 |
| t114, 파라볼리카 | 500 |
| t115, 저속 복귀 | 500 |
| t116, 실제 학생 정차 상태 | 150 |
| t117, 개발 구간 | 75 |

학습1200개는 t118로 복사 합집합을 만들었고 개발75개는 제외했다. 첫 기관 유효 특징은
84→98개, 다음 표본은108→126개다. 미러3개는 계속 유효성0이며 새 카메라라고 부르지 않는다.
강한 제동 정답은 이전 고정20km/h 교사가 계산한 미실행 라벨 그대로다. 새 브레이크
주행을 측정한 데이터로 바꾸지 않는다. 원본과 과거 모델 파일은 모두 보존했다.

t119 초기화는 더 나았던 고정 과제 t100에서 시작해 새 calibration 계약만 등록했다.
전체 모델 텐서·그래프·원본 파일 불변을 확인했고 초기화 체크포인트 SHA-256은
`274c1fb7839326408f1136ae40367cdfb19a2e899cfe726a8295065a1ad8e329`다.
새 바퀴 입력으로 학습되거나 실제 운전에 검증된 모델이라고 하지 않는다.

`configs/ac-native-wheel-finetune.json`은 t119에서6epoch, visual/organs/readout만 학습하며
회로는 고정한다. 새로운 입력 활동으로 조향 RMS0.15·각 페달 RMS0.2에 배율을 맞추며 교사
정답은 이 배율 보정에 쓰지 않는다. 실행은 t120, 결과 검사는 별도 실행 파일을 따른다.
입력·결측·시각·값 불변성과 기존 제어 프로필 관련20개 검사를 통과했다.

## 학습 결과와 출발 실패 원인

t120은 192회 업데이트 후 6epoch를 선택했다. 개발75관측 RMSE는 조향/가속/제동 순서로
0.18119/0.11502/0.10074였다. 하지만 실제 t123 시험은150개 요청을 보냈어도 이동량이
약0.00117m에 그쳐 출발하지 못했다. 바퀴 입력 추가만으로 운전 문제가 해결되지는 않았다.

t125는 기록된 정차 관측에서64결정 동안 상태를 준비한 뒤16결정의 가속 손실을
역전파했다. 정답은0.25인데 예측은 약1e-28~2e-23이었고, visual/organs 입력 가중치의
가속 기울기가 모두0이었다. 꺼진 rectified-tanh 뉴런이 가속 학습을 차단하는 사례다.

학습에서만 음수 영역에0.05의 보조 기울기를 주는 `leaky_surrogate` 옵션을 추가했다.
순전파는 기존 `relu(tanh(x))`와 정확히 같고, 추론 활동·회로 연결·재귀 가중치는 바꾸지
않는다. t126의 같은 입력·가중치 비교에서 모든 순전파 출력은 일치했고 가속 입력 기울기의
최댓값은 visual0→0.32390, organs0→0.67943으로 바뀌었다. 이것은 공학적 학습 규칙이며
파리의 실제 학습 규칙을 입증한 결과는 아니다. 관련 회로/다중시점/학습23개 검사를 통과했다.

t127은 t120에서 추가128회 업데이트하고4epoch를 선택했다. 체크포인트 SHA-256은
`a11e89dcf89409dffe5f29ebfeeac412556e75af6c91bd58593537171af7b8c9`다.
학습 RMSE는0.07718/0.10854/0.08558→0.06726/0.12053/0.07366으로 바뀌었다.
t128 개발 RMSE는0.11913/0.13307/0.09544로 조향·제동은 좋아졌지만 가속은 나빠졌다.
개발자료는 설계에 사용했으므로 독립 최종시험이라고 부르지 않는다. 바퀴 결측 ablation에서
제동 RMSE는0.32841로 악화됐다. 영상 결측도 조향 RMSE를0.34326으로 악화시켰다.

## 실제 백그라운드 출발 검증

t129 읽기 전용 검사에서25번 추론과18개 서로 다른 영상이 수신됐다. 이어 t130은 교사
동작이나 최소 가속 보정을 섞지 않고15개 학생 요청으로 출발했다. 첫 시험의0.5m 제한에서
중단했으며, 정지 과정까지 기록된 최대 변위는0.61699m, 최대 속도4.99001km/h였다.
t131은 원본 영상·기관 입력으로 세 출력의 오차0 재현을 확인했다. 전면 활성화·UI 조작은0,
최종 정지 확인과 vJoy 해제를 마쳤다. SDK 다음 표본 응답의 기존 허용오차 판정은 여전히
실패이며, 출력 재현 성공과 구별한다. 짧은 출발을 서킷 주행 성공으로 해석하지 않는다.

t132는 같은 모델을 기존 tracking_validation 프로필로150결정 실행했다. 실제 이동량은
1.20470m로15m 목표에 미달했으며 종료 사유는 `decision_budget_exhausted`였다.
첫 가속0.10323은 마지막에3.31e-38로 떨어졌고 마지막 제동은0.04432였다. 따라서
출발 개선과 지속 주행 실패가 함께 관측됐다. 정지·해제 및 아카이브 해시 검증은 완료했다.
t133 별도 재현 감사 결과를 실제 제어 기록과 함께 보존한다.

## 다음 검증 계획

1. t132의 연속 정차·출발·재정차 구간을 개발 진단에 사용하고, 현재1200관측에서 해당
   구간별 가속 오차와 회로 활동을 측정한다. 전체 평균 오차만으로 출발 능력을 판정하지 않는다.
2. 재귀 상태를 유지한 긴 구간의 가속 손실을 점검한다. 정차/가속/감속 구간별 지표를
   명시하고, 학습 가중치나 모델 선택 기준을 바꾸면 기존 전체 RMSE도 함께 보고한다.
3. 새 후보는 같은 입력의 오프라인 재현과 백그라운드 읽기 전용 검사를 거친 뒤 기존
   거리·속도 제한에서 비교한다. 출력 하한이나 교사 동작을 학생 출력에 몰래 섞지 않는다.
4. 지속 주행을 확보한 다음 코너·제동·타이어 온도·하중 적응과 미러 영상 보정을 확장한다.
   미러 영상3개, 겹눈 물리 보정, 셋업 적응, 완주·랩타임 최적화는 아직 미검증이다.
