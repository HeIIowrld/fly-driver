# 세션 영수증 복구와 실제 120m 파리 학생 주행

기록일: 2026-10-28 KST. 이전 목표 턴은 GPU cached CSR 전환·동시 학습·개발 평가를 완료한 진전이었다. 이번 턴은 실제 주행을 막던 API 오류를 복구하고 동일 파리 모델의 실제 구간을 120m까지 확장했다. 전체 서킷·독립 다중시각 효과·하중/온도/셋업 최적화는 아직 미완료다.

## 실제 오류와 복구

기존 t394 pause는 접수 영수증만 남았고 `Cannot commit camera metadata` 오류가 발생했다. 실제 paused 상태는 확인했지만 API 반환값은 복원하지 않았으며 같은 명령을 재전송하지 않았다.

설치된 CSP SDK `extension/internal/lua-sdk/ac_apps/lib.lua`의 `io.save(..., true)` 설명은 임시 파일 저장 후 대상 파일로 이동하는 안전 저장 방식임을 확인해 준다. 기존 방식은 클라이언트가 읽는 접수 파일을 완료 결과로 덮어썼다. 열린 파일과 안전 저장 교체가 충돌할 수 있으며, 경로를 포함한 OS 오류를 원래 Lua 로그가 남기지 않아 당시 실패의 정확한 파일은 확정하지 않는다. 상태 heartbeat 저장 실패도 같은 포괄 오류 메시지를 사용했다.

새 v2는 `<id>.json` 접수 파일을 변경하지 않고 `<id>.terminal.json`에 결과를 저장한다. 알려진 API 반환 후 metadata 저장만 실패하면 producer가 결과 저장만 재시도한다. 게임 명령은 다시 호출하지 않는다. 진짜 API 예외/결과 불명은 접수 기록으로 재실행을 막는다. 저장 대기 중에는 새 변경 명령도 차단한다.

heartbeat의 일시적인 저장 실패는 횟수를 기록하고 다음 갱신에서 회복한다. 클라이언트의 2초 최신성·엔진 식별·native 정차/brake hold·카메라 종료·vJoy 해제 조건은 유지한다. 오류나 미완료 영수증이 있으면 변경 명령을 거부한다. 이전 단일 파일의 완료 영수증도 읽을 수 있다.

## 창 조작 없는 배포와 검증

설치된 CSP AppShelf 코드의 앱 갱신 처리에서 live reload 지원을 확인했다. t420에서 최신 paused/정차 센서·FREE vJoy·종료된 카메라를 확인하고, 기존 배포 파일과 새 파일을 해시와 함께 보존한 후 앱 Lua 파일을 교체했다. 실제 generation이 `5836050ULL:0.0005749`에서 `5836050ULL:0.0006335`로 바뀌고 v2 protocol heartbeat가 나타났다. 게임 재실행이나 키/마우스 조작은 없었다.

t423/t428/t433의 resume→restart→start 명령 총 9개에서 API 반환 true·목표 상태·독립 완료 영수증을 확인했다. 각 접수 파일은 여전히 accepted이고, 완료 파일은 별도로 존재한다. t427/t431/t436 pause도 정상 완료했다. 이전 t394의 반환값이 알려졌다고 주장하지 않는다.

실제 LuaJIT로 배포 Lua 소스를 실행해 완료 저장 2회 실패, heartbeat 실패, API 예외, 앱 재로딩, 비정차 거부를 주입했다. 완료 저장이 재시도돼도 API 호출 횟수는 1회였다. client/continuation/pilot/age-wait까지 관련 36개 테스트와 Ruff를 통과했다. 테스트용 선택 의존성 `lupa==2.8`을 추가했고 게임 runtime에는 필요하지 않다. LuaJIT의 처리된 Windows SEH 오류가 Python fatal signal처럼 출력되지 않도록 해당 테스트 범위에서만 faulthandler를 일시 중지·복원한다.

## 실제 파리 모델 주행

모델은 t414(`02a3486d9d60be227d0b23afc7482500aab45e9afd0fa4531108a62500e8e269`)이며 four-camera/yaw retina를 사용했다. GPU에서 학습한 sensory adapter/readout을 CPU cached CSR 경로에 불러왔다. 제어는 실제 픽셀·몸 감각→고정 파리 그래프→지정 출력→차량 codec 경로다. teacher action과 pose/지도는 actor에 들어가지 않았다. 같은 출발 세션을 API로 재설정해 30m, 60m, 120m를 각각 시험했다.

| 목표 | 실제 시작점 대비 변위 | 제어 결정 | 최고 속도 | 최대 기준선 이탈 | 최소 측면 여유 | 최대 모델 제동 |
|---|---:|---:|---:|---:|---:|---:|
| 30m | 30.205m | 176 | 24.270km/h | 2.593m | 1.284m | 3.667% |
| 60m | 60.185m | 286 | 26.185km/h | 2.594m | 1.101m | 5.534% |
| 120m | 120.163m | 528 | 25.275km/h | 2.594m | 1.191m | 5.130% |

세 실행 모두 목표 도달·종료 후 정차·vJoy 해제를 확인했다. 각 실행의 모든 픽셀/몸 감각을 원본 archive에서 다시 처리해 모델 요청을 정확히 재생했다(최대 차이 0). 실제 동작이 40ms마다 이어지는 동안 수치 신경 상태는 유지했고, 명시적인 새 실행에서만 초기화했다.

60m에서는 8개 요청이 brake>0.05였고 최대 요청 0.05534, native brake 최대 0.05535를 관측했다. 120m에서도 3개 요청이 0.05를 넘었고 native brake 최대 0.05080이 관측됐다. 두 독립 최대값의 유사성만으로 제동 전달의 시간 지연·인과 효과·제동 제어 일반화를 입증하지 않는다. SDK/네이티브 feedback 비동기 오차와 모델 요청 재생 검증은 구분한다.

120m profile은 최대 700개 결정·계획 변위 120m·hard 변위 160m로 한정했다. 속도 40km/h, 기준선 이탈 3m, 측면 여유 1m, 모델/영상 지연 제한은 기존과 같다. 카메라 그룹 상한은 ceil(700×0.04/0.03)+50=984로 기존 1000/60초 cap 안이다. 실제 691개 그룹/약 309MB를 기록했다. 처음부터 끝까지 교사 제어와 GUI 조작은 0회다.

이는 곡선 경로 arc length나 공식 유효 랩의 측정이 아니라 시작점과 끝점의 변위다. 전체 서킷 성공이나 노면 조건·열 상태·셋업 적응을 증명하지 않는다. 현재 active 선언은 t414와 yaw retina의 제한된 120m qualification을 유지하며 무제한 주행 승격을 하지 않는다.

## 다음 실제 작업

다음 구간은 현재 정차 위치에서 `prepare_ac_episode --preserve-position`으로 이어가 공간적 주행 범위를 확장한다. 이는 정차/새 실행이 포함된 여러 구간이며 무중단 전체 랩으로 집계하지 않는다. 무중단 전체 랩은 numerical state를 보존한 더 긴 camera acquisition/indexing, 명시적 시간/저장 한도, 공식 lap/연속 route coverage의 별도 증거가 필요하다. 현재 1000개 camera group/700개 결정 제한을 전체 랩 성공 기준으로 축소하지 않는다.

오류/회복 상태를 실제 영상·몸 감각과 함께 수집하고 teacher 질의를 분리한 뒤, 검증된 GPU CSR와 최대 3개 독립 병렬 실험으로 학습한다. 따로 남긴 t347/t303은 설계에 활용한 개발 평가이므로 독립 최종 시험이라고 부르지 않는다. 현재 마지막 상태는 t436 정상 pause 뒤 t437의 fresh v2 heartbeat에서 확인한다.

주요 실행: t420 배포/프로토콜/테스트 영수증, t425/t426 30m, t429/t430 60m, t434/t435 120m, t436 일시정지. 계획과 active camera 선언을 이 증거에 맞춰 갱신했다.
