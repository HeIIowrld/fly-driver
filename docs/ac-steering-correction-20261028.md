# 조향 교정 모델의 재시험과 실행 시간 조건

2026-10-28 KST. 전체 목표는 파리 감각·신경회로를 사용한 자율 서킷 주행과 최적화다.
이 기록의30m 시험은 전체 목표 완료를 뜻하지 않는다. 화면 활성화·클릭·키 입력은 사용하지 않았다.

후속 작업에서는 픽셀 망막 계산을 수집 worker로 옮기고 시간 처리/입력 수치를 검증했다.
반복 시험과 새 출발점 교사400개 자료의 최신 상태는
[비동기 망막·주기 교사 기록](ac-async-retina-and-paced-teacher-20261028.md)을 따른다.

## 학습과 개발 평가

t244의 실제 학생144개 관측에 t247에서 같은30km/h 기하 교사를 질의했다. 이 미실행
교정 라벨을 기존938개와 합친 t248은1,082개,6개 연속 에피소드다. 관측·마스크·시각을
바꾸지 않았고 actor에 교사 위치·경로를 추가하지 않았다.

t249는 t240에서 시작해3에포크·180회 업데이트를 완료했다. 고정 연결 그래프는 유지하고
시각·기관 어댑터와 운동 출력만 학습했다. 체크포인트 SHA-256은
`da0e422b9569b6092e6863874b764d19ea1f92b20706345d077a25ebd397ca0c`이다.

| 동일1,082개 학습 자료 | 조향 RMSE | 가속 RMSE | 제동 RMSE |
|---|---:|---:|---:|
| t240 초기값 | 0.13252 | 0.08479 | 0.07988 |
| t249 선택 회차3 | 0.08761 | 0.04999 | 0.06968 |

그러나 별도75개 개발 관측에서 조향 오차는 t240의0.10457에서 t249의0.14749로 늘었다.
가속도0.06224→0.06512, 제동은0.04174→0.04014였다. 학습 재생의 개선을 일반화나 실제
조향 개선으로 간주하지 않는다. 개발 자료는 같은 차·트랙·세션이고 설계에 사용됐으므로
독립 최종 시험이 아니다. t259에서 회로5개 고정 텐서와 그래프 보존을 다시 확인했다.

## 방향별 영상 가림 평가

t250은 t240에 대해 같은75개 개발 관측의 입력만 가린 평가다. 몸 감각은 유지하며 가린
소스의 RGB·대비·유효 마스크를0, 나이를 최대 나이의10배로 설정했다. `--view-detail`과
입력 보존 테스트를 추가했고 t259에서는 교정 모델도 같은 방식으로 평가했다.

| t240 입력 | 조향 RMSE | 가속 RMSE | 제동 RMSE |
|---|---:|---:|---:|
| 네 방향 | 0.10457 | 0.06224 | 0.04174 |
| 전방만 | 0.26731 | 0.11370 | 0.02591 |
| 전방 결측 | 0.09652 | 0.11919 | 0.04041 |
| 왼쪽 결측 | 0.14126 | 0.07178 | 0.03837 |
| 오른쪽 결측 | 0.09716 | 0.07988 | 0.04175 |
| 후방 결측 | 0.09140 | 0.09241 | 0.02837 |

현재 모델이 비전과 여러 방향 입력에 의존함을 보여주지만, 카메라별 이득이 모든 출력에서
일관되지는 않다. 전방 전용 모델을 따로 같은 예산으로 학습한 비교나 실제 주행 비교가
아니므로 다중 시점 구조가 본질적으로 우월하다는 증거로 해석하지 않는다.

## 원래 Hotlap 출발점에서의 실제 시험

두 모델 모두 API로 세션을 초기화하고 native 정차·조향 보정·1단 연결을 확인했다.
시작 x/y와 heading·타이어 온도 등을 원본 기록으로 대조할 수 있게 보존했다. 완전히 같은
광학·열·호스트 부하 조건의 반복 실험이라고 주장하지 않는다.

t256과 t272의 초기 위치 차이는약0.00131m, native heading 차이는약0.0000167rad,
타이어 core 온도의 최대 차이는약0.112°C였다. 둘 다 비전면이었으므로 출발 위치의 큰 차이로
t272 실패를 설명할 수는 없다. 여전히 단일 비교이며 광학·호스트 부하까지 동일하다는 뜻은 아니다.

| 시험 | 모델/시간 처리 | 제어 수 | 계획30m | 최고 피드백 속도 | 평균 절대 gap | 종료 gap |
|---|---|---:|---|---:|---:|---:|
| t256 | t240, 기존 상대 주기 | 255 | 도달 | 13.00km/h | 1.430m | -0.611m |
| t264 | t249, 기존 상대 주기 | 137 | 도달 | 29.26km/h | 2.070m | 1.404m |
| t272 | t249, 백그라운드 필수 | 129 | 실패 | 16.30km/h | 별도 원본 보존 | 3.011m |
| t276 | t240, 절대 시각 기준 주기 | 90 | 실패 | 11.21km/h | 별도 원본 보존 | 3.016m |

t264는 실제137개 요청 모두 전면 상태로 기록됐다. 초기화 API와 정차 보정 당시에는
비전면이었고, 코드에 창 활성화 호출은 없었다. 전면으로 바뀐 원인은 이 자료만으로
확정하지 않는다. t256은 모든 요청이 비전면이었다. 따라서29km/h 결과를 동등 조건의
학습 효과로 단정하지 않는다. t264 감사 t265의 정지 과정 포함 최고 속도는29.296km/h,
최대 변위는33.807m였다. 경로 추종 개선 모델로 채택하지 않았다.

`--require-background`를 추가해 전면 상태면 제어를 중단하도록 하고, 창을 뒤로 보내는
자동 조작 없이 t272를 재시험했다. 모든129개 요청은 비전면이었으나 약13.969m에서
gap3m 제한을 넘었다. t273에서 원본 영상·몸 입력→출력 재생과 실제 정지·장치 해제를
확인했다. t249는 기존 모델을 대체하지 않는다.

t276은 아래 시간 처리 변경 뒤 약6.590m에서 같은 gap 제한으로 중단됐다. t277도 실제
입력/출력 재생과 정지를 확인했다. 이전 t240의30m 성공은 유효한 과거 관측이지만,
변경된 실행 환경에서 반복 가능한 경로 추종이나 완주를 증명하지 않는다.

## 실행 시간의 제한

기존 학생 루프는40ms 대기 뒤 센서를 읽어, 응답 대기 시간이 다음 결정 주기에 누적됐다.
t256 요청 간격 중앙값은43.663ms, t264는50.414ms, t272는43.941ms였다.

한 에피소드의 기준 시각에 모든 결정 목표 시각을 맞추도록 수정했다.6ms 센서 지연을 넣은
테스트에서는 첫 정렬 이후40ms를 유지하며46ms로 누적되지 않았다. 하지만 실제 t276의
요청 간격 중앙값은46.560ms, 추론 구간 중앙값은40.766ms였다. 처리 비용 자체가 예산을
넘으면 이 수정만으로25Hz를 확보할 수 없다. 실패 원인을 시간 처리 하나로 확정하지 않는다.

t279는 실제 pose-free 관측75개로 신경회로만 오프라인 재생했다.1스레드 중앙값18.54ms,
2스레드19.24ms,4스레드19.24ms였고 출력은 모두 비트 단위로 같았다. 더 빠르지 않아
스레드 설정은1로 유지했다. 실제 카메라 수집과 동시에 실행하는 전체 경로 시간과 구분한다.

t280의 읽기 전용100회 측정에서 중단 파일 존재 확인 중앙값은 NAS0.036ms, 로컬0.036ms,
창 신원 확인0.021ms, 프로필 해시0.383ms였다. 이 측정에서는 큰 병목이 아니므로 NAS 중단
파일 검사만 원인으로 몰거나 중단 기능을 제거하지 않았다. 원인 규명과 전체 지연 검증은 남아 있다.

망막의 고정 표본 좌표·계수를 캐시했다. 변경 전 전체/부분 영역의1,709개 수용기 결과 해시를
기준으로 최초/반복 호출 모두 바이트 일치를 검사했다. 좌표 캐시만의100회 측정은 중앙값
약1.68→1.57ms/소스로 작은 개선이었다.9개 탭을 한꺼번에 계산하는 실험은 약2.47ms로
더 느려 배제했다. 관측을 바꾸는 근사나 해상도 축소를 시간 개선으로 사용하지 않았다.

t281에서는 좌표 캐시 변경 후 t276의 실제90개 요청을 원본 픽셀·몸 감각에서 다시 재생했고
모델 출력 최대 오차0을 확인했다. 관련26개 테스트와 Ruff 검사를 통과했다. 처리 시간 예산
충족이나 주행 성능까지 입증하는 검사와는 구분한다.

## 화면 없는 에피소드 준비

`scripts/prepare_ac_episode.py`는 상태 확인→필요 시 API 재개→세션 재시작→native 정차
확인→API 주행 시작→조향 보정→필요 시1단 연결→최종 정차/기어 확인을 한 번 실행한다.
실패한 단계는 자동 재시도하거나 화면 조작으로 우회하지 않는다. t275에서 전체 순서를
실제 검증했다. 기본값은 읽기 전용이며 변경에는 `--execute`가 필요하다.

```powershell
$env:PYTHONPATH='src'
python -m scripts.prepare_ac_episode --execute --output runs/UNIQUE-episode
```

준비 결과의 `calibration_result` 경로를 해당 세션의 학생/교사 시험에 사용한다.
준비는 주행 성공을 뜻하지 않으며 모델 제어는 별도 유한 시험으로 수행한다.

## 다음 작업과 전체 목표

현재 교정 후보는 채택하지 않았고 게임은 API로 정차·일시정지했다. 다음 수집 전 실제
카메라+회로+계측 경로가 유지할 수 있는 결정 주기를 측정하고, 선언한 신경 틱/결정 시간과
실행 시간의 관계를 일관되게 검증해야 한다. 이어 그 조건의 실제 교사 연속 관측과 실패
상태를 보강해 여러 시작점에서 경로/가감속을 함께 평가한다. 학습 손실만의 감소를 채택
조건으로 삼지 않는다. 코너·지속 서킷 주행·완주, 열·하중·셋업 적응과 최적화는 전체 목표로 남아 있다.
