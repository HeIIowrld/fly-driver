# 시점별 시각 정규화와 긴 구간 주행 비교

갱신: 2026-10-27, Asia/Seoul. 최종 목표는 겹눈·파리 신경회로와 차량 몸 감각으로
Assetto Corsa를 비전 기반 운전하는 것이다. 이번 실행은 그중 다중 시점 조향 입력 개선이다.
앞선 [첫 학습](multiview-learning-20261027.md)은 시각의 유용성을 입증하지 못했다.

## 바꾼 부분

기존 입력은 RGB·시간 대비와 함께 유효성 플래그 자체도 학습 가능한 시각 신호로 사용했다.
일정한 밝기와 플래그에서 생기는 출력을 도로 변화에 따른 출력과 구별하기 어려웠다.
새 선택 모드 `photometric_normalization`에서는 다음을 적용한다.

- 각 시점의 각 겹눈 방향에서 RGB·시간 대비의 평균과 표준편차를 계산한다.
- 교사 조작·위치·지도·개발 주행 영상은 이 통계 계산에 쓰지 않는다. 기존512결정의
  학습 영상만 사용한다. 시점 간 통계나 특징을 섞지 않는다.
- RGB 표준편차 하한0.03·시간 대비 하한0.1, 표준화값은±5로 제한한다.
- 유효성은 값을 통과시키는 마스크로만 쓰고, 플래그 자체에서 신경 구동을 만들지 않는다.
- 학습 때 관측하지 못한 방향과 누락 영상의 구동은0이다. 평균을 빼는 연산이 누락 시각에
  가짜 음수 자극을 만들지 않도록 표준화 뒤에도 마스크를 적용한다.
- 통계는 모델 체크포인트에 저장하고 평가 중 갱신하지 않는다. 기존 모드와 체크포인트는
  그대로 복원되며 새 모드에서는 별도 통계 버퍼를 요구한다.

이는 파리의 생리학적 적응을 재현했다는 주장이 아니라, 영상 통계를 이용한 공학적 입력 보정이다.
시각 포트는 여전히 한 시점의 가까운12방향만 읽고, 시점 간 상호작용은 공유 재귀 회로 안에 있다.
정규화 자체에서 여러 시점을 합성하거나 직접 조향을 예측하지 않는다.

## 학습·검증 계약

설정은 [정규화 실험](../configs/multiview-photometry-pilot.json)에 있다. 학습률0.0002·8epoch·
32회 갱신,32결정 TBPTT로 기존 후속 실험과 같은 학습 예산을 사용한다. 수치 신경 상태는
결정 사이와 gradient detach 뒤에도 유지한다. 시각 어댑터만 학습하고 회로 연결·몸 감각
어댑터는 고정한다. 체크포인트 선택 기준은 전체 학습 시퀀스의 조향 RMSE다.

앞선6.4초 구간 대신 두 개발 출발점에서 최대24초·600결정씩 평가한다. **정규화 전 모델도
같은24초 구간에서 재평가**하며, 각 모델의 시각 제거와 경로 기반 교사 기준값을 함께 기록한다.
1.5m/s 고정 속도, MuJoCo 저수준 제어기와 곡률 의도를 사용한다. 실제 AC 조향각·가속·
브레이크를 학습한 결과로 표시하지 않는다. 타이어 열 학습과 실제 미러 반사 보정도 미검증이다.

시각 누락 시0구동, 시점별 독립성, 정규화 체크포인트 복원, 잘못된 표준편차 거부를 검사한다.
WSL 관련29검사와 전체 소스 Ruff 검사가 통과했다. 학습 손실 감소만으로 운전 성공을 판정하지 않는다.

## 결과

학습 조향 RMSE는0.15870에서 **0.09267**로 약42% 줄었다. 두 모델 모두 같은512결정·8epoch
예산을 사용했다. 정규화 모델은8epoch를 선택했고, 조향 출력 이득은약210,208이다. 큰 이득으로
작은 회로 신호를 증폭하는 조건은 여전히 남아 있으며 생리학적 운동 이득으로 해석하지 않는다.

| 24초 주행 조건 | 개발A RMS(m) | 개발B RMS(m) | 두 구간을 합친 RMS(m) |
|---|---:|---:|---:|
| 이전 모델, 시각 정상 | 0.33564 | 1.59559 | 1.15295 |
| 정규화 모델, 시각 정상 | **0.15093** | **0.20661** | **0.18092** |
| 정규화 모델, 시각 제거 | 0.84988 | 1.06990 | 0.96618 |
| 경로 기반 교사 기준값 | 0.08110 | 0.08094 | 0.08102 |

정규화 모델은 이전 모델보다 합친 횡오차가약84%, 자신의 시각 제거 조건보다약81% 작다.
정상 모델은 각 구간약34m를 진행했다. 모든 조건600결정·24초를 관측했고 종료 이유는
`time_limit`이다. 이탈 때문에 짧아진 구간끼리 RMS를 비교하지 않도록 공통 시간 구간 비교기를
추가했고, 조기 종료가 있는 합성 사례1개로 검사했다. 이 결과에서는 공통 구간도 모두600결정이다.

**이 두 개발 조건에서는 영상이 유용하게 조향에 기여했다.** 하지만 같은 도로 형상에서 조정한
개발 결과다. 독립 코스·여러 시드·전면 전용 별도 학습·일반 재귀 모델과의 효율성 비교는 하지
않았으며 다중 시점 자체의 우위도 입증하지 않았다. 전 구간 완주·속도 최적화·AC 운전 성공으로
표시하지 않는다. 다음은 새로운 출발/곡선과 더 긴 구간에서 재검증하고 실제 AC 감각 기록을

## 실제 게임 계측

같은 작업 중 실행한 읽기 전용 확인에서는 AC 런처만 관측했고 `acs`/`acs_x86` 엔진은
찾지 못했다. TCP 센서 수신은1초 제한에서 시간 초과, 수신0개다. 실패 기록은
`runs/ac-readonly-probe-20261027-t27/`에 보존했다. 실제 게임 픽셀·타이어 온도·하중의
학습 자료가 확보됐다는 의미가 아니다. 주행 세션 상태는 사용자에게 확인 요청했다.

사용자가 런처만 열린 상태라고 확인한 뒤 Computer Use로 BMW Z4 GT3·Monza 연습을 선택했다.
초기 비디오 검증 요구를 처리하고 Single Screen·전체 화면 해제,1280×720 설정을 저장한 뒤
실제 `acs.exe` 주행 엔진과 연습 화면을 확인했다. 비디오 변경 전/후와 영수증은
`runs/ac-video-valid-20261027-t27/`에 있다. SDK 앱은 실제 로그에서5행의 `import socket` 로딩
실패를 확인했다. 이는 앞선3.3 문법 검사와 일반 Python 테스트로는 검증하지 못했던 문제다.

네트워크 확장을 불러올 수 없는 AC에서도 앱을 로딩하도록 TCP 의존성을 지연 import하고,
실패 시 사용자 쓰기 가능 폴더 `%LOCALAPPDATA%/flybrain/telemetry/`의 두 파일에 최신 값만
쓰는 읽기 전용 전달 방식을 추가했다. 누적 파일이 계속 커지지 않으며 외부 수집기가 유한
샘플 예산으로 기록한다. 원자 교체·생산자 세션·수신 순서·반복값/시간 초과·프레임 크기를
검사하고, 중간 스냅샷이 빠질 수 있음을 명시한다. 단위·시뮬레이션 시계·영상 동기는 여전히
검증 전이다. Windows 파일 전달3검사, WSL 관련27통과·Windows 전용2건 건너뜀과 Ruff 검사를
완료했다. Windows 전체 선택 검사에서는26통과·네트워크2실패(TCP reset·기존 UDP timeout)를
기록했으며 방화벽 설정을 변경하지 않았다.

수정한 앱을 배치했고 이전 파일과 영수증을 `runs/ac-file-deployment-20261027-t27/`에 보존했다.
새 앱 SHA-256은 `955eebca4497b3cc93d1ef74f07b571adbbda66a6577b50d7dc0abf579a7eb8c`다.
테스트 소스·로그234파일은 `runs/ac-file-transport-20261027-t27/`에 회수·해시 대조했다.
배치 뒤에는 주행 엔진을 다시 시작해야 한다. 현재 Windows 방화벽 확인창은 사용자 직접 처리를
기다리고 있으며, 네트워크 허용을 자동 조작하지 않았다. 따라서 실제 센서 수신은 아직0개다.
