# 망막 사전 계산과 실제 주기에 맞춘 교사 자료

2026-10-28 KST. 파리 신경회로의 자율 서킷 주행을 위한 후속 작업이다. 학생 완주와
30km/h 속도 유지·셋업 적응은 아직 검증되지 않았다. 화면 조작은 사용하지 않았다.

## 실제 수집과 함께 측정한 시간

t282의 API로 재개한 뒤 t283에서100회 읽기 전용 추론을 했다. 단계별 시각은 QPC로
측정했고 구동기는 취득하지 않았다. 모델은 t240, 관측은 현재 네 카메라와 native 몸 감각이다.

| 처리 단계 | 중앙값 | 95백분위 | 99백분위 |
|---|---:|---:|---:|
| native 읽기 | 0.049ms | 0.080ms | 0.097ms |
| 카메라 cache 선택 | 0.050ms | 0.069ms | 0.070ms |
| 망막/몸 감각 변환 | 9.764ms | 13.486ms | 14.098ms |
| 감각 입력→회로 drive | 2.382ms | 4.019ms | 4.899ms |
| 신경회로4틱 | 22.049ms | 27.004ms | 30.558ms |
| 전체 처리 | 34.694ms | 42.539ms | 44.505ms |

이전 오프라인 회로 전용 측정보다 실제 경로가 느렸다. 단순히 CPU 스레드를 늘리는 것은
이전 t279에서 이득이 없었으므로1스레드를 유지했다.

## 픽셀만의 계산을 수집 worker로 이동

`CSPCameraRetina.precompute_pixels()`를 카메라 수집 worker에서 호출하도록 연결했다.
이미지 내용을 해시한 bounded64개 cache에 순수 픽셀→수용기 RGB 결과만 저장한다.
완성된 네 이미지 묶음은 이 준비가 끝난 뒤 공개된다. 무거운 계산은 cache lock 밖에서 한다.

제어 시점에는 원본 RGB와 그 해시·식별자·시각을 계속 검사한다. cache는 시각·대비 이력·
몸 감각·유효 마스크를 저장하거나 대신 결정하지 않는다. 대비는 마지막으로 소비한 영상과
현재 영상의 실제 시각 차이로 계산하고, 영상 나이와 native 몸 감각은 결정 시점에 평가한다.
stale 영상은 준비돼 있어도 사용할 수 없다. actor 입력 필드7개와 원본 PNG를 유지했다.

준비 여부와 무관한 결과 일치, cache 용량 제한, 원본 이미지 변경 탐지, 결측 처리를 테스트했다.
몸 감각 이력에 준비 계산이 영향을 주지 않음도 검사했다. 기존 픽셀 표본 계산의 golden 해시는
유지했다. GPU 공유 텍스처나 headless 렌더로 바꾼 것이 아니며 전체 CPU 사용량 감소량은
직접 측정하지 않았다.

t284는 동일 t240으로 비전면100회 추론을 완료했다. 네 영상 모두 유효했고 cache hit400,
miss0이었다. 제어 쪽 망막 변환 중앙값은1.247ms, 전체 중앙값31.681ms,95백분위36.744ms,
99백분위38.283ms였다. 회로 계산 중앙값 자체는26.894ms로 늘어 전체 이득이 망막 단계
절약량과 같지는 않았다. host load와 worker 경쟁이 있을 수 있고 원인을 하나로 확정하지 않는다.

## 실제 학생 반복 시험

각 시험은 API 초기화·정차 조향 보정·1단 확인 후, 교사 혼합 없이 t240 출력으로 수행했다.
모두 백그라운드 필수 조건을 사용했다. 원래30m 목표·40km/h·40m·gap3m·측면 여유1m·
입력 나이150ms·추론80ms 제한을 늘리지 않았다.

| 시험 | 학생 제어 | 제어 종료 변위 | 최고 기록 속도/종료 | 결과 |
|---|---:|---:|---|---|
| t286 | 268개 | 30.132m | 13.532km/h | 계획30m 도달 |
| t289 | 28개 | 짧은 출발 구간 | 입력 나이 또는 추론 시간 만료 | 자동 정지 |
| t294 | 300개 | 26.571m | 약9.955km/h | 결정 예산 종료,30m 미달 |

t286 요청 간격 중앙값40.532ms,99백분위48.658ms였고 추론 구간99백분위37.774ms였다.
평균 절대 gap1.511m, 종료 gap0.603m였다. t287에서 입력→재귀 출력 최대 오차0, 실제 정지와
장치 해제를 확인했다. 네 영상에 대한 준비 cache는 hit1072,miss0이었다.

t289는 t290에서 실제28개 요청 재생을 검증했다. 당시 오류 문구가 입력150ms 초과와
추론80ms 초과를 구분하지 않아 원인을 더 좁힐 수 없었다. 성공 한 번으로 반복성을
확보했다고 하지 않으며 이 실패 기록도 보존한다.

이후 만료 당시 수치와 처리 단계·입력 메타데이터를 `expired_inference`에 기록하도록 했다.
기록 I/O보다 먼저 중립/제동과 장치 해제를 수행한다. 마지막 guard가 지연되면 그 뒤에
입력 나이·추론 시간을 다시 평가해 만료된 출력을 보내지 않는다. 지연을 주입한 테스트에서
순서와 무송신을 확인했다. 학생 프로세스의 GC 시각도 별도 기록한다.

t294에서는 만료나 경로 제한 초과가 없었지만300개 결정 안에30m에 못 갔다. 요청 간격은
중앙값40.232ms,95백분위45.230ms,99백분위49.655ms였다. 추론 시간99백분위39.976ms,
cache hit1200/miss0이었다. t295의300개 출력 재생 최대 오차는0이며 실제 정지도 확인했다.
이 run에 기록된 GC generation2 수집은 없었다. t289의 실패 원인을 GC로 확정하지 않는다.

따라서 처리 경로 개선과 수치 보존은 검증됐지만 경성 실시간 보장이나 충분한 가속·경로
추종의 반복성은 아직 없다.

## 같은 시간 기준의 출발점 교사400개

교사 루프도 에피소드 기준 시각을 사용해 센서 응답 대기가 주기마다 누적되지 않게 했다.
6ms 센서 지연을 넣은 테스트에서 초기 정렬 뒤40ms를 유지했다. 네 카메라의 사전 계산도
사용하되40ms 계산 마감과30km/h 목표·40km/h 중단 조건은 유지했다.

t296에서 화면 없이 에피소드를 준비했고 t297은 원래 Hotlap 출발점에서400개 실제 교사
제어를 완료했다. 요청 간격 중앙값39.928ms,95백분위41.941ms,99백분위43.210ms였다.
최고29.041km/h, 초기 오차를 포함한 최대 gap약2.593m, 종료 gap약0.00677m였다.
foreground 기록은0이며 네 방향 cache hit1600/miss0이었다.

t298의 독립 native 정차·vJoy FREE 검사를 통과했다. t299에서 원본 PNG·native prefix로
7개 actor 필드를 다시 구성하고 기하 교사 제어를 다시 계산한 최대 오차가 모두0이었다.
400개 관측 모두 네 소스가 유효하고 고유 카메라 묶음도400개다. 새 봉인 manifest SHA-256은
`0863f60582919046b010bbaa5c41a03022c32065bdd592c115734ec53ce0dd8a`다.

교사 구현의 시간 처리가 바뀌어 구현 해시도 바뀌었다. 과거 라벨 계약과 바로 합치지 않으며,
기존 관측을 사용할 때는 현재 교사 계약으로 재질의한 뒤 합쳐야 한다. 이 자료를 학생이
이미 학습하거나 같은 결과를 낸 것으로 보고하지 않는다. t300의 API로 다시 일시정지했다.

## 회전 몸 감각의 별도 검토

t292는 t230·t244·t286의 원본 native prefix만 읽어, `-heading`의 중앙 차분과
`localAngularVel`의5샘플 평균을 비교했다. host receipt 시각을 사용했고 속도>5km/h,
시간 창0.04~0.4초, 충분한 회전을 보인 샘플만 선택했다. 세계 위치나 경로는 쓰지 않았다.

| 원본 기록 | 샘플 | native 축1 기울기 | 상관 | 잔차 RMSE |
|---|---:|---:|---:|---:|
| t230 | 377 | 1.00170 | 0.99944 | 0.000693 |
| t244 | 125 | 1.00073 | 0.99912 | 0.001279 |
| t286 | 232 | 0.99997 | 0.99991 | 0.000430 |

축0/2는 yaw 변화율과 일관되게 대응하지 않았다. 축1은 native yaw rate 후보로 강한
내부 일관성을 보였지만 독립 SI 단위·모든 회전 축·파리 생리 보정을 증명하지 않는다.
현재 actor의 할테르6개 슬롯은 계속 미관측 상태이며 이 검토로 입력을 자동 추가하지 않았다.

다음 모델에서는 이 검증을 바탕으로 회전 감각을 명시적으로 등록할 수 있다. 도입 시
관측/기관 calibration을 갱신하고 원본 prefix에서 새 입력을 재구성해 감사한 뒤 다시
학습·실제 비교해야 한다. 절대 heading·세계 위치는 actor 입력으로 보내지 않는다.

다음은 새 출발점 자료 보강과 회전 감각 입력 검토, 반복된 주행 검증이다. 지속 주행·코너·
완주, 타이어 열/하중·셋업 적응과 랩타임 최적화는 전체 목표로 남아 있다.
