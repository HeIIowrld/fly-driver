## 세션 1 · 처음 보는 서킷의 코너 판독

초파리의 겹눈/운동 시각과 비행 유래 균형·운동 회로를 자동차라는 가상 몸에 연결한다. 차체 기울기·회전·하중·타이어 상태를 몸 감각으로 되먹임하며 조향·가감속과 빠른 레이싱 라인/랩타임을 학습한다.

**이번 목표.** 전후좌우 영상의 방향과 시간 변화에서 코너 유무, 좌우 방향, 시작 거리, 판독 보류를 구분한다. 이 채팅에서는 저장 영상과 원본 시각으로 판단을 검증한다. 코너 검증을 위해 Imola에서 주행하는 작업으로 전환하지 않는다.

**현재까지.** 고정한 기준은 3프레임 T4/T5 계열 운동 시각 특징을 쓰는 [판독 설정](../runs/vision-frozen-next-corner-20261110-01/pins.json)과 [추론 스크립트](../scripts/infer_frozen_next_corner.py)다. Magione 4–20m 접근 152프레임에서 방향 적중은 좌 2/67, 우 64/85였고 방향과 거리 ±5m를 동시에 맞춘 건 52개였다. 범위 밖 경보는 26개였다. 좌 접근 67개 중 59개가 배경으로 분류됐고, 원시 좌 후보 8개 중 2개만 코너 유무 관문을 통과했다. Monza 검증의 좌 2/6은 두 랩에 반복된 물리 코너 하나에서 나왔다. 작은 표본을 독립 코너 성능으로 확대 해석하지 않는다. [Magione 결과](../runs/vision-magione-gradual-edge-transfer-20261111-01/landmarks.json), [좌 판독 단계](../runs/vision-magione-left-readout-stages-20261111-01/result.json), [Monza 검증](../runs/vision-monza-corner-event-readout-20261111-01/result.json)

Imola의 입고 기록 6개와 원본 캡처 616개에는 4–20m 양성이 없었다. 이동 판독 155개 중 범위 밖 경보가 121개였다. 연속 굽음 조건이 이를 24개로 줄였지만 Magione 결합 적중도 52→14개, Monza는 5→0개로 줄었다. Magione에서 보조 판독은 확인 접근 3→4건과 먼 오경보 구간 1→25건을 함께 만들었다. 거리 갱신도 기존 52개를 42·45개로 낮췄다. 이 조건들은 승격하지 않았다. [Imola 입고](../runs/vision-imola-archive-admission-20261111-01/admission.json), [연속 확인 비교](../runs/vision-corner-third-track-confirmation-20261111-01/result.json), [접근별 비교](../runs/vision-corner-event-operating-comparison-20261111-01/result.json), [거리 갱신](../runs/vision-corner-causal-onset-update-20261111-01/result.json)

**인계 작성 당시 계획.**

1. 기존 [채점기](../scripts/evaluate_live_corner_geometry.py)의 기본 결과를 보존하면서 공통 채점 모드를 완성한다. 원본 캡처 전체를 분모에 넣고 미출력·보류·직선·좌·우를 분리한다. 4–20m 방향과 ±5m 결합 적중, 시작 거리 편향 및 접근 중 거리 변화, 물리 코너별 최초 안정 예고 거리, 직선/범위 밖 연속 오경보를 함께 남긴다.
2. Magione 좌측을 원시 특징→후보 방향→코너 유무 관문→거리로 나눠 다시 본다. 직선에서 울리지 않는 조건을 같이 확인하고, 상대 이동에 따라 예고 거리가 줄어드는지 비교한다. 과거 프레임과 허용된 상대 운동만 사용하며, 영상 결측은 보류로 기록한다.
3. [자료 인벤토리](../runs/vision-cross-track-source-inventory-20261110-01/result.json)에서 입고 상태를 재확인한다. 좌·우 여러 물리 코너와 직선을 포함하는 독립 서킷 원본으로 개발·최종 평가를 분리한다. 최종 영상에 손대기 전에 핀·임계값·평가 기준을 고정한다. 자료가 없다면 미검증으로 남기고 필요한 원본 조건을 전달한다. 트랙 ID·지도·절대 위치와 방향은 평가에만 둔다.

**현재 다음 작업.** Laguna Seca 독립 평가는 실행했고 사전 기준에 실패했다. [실패 원본과 판독 단계](corner-laguna-independent-20261111.md)를 보존한다. 개발 자료에서 코너 유무와 좌·우 선택을 분리했다. Magione의 좌·우 선택은 접근 143개 모두 맞혔지만 코너 유무 임계값이 서킷 사이에서 통하지 않았다. [분리 실험과 임계값 비교](corner-factorized-readout-20261111.md). 가까운 도로 경계와 경보 복구를 결합한 후보를 고정해 Mugello에서 평가했다. 다음 비교는 코너 접근을 직선으로 판독한 단계를 추적하고, 새 독립 자료에서는 연속 예고를 채점할 수 있는 접근을 사전 확인한다. [Mugello 평가](corner-mugello-independent-20261111.md). [네 카메라 기여와 외부 코드](corner-camera-and-external-code-20261111.md)에 입력 경로가 있다.

**완료와 인계.** 기준과 후보의 동일 입력 결과, 고정 설정과 해시, 누락과 오경보 사례를 남긴다. 좌우 및 거리·오경보를 함께 봐도 성능이 유지될 때만 일반화 근거로 넘긴다. 세션 2에는 시각, 코너 유무·방향, 시작 거리, 신뢰/보류, 유효 입력 상태와 시계 계약을 전달한다.

## 세션 2 · 도로 경계와 진입·통과·탈출 라인

초파리의 겹눈/운동 시각과 비행 유래 균형·운동 회로를 자동차라는 가상 몸에 연결한다. 차체 기울기·회전·하중·타이어 상태를 몸 감각으로 되먹임하며 조향·가감속과 빠른 레이싱 라인/랩타임을 학습한다.

**이번 목표.** 세션 1의 예고와 영상에서 보이는 좌우 경계로 차량이 달릴 수 있는 국소 라인을 만든다. 저장 영상에서 진입·안쪽 통과·탈출이 시간에 따라 이어지는지 먼저 평가한다.

**현재까지.** [아카이브 플래너](../scripts/plan_frozen_corner_archive.py)에는 경계 기억과 코너 유도/연장 옵션이 있다. Magione 1,195개 중 경로 967개, 지도 평가상 내부 907개, 검증 불완전 60개, 무경로 228개, 연장 36개였다. 검증된 외부 이탈은 0건이었다. 이 집계로 코너 전체의 연속성이 입증되지는 않는다. Magione 가까운 네 접근의 라인은 시작 약 1m 전에 끝났고 Monza 비교에서는 전체 코너에 걸쳐 이어진 경로가 0/22였다. [Magione 폭 검증](../runs/vision-magione-extension-width-transfer-20261111-01/result.json), [Magione 경로 중첩](../runs/vision-magione-rolling-line-overlap-20261111-01/result.json), [Monza 연속 단면](../runs/vision-monza-rolling-cross-section-20261111-01/result.json)

Magione 경계 기억 0.85초는 4m 양측 적중을 145/152까지 올렸지만 그 실험의 방향·거리 결합 적중은 54개 그대로였다. 별도 시작점 진단에서 영상·동일 단면 지도·촘촘한 지도 적중이 5·71·90개로 갈렸다. 경계 관측과 굽음 시작점을 찾는 로직을 따로 검증할 이유다. 추가 코너 경보를 라인에 넣은 실험에서는 적중 27개에서 진입 성공이 26→26개, 시작 뒤 10m 도달이 23→24개였고 범위 밖 경보 81개가 라인 44개를 바꿨다. [경계 기억](../runs/vision-magione-near-edge-memory-duration-20261111-01/result.json), [시작점 오차 분해](../runs/vision-magione-onset-error-decomposition-20261111-01/result.json), [예고와 라인 연결](../runs/vision-magione-rescued-corner-line-20261111-01/result.json)

**재개 후 할 일.**

1. 저장된 Monza/Magione에서 경로 연속성 기준을 먼저 고정한다. 동일 물리 구간의 연속 프레임을 차량 상대 이동으로 맞추고, 겹치는 부분의 횡방향 차이, 진입·통과·탈출 각 단계의 유효 거리, 경계 여유와 경로 끊김을 측정한다. 완전한 통과 원본이 없는 경우 해당 단계를 분리한다.
2. 관측 좌우 경계에서 안전 여유와 차량 곡률 한계를 두고 라인을 생성한다. 경계 관측이 짧거나 사라지면 유효 지평과 원인을 표기한다. 동일 입력으로 코너 예고 사용/미사용과 신뢰도가 낮거나 잘못된 예고의 영향을 비교한다.
3. 지도·절대 자세와 기준 라인은 채점·교사에 둔다. 타임스탬프, 좌표계, 경계 지지 범위, 경로 및 곡률, 보류/종료 사유를 기록한다. 진입 경로와 코너 전체 라인, 빠른 라인의 랩타임 검증을 별개로 보고한다.

**완료와 인계.** 좌우 실제 코너 저장 영상에서 진입·통과·탈출 라인의 연속성, 차량 폭을 포함한 경계 여유와 곡률 한계를 검증한다. 세션 3에 동일 시각 재생이 가능한 국소 경로 계약, 유효 지평, 실패 예시를 넘긴다. 세션 1의 고정 판독기를 받은 뒤 같은 평가를 반복한다.

## 세션 3 · 비행 유래 몸 되먹임과 AC 최종 검증

초파리의 겹눈/운동 시각과 비행 유래 균형·운동 회로를 자동차라는 가상 몸에 연결한다. 차체 기울기·회전·하중·타이어 상태를 몸 감각으로 되먹임하며 조향·가감속과 빠른 레이싱 라인/랩타임을 학습한다.

**이번 목표.** 세션 2에서 검증한 라인을 고정하고 몸 감각 되먹임이 조향·가속·제동에 미치는 인과적 기여를 측정한다. 앞선 두 세션을 기다리는 동안에는 저장 재생과 입출력 계약을 준비한다.

**현재까지.** 같은 Monza 랩 473개 판단에서 영상과 native 몸 감각을 원본 시각으로 결합했다. 하중·온도 중립화에 따른 조향 의도 최대 차이는 각각 0.06380·0.01174였다. 몸 모델에서 하중만 되먹인 조건은 횡 RMS 0.832→0.646m, 시간 4.825→4.865초였다. 앞 수치는 저장 재생 반응이고 뒤 수치는 합성 폐루프 결과다. 별도 Imola 저속 shadow의 18개 출력은 입력 수신→출력 중앙값 158.14ms로 카메라 100ms 주기보다 길었고 액추에이터 송신은 없었다. 과거 학생 SDK 시험은 있었으며, 여기서 인계하는 판독기·라인·비행 회로 조합으로 미지 서킷 유효 랩과 랩타임을 입증한 근거는 확인되지 않았다. [구현 현황](implementation-status.md), [실행 기록](vision-next-corner-20261110.md), [출력 계약](current-flight-output-contract-20261105.md)

**재개 후 할 일.**

1. 비행 안정화·날개 조종에 대응하는 회로 포트, 실측 연결, 기능 근사와 차량 대응 어댑터를 구분한다. 원본 시계 기준으로 경로와 몸 센서의 단위·부호·신선도·결측을 점검한다. 회전과 기울기는 몸 감각으로 사용하고 절대 방위는 평가에만 둔다. 순환 상태는 결정 사이 유지하고 에피소드 경계에서 초기화한다.
2. 같은 시각·경로·초기 차량 조건으로 전체 회로와 요레이트·기울기·하중·타이어 입력 각각을 중립화한 조건을 비교한다. 포화, 반응 방향, 지연, 차선 여유, 조향·가감속 변화를 기록한다. 교란이 없는 추종과 교란 회복을 분리한다. 과거 조향/페달 모델은 비교군으로 식별한다.
3. 1·2번 검증을 통과하고 실험 범위가 AC 제어로 넘어간 뒤, [CSP 세션 제어](../scripts/control_ac_session.py)와 백그라운드 센서·제어 경로에서 진행한다. API 실패는 기록한다. 훈련·리셋에 데스크톱 입력을 사용하지 않는다. shadow에서 새 경로의 시각·센서 신선도·제어 출력·종료 계약부터 검증한다.
4. 최종 독립 서킷에서 같은 차량·셋업·초기 조건으로 회로 적용/대조를 비교한다. 전체 시도, 유효·무효 랩, 종료 원인, 경계 이탈, 유효 랩타임을 함께 보고한다. 설정·소스 리비전·해시·시드·원본 로그를 runs/에 보존한다.

**완료와 인계.** 회로 부품 반응, 차량 통합, 유효 완주, 랩타임 효과를 각각 판정한다. 저장 재생과 합성 폐루프에서 얻은 수치를 AC 랩 결과에 합치지 않는다.
