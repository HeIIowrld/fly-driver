# 실제 저속 이동과 비행 회로의 회전 감각 피드백

2026-10-29, Asia/Seoul. [프로젝트 대전제](PROJECT_CHARTER.md)는 그대로 유지한다.
**실제 AC 차량을 비행 후보의 조향으로 저속 이동시키고, 실제 몸 회전 입력이 회로 출력을
회전 반대 방향으로 바꾸는 것을 전체 원본 재생에서 확인했다.** 영상 기반 경로 추종,
실제 교란 억제 성능, 학습된 가감속, 완주·레이싱 최적화의 검증은 아직 아니다.

## 적용한 것과 시험용으로 고정한 것

- 후보/가중치: 기존 t1121. 고정 시각망4상태와 비행 후보9728뉴런/1311145선택 연결을 사용했다.
  추론 소스/설정은 전체 원본 대조 t1132와 일치해야 한다. 새 학습이나 후보 승격은 하지 않았다.
- 과제 속도: 6km/h, 기존 속도 명령 단위로 `goals[1]=6/30`. 명령의 의미를30km/h로 남겨놓고
  저속 시험이라고 부르지 않았다. 좌우 과제는 사전에 지정한 `0 → +0.5 → −0.5 → 0`이다.
- **이동 중 조향은 회로 의도에 −0.6을 곱하고 ±0.1로 제한했다.**
  정차 prefix와 마지막 제동에서는 조향을0으로 덮어썼다. 원래 회로 출력은 계속 기록했다.
- **페달은 시험용6km/h 속도 제어기다.** 가속은 최대0.12, 목표 초과 시 가속을 끄고 제동한다.
  회로가 낸 전진/정지 의도로 페달을 학습·제어한 결과가 아니다.
- 전25관측 정차 →75관측 출발 →좌25 →우25 →시각 기준 복귀25 →제동50의 총225관측.
  처음 중립이면 첫 정차 구간에 이미 연결된 기어 버튼을 한 번 눌렀다. 창·키 입력은0회다.
- 차량 위치/기어/바퀴 이탈은 별도 진단 가드에만 사용했다. actor는 영상과 허용된 몸 감각,
  사전 지정 과제 명령을 받는다. 정답 경로·world pose를 actor에 넣지 않았다.
- 최고10km/h/위치 변화20m/바퀴 이탈0 가드를 유지했다. 실제 결과는 이 한계 안이었다.

실행은 `scripts/probe_flight_moving_body.py`, 고정 계획은
`configs/flight-moving-body-v1-20261029.json`, 페달/조향 구분은
`src/flybrain_drive/flight_moving_probe.py`에 있다.

## 실제 회전 감각이 회로에 준 영향

동일한 원본 영상·몸 이력·과제 명령을 유지하면서, 비교 회로에 들어가는 **yaw 값만0**으로
만들었다. 유효성은 그대로 유지해 ‘센서 없음’ 효과와 구분했다. 추가로 yaw 부호를 뒤집은
반례도 저장했다. 두 비교 상태 모두 처음부터 연속 적분했고 중간에 초기화하지 않았다.
비교 자료는 감사 실행의 `yaw-replay.npz`에 있다.

| 구간 마지막10관측 평균 | 실제 왼쪽 회전 속도(rad/s) | 실제−yaw0 왼쪽 회전 의도 |
|---|---:|---:|
| 좌 과제 | +0.016663 | −0.0016063 |
| 우 과제 | −0.027437 | +0.0026410 |

**양방향에서 실제 회전 감각이 회전을 누르는 방향의 신경 출력 차이를 만들었다.**
이는 등록된 yaw→비행 감각 경계→선택 회로→운동 의도의 기능 기여 증거다.
정적 기울기·하중·온도도 몸 v1 입력에 남았지만 이 시험에서 각각의 인과적 기여를 분리하지 않았다.
생물학적 감각 수용기 tuning이나 초파리 비행 생리 전체를 재현했다는 뜻은 아니다.

이 비교는 **기록된 동일 입력을 재생한 것**이다. yaw0 회로가 실제로 다른 조향을 적용했다면
영상·차량 움직임도 달라졌을 것이다. 따라서 실제 주행 안정화, 회전 오차 감소, 교란 후 복원,
랩타임 개선을 이 결과로 판정하지 않는다. 비교 기준은 감사 manifest에 기록했다.

## 실패·종료 상태와 재개

- t1153 읽기 전용 사전 검사를 통과한 뒤 t1154를 한 번 실행했다.
- 첫 감사 t1155는 최종 JSON 저장에서 NumPy boolean 형식 때문에 실패했다.
  명시적 Python bool로 고치고 동일 t1154 원본 전체를 t1157에서 다시 대조했다.
  실제 차량 시험이나 원자료를 다시 만들어 통과시키지 않았다. 실패와 재생 파일은 보존했다.
- 실제 실행 handle1486은 종료0. 감사의 실제 GPU 자식 PID11384는 exit1,
  PID26900은 exit0을 Windows `GetExitCodeProcess`로 확인했다.
  자식 종료 뒤에도 남은 launcher PID44904/36412는 명령행/실행 생성 시각과 자식 종료 코드를
  재확인한 뒤 정리했다. 도구 handle16752/22541은 launcher 정리로 둘 다exit1이다.
  실제 GPU 감사의exit0과 launcher 정리 코드를 구분한다. 감사 실행의 `launcher-cleanup.json`에
  영수증을 남겼다. 실행 중 GPU 작업이나 다른 사용자 프로세스를 종료하지 않았다.
- t1156 읽기 전용 상태: paused/AIoff/cameraoff/gas0/brake1/주행선off/창 비전면.
  실제 게임과 프로세스 상태는 다음 실행 전에 다시 확인한다.
- 새 속도 제어 가드·정차/제동 덮어쓰기 검사5개와 기존 codec7개, 새 파일 Ruff가 통과했다.

다음은 같은 고정 과제에서 **실제 차량에 적용하는 full/yaw0 조건을 비교하고,
사전에 지정한 작은 조향 교란 뒤 회전 응답·복원 시간·오차를 평가하는 것**이다.
같은 영상의 재생 결과를 실제 안정화 성능으로 바꾸지 않는다. 이후 실제 좌우 커브와 양성 제동,
시각 경로 추종의 전이·중립 편향, 미등록 몸 축·자기 운동·T4d 불일치, 타이어/셋업 판단,
학생 단독 유효 완주·반복·빠른 레이싱 라인/랩타임 검증을 이어간다.
