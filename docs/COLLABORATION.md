# 공동 연구 작업 방식

작성: 2026-11-03. 상태: 협업 제안. 담당자 배정·저장소 보호·자동화 설정은 아직 적용하지 않았다.

목표와 정보 경계는 [PROJECT_CHARTER.md](PROJECT_CHARTER.md), 단계별 통과 기준은 [ROADMAP.md](ROADMAP.md)를 따른다. 초파리 겹눈/운동 시각과 비행 유래 균형·운동 회로를 차량 몸에 연결하는 단일 감각운동 시스템을 함께 개발한다.

## 1. 두 사람이 시작할 때의 분담

| 역할 | 먼저 맡을 작업 | 상대에게 넘길 결과 |
|---|---|---|
| 시각·회로 담당 | R1 시야/T4·T5/공간 pooling/비행 전달 진단, R2 공간 보존·선행 예측 후보 | 재현 가능한 오프라인 진단, 버전별 특징·상태 계약, 후보 checkpoint와 실패 사례 |
| 시뮬레이터·몸 감각 담당 | 시간 정합·결측·몸 축/단위 검증, 트랙/교사 목록과 차량별 계약, R3 수집 | 적격 데이터 manifest, 원본 시간/valid mask, 교사 재현과 지연·이탈 분류 |
| 공동 검토 | actor/교사 정보 경계, 생리 근거와 공학 근사, R4 이후 평가·통합 | 사전 고정한 평가 조건과 상대방이 재현한 결과 |

이 분담은 개발 책임을 나누는 것이며 독립된 두 최종 운전 모델을 만드는 뜻이 아니다. 각 작업의 구현 담당 1명과 검토자 1명을 정하고 매주 막힌 계약·증거·다음 결합점을 확인한다. 사람이 늘면 독립 평가/재현 역할부터 분리한다.

## 2. 코드는 개인 작업 공간, 통합은 PR

팀 저장소를 통합 기준으로 두고 각자 로컬 clone에서 작업한다. NAS의 같은 작업 폴더를 두 사람이 동시에 편집·실행하지 않는다. 현재 flybrain 작업 폴더는 그대로 보존하며 이 제안 때문에 이동·초기화하지 않는다. 팀원은 별도 clone을 사용한다.

- 작업 하나에 이슈 하나, 짧은 브랜치 하나, PR 하나를 연결한다. 브랜치 예: `codex/r1-visual-path-diagnostics`, `feature/sensor-time-contract`.
- 처음부터 Draft PR로 변경 범위와 입력/출력 계약을 공유하고 같은 핵심 파일을 동시에 바꿔야 하면 편집 담당을 먼저 정한다.
- `main`에는 검토된 결과를 합친다. 저장소 권한/요금제가 허용하면 직접 push 제한, 상대방 승인 1회와 필요한 CI 통과를 설정한다. 이 문서 작성만으로 설정되지는 않는다.
- PR에는 문제·바뀐 동작·재현 명령·검증 결과·자료/소스 해시·미검증 범위를 적는다. 관련 테스트를 실행하고 문서만 바뀐 경우 링크/형식 검증을 한다.
- CI는 시뮬레이터 없는 계약/로더/오프라인 시험을 우선한다. 실제 AC 제어를 공개 PR이나 범용 CI에서 자동 실행하지 않는다.

## 3. 합치기 전에 고정할 계약

| 경계 | 반드시 기록할 것 |
|---|---|
| 네 시야 | 순서·방향·카메라 장착/차량 버전·좌표·해상도·노출/획득 시간의 의미·시계 변환·seq·결측 |
| 몸 감각 | 채널명·단위·축·부호·물리 시각·valid mask. 미검증 값을 valid로 승격하지 않음 |
| 모델 | 특징/상태 차원·dtype·정규화 출처·회로/전처리 hash·연속 상태와 reset 경계 |
| 조작 | 조향·가속·제동·변속 단위/범위·부호·실제 적용 시각·제어권·중단/해제 동작 |
| 데이터/평가 | 교사/actor/critic 경계·에피소드/트랙 분할·원본 hash·적격 기준·모든 종료 사유 |

기존 몸50ms·영상150ms·결정40ms·bounded 정합25ms 기준은 임의 완화하지 않는다. 원본 시각을 다시 매기거나 지도/절대 pose/미래 정답으로 결측을 채우지 않는다. recurrent state는 에피소드 동안 연속 유지하며 gradient detach를 reset으로 처리하지 않는다.

## 4. 데이터·실험 장비 운영

코드/설정/작은 manifest/검증 보고서는 Git, 큰 영상·NPZ·checkpoint·connectome 원본은 접근 제어된 공용 저장소에 둔다. `runs/`와 `assets/external/` 경로 규칙을 유지하며 Git에는 위치를 찾는 참조와 SHA256·버전·사용권·수집 조건을 남긴다. 토큰/비밀번호·게임 바이너리·유료 트랙을 저장소에 올리지 않는다. 기존 중복 제거 참조표와 공통 로더를 유지한다.

AC를 설치하지 않은 팀원도 적격 에피소드로 오프라인 진단·학습·재현을 할 수 있어야 한다. 원본을 덮어쓰지 않고 개인별 고유 run 디렉터리와 config/seed/종료 사유를 남긴다.

**AC 한 인스턴스의 조작 담당은 동시에 한 명뿐이다.** 이슈/예약 기록에 담당자·시간·run ID·제어권 보유 상태를 남기고 넘길 때 실제 제어 해제와 세션 상태를 확인한다. 예약 기록은 시스템 락을 대체하지 않는다. 자동 실행을 여러 작업자가 공유하기 전에는 독점 제어 락·상태 확인·오류 해제를 구현/검증해야 하며 현재 구현됐다고 가정하지 않는다. 검증된 CSP lifecycle API와 background 인터페이스만 사용하고 API 실패 시 AC 창 조작으로 우회하지 않는다.

## 5. 평가 누출을 막는 역할

기존 Monza heldout은 이미 소비된 회귀/개발 자료다. 새 봉인 트랙과 시도 수·seed·통과 기준은 튜닝 전에 고정하고 가능하면 구현자가 아닌 사람이 최종 평가를 수행한다. 두 명이 모두 시험 결과로 튜닝했다면 그 시험은 소비됐다고 표시하고 새 시험을 확보한다. 실패도 분모에 포함하고 teacher 개입·속도 제한·시스템 감각 실패를 별도 기록한다.

시각 기여 가림 점수, 부품 반응, 교사 완주, 학생 자율 완주, 미학습 조건 일반화는 각각 별도 증거다. 차종별 절대 랩타임을 곧바로 정책 순위로 비교하지 않는다.

## 6. Projects/이슈에 옮길 구성

제안 상태는 `Backlog → Ready → In progress → Review → Done`, 차단 사유는 별도 필드다. 필드는 단계(R0–R7), 영역(vision/body/simulator/learning/evaluation), 담당자, 검토자, 우선순위, 선행 이슈, 증거 경로를 사용한다. `Done`은 명시한 완료 조건과 검증 증거를 상대가 확인했을 때만 설정한다. 현재 보드 설정을 변경했다는 뜻은 아니다.

첫 작업 카드는 다음과 같이 쪼갠다.

| 우선순위 | 카드 | 완료 조건 | 선행 |
|---|---|---|---|
| P0 | R0 기준 checkpoint·데이터·정보 계약 고정 | 기존 지표/해시 재현, 소비된 시험 표시, 재현 절차 확보 | 없음 |
| P0 | R1 시각 경로 병목 진단 | 시야→T4/T5→pool→비행→근육 반응과 원인 후보·개입 결과 | R0 |
| P0 | 몸 감각·시간 계약 및 AC 제어 인계 | valid/missing/시계·축·제어 해제 증거, 장비 담당·예약 규칙 | R0 |
| P1 | 다중 트랙·공개 교사 가용성 조사 | 설치/사용권·차량 계약·교사 재현 가능성 목록, 수집/시험 제안 | R0 |
| P1 | R2 공간 보존/미래 예측 비교 | 각각의 추가 가치·개발 성능·실패 보존, actor 누출0 | R1 |
| P1 | R3 데이터 수집/공동 학습 | 교사별 적격 원본과 분할·학습/개발 manifest | 계약·교사 확보·R2 후보 |
| P1 | R4 학생 폐루프와 미학습 트랙 | 사전 고정한 모든 시도와 유효 완주/지연/이탈 보고 | R3 |
| 후속 | R5–R7 차량 적응·빠른 랩·최종 감사 | ROADMAP의 기전/운전 두 축 충족 | 단계별 통과 |

작업 카드 본문 공통 형식:

```markdown
## 목적 / 해결할 관찰
## 범위와 바뀌는 계약
## 선행 작업 / 담당 / 검토자
## 완료 조건
## 재현 명령 / config / seed / source·data hash
## 결과·실패·미검증 / 증거 위치
```
