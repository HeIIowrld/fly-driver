# 시간 정렬·코스 범위와 v3 추가 수집

2026-10-29, Asia/Seoul. 초파리 겹눈/운동 시각과 비행 균형·몸 제어를 자동차에 연결한다는
[대전제](PROJECT_CHARTER.md)를 유지한다. 직전 비선형 비교 실패 뒤, 자료의 시간·공간 범위를 먼저 확인했다.

## 기존 자료에서 확인한 범위

t1389는 원래 train6/개발2구간의 정답·mask·관측 시각을 원본 사건 및 봉인 전 proposal과 정확히 대조했다.
모든 원본 역할을 유지했고 평가 구간은 열지 않았다. 조향 정답 수신은 decision 뒤40~65ms다.
렌더 시작 하한부터 정답 수신까지의 구간별 중앙값은99.88~102.24ms였다.
이는 호스트 수신/렌더 경계이며 물리 노출 시각·내부 AI 명령 시각의 확인이 아니다.
기존 신경 재생의 이전 망막 hold 및 회로 동역학을 포함한 정확한 감각운동 지연은 별도다.
정답을 이동시키거나 모델을 추가 학습하지 않았다.

576차원 특징의 다른 train 이력 최근접 표적 비교는 개발02 RMSE0.086075,
개발07 0.046781이었다. 평균 기준은0.055131/0.096665다. 한 구간만 개선됐으므로
일반화 성공으로 보지 않는다. 같은 train 이력은 후보에서 제외했고 이웃 선택에 query 정답을 쓰지 않았다.
고정 lag별 몸 yaw 상관도 모두 보존했다. 시간 자기상관·과도 응답이 있으므로 최상 lag를 명령 지연으로 선택하지 않았다.

t1393은 별도 진단용 route metadata를 감사했다. 100개1% bin 중 train/개발에서 실제 관측된 bin은37개다.
bin09~11과25~84에 해당하는 관측이 없었다. 평가 구간을 제외한 자료 범위이며,
관측 bin 수는 연속 거리나 실제 주행 가능한 코스 비율과 같지 않다.
랩 경계에서 spline이1→0으로 바뀌므로 단순 min/max를 전체 코스 방문으로 해석하지 않았다.
모든 해당 driving telemetry에서 wheels_outside는0이었지만 유효 완주 증거는 없다.
route/좌표는 진단·교사용이며 actor 입력으로 넣지 않았다.

train16/개발4/평가4, 현재 위치에서 계속하며 재시작·화면 입력0. 역할은 수집 전에 고정했다.

두 완료 train 이력만 t1396/1397과 t1399에서 원시 재생·표적 proposal 감사를 완료했다.

## 정지 실패와 수정 범위

서버는 마지막 정지에서 CSP speed0.045879837km/h를 보고 pause했다.
정지 후 native packet222775는0.108073726km/h/full brake1/gas0였다.
이 값은 이후 읽기 전용 재검사에서도 같았다. 기존 native<0.1 기준은 그대로 실패다.
두 경로의 갱신 차이와 조기 pause에 부합하지만 정확한 내부 원인까지 확정하지 않았다.

저장소 Lua의 motion cleanup pause 조건만 CSP<0.1에서 **<0.01km/h**로 강화했다.
native admission<0.1·속도/거리/카메라 제한·4초 teardown deadline은 변경하지 않았다.
이는 native packet이 멈추기 전 여유를 확보하려는 수정이며 실제 native 결과는 다시 검증해야 한다.
관측된0.045879837·0.01·0.099에서는 pause하지 않고0.009에서 pause하는 회귀 검사3개를 추가했다.
Lua/control 검사169개와 관련 Python Ruff가 통과했다.
**수정은 저장소에만 있으며 게임에 배치하지 않았다.** 실행 Lua와 저장소 Lua의 차이는 의도적인 staging 상태다.
현재 엔진은 paused/full brake이며 native residual0.108 때문에 정상 lifecycle/교사 시작 guard를 통과하지 않는다.
다음 작업은 이 실패에 한정된 브레이크 정착 복구 절차를 검증한 뒤 새 정지 조건을 실제 검증하는 것이다.
정상 admission을 완화하거나 실패한 v3를 자동 재시작하지 않는다.

t1398 감사 watcher는 시작할 때 이미 종료한 collection PID의 handle을 요구해 실패했다.
이를 보존하고, 실제 terminal 결과가 있는 경우 완료 prefix만 감사하도록 수정했다.
새 t1399는 두 완료 train만 감사한 뒤 세 번째 미완료 구간에서 종료0했다.
이후 실행되지 않은 구간·평가 자료를 읽지 않았다. 이전 실패를 성공으로 덮어쓰지 않았다.
